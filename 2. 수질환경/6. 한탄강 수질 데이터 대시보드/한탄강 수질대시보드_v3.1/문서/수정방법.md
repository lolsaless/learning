# 한탄강 수질 대시보드 — 수정 방법 (부품 단위)

v3.1부터 프로그램은 **부품 49개**로 나뉘어 있습니다. 고칠 일이 생기면 **해당 부품 파일 하나만** 고친 뒤 **빌드**합니다. 빌드는 부품과 DB 엑셀을 합쳐 `한탄강_수질대시보드.html` 한 파일로 만드는 작업입니다.

```
소스/ (부품 49개) ─┐
                   ├─빌드─▶  한탄강_수질대시보드.html (업무에서 쓰는 파일 1개)
한탄강_수질DB.xlsx ─┘
```

> `한탄강_수질대시보드.html`은 **직접 고치지 않습니다.** 다음 빌드 때 덮어써집니다.

---

## 1. 고치는 순서

| 순서 | 할 일 | 방법 |
|---|---|---|
| ① | 고칠 부품 찾기 | `문서/부품지도.md` 맨 위 **"자주 하는 수정 → 고칠 부품"** 표, 또는 부품별 표의 "이럴 때 고침" 칸 |
| ② | 그 파일만 고치기 | VS Code로 `소스/…/부품` 열기. 파일 맨 위 머리말에 하는 일·주요 이름이 있다 |
| ③ | 빌드 | 아래 2장. **서버(대시보드_열기)가 켜져 있으면 브라우저 새로고침(F5)만 하면 자동으로 빌드된다** |
| ④ | 확인 | 고친 화면 확인. 오류가 나면 F12 → 콘솔의 빨간 줄 위쪽 `/* ===== 부품: … ===== */`로 부품 확인 |
| ⑤ | 시험 | `python 시험/빌드_시험.py`, 화면을 고쳤으면 `python 시험/화면_통합시험.py` (3장) |
| ⑥ | 기록 | `문서/변경이력.md`에 증상 → 원인 → 수정 → 검증 결과. 버전을 올리면 4장 |

## 2. 빌드

| 방법 | 명령 | 설명 |
|---|---|---|
| Windows | `빌드_windows.bat` 더블클릭 | Python이 있으면 `tools/build.py`(검사 포함), 없으면 PowerShell 간단 빌드(검사 없음) |
| Mac | `빌드_mac.command` 더블클릭 | python3이 있으면 `tools/build.py`, 없으면 `tools/build_simple.sh`(검사 없음) |
| 서버 켜 둔 채 | 브라우저 F5 | `대시보드_열기`로 연 서버가 부품·DB 변경을 감지해 다시 빌드한다. 오류면 이전 화면 유지 + 서버 창에 오류 표시 |
| 명령줄 | `python tools/build.py` | VS Code 터미널 등. Mac은 `python3` |
| 검사만 | `python tools/build.py --check` | 파일은 만들지 않고 검사만 |
| 자동 빌드 | `python tools/build.py --watch` | 부품·DB를 저장할 때마다 다시 빌드(1초 간격). 멈추려면 Ctrl+C |
| 디자인만 | `python tools/build.py --cache` | DB를 읽지 않고 지난번 데이터(`빌드결과/_data.js`)로 조립. 빠르다 |
| 공유용 | `python tools/build.py --no-key` | V월드 키를 뺀 `한탄강_수질대시보드_공유용.html` |

**빌드가 하는 일**

1. `소스/빌드목록.txt` 순서대로 부품을 이어 붙인다.
   - `.css`는 `<style>` 한 곳에, `.html`은 화면에 들어간다.
   - 외부 라이브러리는 각각 `<script>`로, 나머지 `.js`는 한 `<script>`로 묶는다.
   - 각 부품 앞에 `/* ===== 부품: 경로 ===== */` 표시를 넣는다.
2. 검사한다. **하나라도 걸리면 HTML을 만들지 않고 기존 파일을 그대로 둔다.**

   | 검사 | 오류 예 | 조치 |
   |---|---|---|
   | 목록의 파일이 있는가 | `목록에 있지만 파일이 없음` | 파일 이름 오타 확인 |
   | 목록에 없는 부품 | `[주의] 목록에 없는 부품` | 새로 만든 부품이면 `빌드목록.txt`에 한 줄 추가 |
   | 이름 중복 | `이름 "renderTs" 이(가) 두 부품에 있음` | 한쪽 이름을 바꾼다(5장 규칙 1) |
   | 문법(Node.js 있을 때) | `문법 오류 → 부품 40_화면/12_종단.js 의 84번째 줄 근처` | 그 줄의 괄호·따옴표·쉼표 확인 |
   | `</script` 글자 | `"</script" 글자가 있으면 화면이 깨집니다` | `<\/script`로 쓴다 |
   | 화면 짝 | `화면 "heat" 을 등록했지만 화면 자리가 없음` | `02_화면/…html`과 `40_화면/…js`를 둘 다 목록에 |
   | id 중복 | `화면 부품에 같은 id가 두 번 있음` | id 하나를 바꾼다 |
   | 외부 주소 | `[주의] 외부 주소(…)가 있음` | 행정망에서 열리지 않음. 파일 안에 넣거나 뺀다 |
   | 버전 | `[주의] 버전 표기가 다름` | 4장 |

3. 이전 HTML은 `빌드결과/이전/`에 보관한다(최근 5개). 잘못 빌드했으면 거기서 꺼내 쓴다.
4. `문서/부품지도.md`와 `빌드결과/_data.js`(간단 빌드용 데이터)를 새로 만든다.

> Node.js가 없으면 문법 검사만 건너뛴다(안내가 나온다). 문법 검사까지 하려면 Node.js(LTS)를 설치한다.

## 3. 시험

| 시험 | 명령 | 준비 | 확인하는 것 |
|---|---|---|---|
| 빌드 시험 | `python 시험/빌드_시험.py` | 없음 | 정상 빌드, 고장 5종을 막는지, 간단 빌드 결과 = Python 빌드 |
| 화면 통합 | `python 시험/화면_통합시험.py` | `pip install playwright` → `python -m playwright install chromium` | 9개 탭·분석 4종 오류 0, 화면 통계 = Python 계산, 하천 클릭 색, ⚡ 표시, 설정 저장. 서버 모드(임시 복사본): 지점·설정 저장 → 엑셀 반영, 부품 수정 자동 빌드 |
| 화면 통합(빠르게) | `python 시험/화면_통합시험.py --file` | 위와 같음 | 서버 시험 생략 |

- 두 시험 모두 프로그램 폴더를 **임시 폴더에 복사해서** 하므로 원본 DB는 바뀌지 않는다.
- `시험/결과/`의 화면 사진에는 실제 자료가 보이므로 배포 묶음에 넣지 않는다.

## 4. 버전 올리기
1. `소스/버전.txt`를 새 번호로 바꾼다(예: `3.2`). 화면 제목 옆 표시와 HTML에 자동으로 반영된다.
2. `문서/변경이력.md` 맨 위에 `## v3.2 (날짜)` 항목을 추가한다. 두 번호가 다르면 빌드가 `[주의]`로 알려 준다.
3. 배포 폴더 이름을 `한탄강_수질대시보드_v3.2/`로 한다.

## 5. 부품 규칙 (꼭 지킬 것)

| 번호 | 규칙 | 이유 |
|---|---|---|
| 1 | 스크립트 부품(20·30·40·90)은 **한 `<script>` 안에 이어 붙는다.** 다른 부품의 이름을 `import` 없이 바로 쓸 수 있다. 대신 맨 앞(줄 첫 칸)에 쓰는 `function`·`const`·`let` 이름이 **겹치면 안 된다.** | 겹치면 한쪽이 덮어써짐 → 빌드가 오류로 막음 |
| 2 | **순서가 중요하다.**<br>• CSS는 뒤에 있는 규칙이 이긴다.<br>• 스크립트는 맨 위(부품을 읽을 때 바로 실행되는 줄)에서 **뒤 부품의 이름을 쓰면 안 된다.** 함수 안에서 쓰는 것은 괜찮다. | 예: `registerView`는 30_틀동작/01에 있으므로 40_화면 부품에서 쓸 수 있다 |
| 3 | **화면(탭) 하나 = 부품 2개**: `02_화면/○○.html`(자리: `<section class="view" id="v-아이디" hidden>`) + `40_화면/○○.js`(맨 위에 `registerView({id:"아이디", label:"탭 이름", render, bind})`). 두 파일 모두 `빌드목록.txt`에 넣는다. 탭 순서 = 목록 순서 | 빌드가 짝을 검사한다 |
| 4 | 화면 안 버튼은 **그 화면 부품의 `bind`** 에서 연결한다. 왼쪽 패널 버튼만 `90_시작/02_이벤트_연결.js`에서 연결한다. 화면이 아닌 부품(인쇄 등)은 `onInit(함수)`로 처음 할 일을 등록한다. | 화면을 빼도 다른 부품이 깨지지 않게 |
| 5 | 화면 전체를 다시 그릴 때마다 할 일은 `onRefresh(함수)`, 라이트/다크가 바뀔 때 할 일은 `onTheme(함수)`로 등록한다. | 공통 부품을 고치지 않고 기능을 더할 수 있게 |
| 6 | 새 부품을 만들면 번호를 붙여 알맞은 폴더에 두고 `빌드목록.txt`에 한 줄 추가한다. 머리말(하는 일·주요 이름·이럴 때 고침)을 쓰면 부품지도에 자동으로 실린다. 자주 하는 수정이면 `소스/자주하는수정.txt`에도 한 줄 추가한다. | |
| 7 | `10_외부라이브러리`(ECharts·Leaflet·시군 경계)는 고치지 않는다. | 공개 라이브러리 원본 |
| 8 | 엑셀 DB 구조(시트·열·설정 기본값)는 `tools/wq_common.py`, DB → 화면 데이터는 `tools/data_builder.py`에서 바꾼다. 화면에서 새 데이터를 쓰려면 `data_builder.py`의 `data` 사전에 넣고 화면 부품에서 `D.이름`으로 쓴다. | 화면 부품은 엑셀을 직접 읽지 않는다 |

**부품 머리말 형식** (새 부품에도 똑같이)

```js
/* ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   [40_화면/13_히트맵.js] 히트맵 화면
   하는 일 : 시료번호×월 색칸, 측정값/평균 대비 모드
   주요 이름: renderHeat
   이럴 때 고침: 히트맵 색·라벨
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ */
```

**새 화면(탭) 만들기 예**

```html
<!-- 소스/02_화면/22_메모.html -->
    <section class="view" id="v-memo" hidden>
      <div class="card"><div class="card-h"><h3>메모</h3></div><div id="memoBody"></div></div>
    </section>
```
```js
/* 소스/40_화면/22_메모.js */
registerView({ id:"memo", label:"메모", kpi:false, item:false,
  render(){ $("memoBody").textContent = "선택한 시료번호 " + S.sel.size + "개"; },
  bind(){ /* 이 화면의 버튼 연결 */ } });
```
그다음 `빌드목록.txt`의 화면 자리 묶음에 `02_화면/22_메모.html`을, 화면 동작 묶음에 `40_화면/22_메모.js`를 추가하고 빌드한다.

## 6. Claude에게 수정을 맡길 때

전체 코드를 다시 읽지 않도록, 요청할 때 아래처럼 말하면 됩니다.

```
한탄강 수질 대시보드 v3.1 수정 요청.
- 증상/요청: (예) 히트맵 칸에 소수 둘째 자리까지 보이게 해 줘
- 자료: (필요하면 DB 엑셀이나 화면 사진)
부품지도.md를 보고 관련 부품만 읽고 고쳐 줘. 고친 뒤 빌드·시험하고 변경이력을 남겨 줘.
```

Claude 작업 순서(약속):
1. `문서/부품지도.md`(프로젝트 문서에도 있음)만 먼저 읽고 고칠 부품을 정한다.
2. 그 부품만 읽고 고친다. 필요하면 바로 이웃 부품 1~2개까지 읽는다.
3. `python tools/build.py` → 검사 통과 확인 → `python 시험/빌드_시험.py`, 화면을 고쳤으면 `python 시험/화면_통합시험.py`
4. 고친 부품 이름과 변경 내용을 변경이력에 적고, **바뀐 부품 파일과 `한탄강_수질대시보드.html`만** 다시 전달한다.

## 7. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| 빌드 창이 바로 닫힘 / 아무 일 없음 | 압축 파일 안에서 직접 실행했는지 확인 → 압축을 풀고 실행 |
| Windows: "Python이 없어 간단 빌드로…" | 정상 동작(검사만 빠짐, 데이터는 지난번 것). 검사까지 하려면 python.org에서 Python 설치("Add to PATH" 체크) |
| Windows: PowerShell "스크립트를 실행할 수 없으므로" | 기관 보안 정책으로 막힘 → Python 설치 후 다시 실행, 또는 전산 담당자 문의 |
| Mac: "확인되지 않은 개발자" / "권한이 없어 열 수 없음" | 처음 한 번은 오른쪽 클릭 → 열기. 그래도 안 되면 터미널에서 `chmod +x *.command tools/build_simple.sh` |
| `[오류] DB 파일이 없고 지난번 데이터도 없습니다` | `한탄강_수질DB.xlsx`가 프로그램 폴더에 있는지 확인 |
| `엑셀에서 열려 있습니다` | DB 엑셀을 닫고 다시 빌드(빌드는 읽기만 하지만, 저장 중인 파일은 못 읽을 수 있음) |
| 빌드는 됐는데 화면이 비거나 버튼이 안 됨 | Edge F12 → 콘솔의 빨간 오류 → 오류 줄 위쪽 `/* ===== 부품 ===== */`로 부품 확인. 직전 정상 파일은 `빌드결과/이전/` |
| 탭이 안 생김 | 화면 부품 `registerView`의 id와 `02_화면` 부품의 `id="v-…"`가 같은지, 두 부품이 모두 빌드목록에 있는지 |
| 빌드 메시지 한글이 깨짐(Windows) | 결과에는 영향 없음. 오래된 콘솔 글꼴 문제 |
