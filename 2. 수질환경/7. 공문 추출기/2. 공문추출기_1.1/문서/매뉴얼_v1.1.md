# 검사의뢰 공문 추출기 — 매뉴얼

- 파일: `공문추출기.html` (HTML 판, 약 100KB) / `공문추출기.py` (파이썬 판)
- 버전: **v1.1** (2026-10-22) — 변경 내용은 `변경이력.md` 참고
- 실행 환경: Windows PC, **Microsoft Edge** 또는 Chrome 최신 버전 (HTML 판) / Python 3.8 이상 (파이썬 판) — 인터넷 불필요, 내부망 사용 가능

---

## 1. 최초 기획

### 1.1 목적
수질검사 의뢰 공문(ODT)을 하나씩 열어 의뢰자·시료번호·검사항목·기준·채취일·시행/접수 정보를 옮겨 적는 반복 작업을 없앤다. 공문을 폴더에 모아 두기만 하면 프로그램이 전부 읽어 **시료 1개당 1행** 표로 보여 주고, 엑셀로 저장하며, 성적 처리가 끝난 공문은 `성적처리완료` 폴더로 옮겨 관리한다.

### 1.2 요구사항

| 번호 | 요구사항 | 버전 |
|---|---|---|
| 1 | 의뢰기관·의뢰자는 **가장 큰 기관** (예: 진접읍장 → 남양주시 / 남양주시장) | v1.0 |
| 2 | 원래 하단 명의는 **발신명의** 열에 보관 (경기도 → 경기도 / 경기도지사 / 기후환경관리과장) | v1.0 |
| 3 | 채취일: 시료 표 → 본문 문장 → 없으면 **"채취일자 확인 필요"** | v1.0 |
| 4 | 시료 1개 = 1행 (공통 정보 반복), TMS `(A~D)`는 A·B·C·D 각각 1행 (`TMS 2-10-3(A)`) | v1.0 |
| 5 | 공문에 기준이 없으면 비워 두고, **기준표**를 넣으면 항목별 기준을 자동 표기 | v1.0 |
| 6 | **공문 폴더** 방식: 실행하면 폴더 안 공문 전체를 읽어 표로 표시 | v1.0 |
| 7 | **엑셀 저장** | v1.0 |
| 8 | **공문 단위 완료 체크** → [처리 완료] 시 `성적처리완료` 폴더로 이동 | v1.0 |
| 9 | 접수일 **최근 순(내림차순)** 표시 | v1.1 |
| 10 | 열 순서: **접수일 · 의뢰기관 · 의뢰자 · 발신명의 · 시행 · 시료번호 · 검사항목 · 시료채취일** | v1.1 |
| 11 | 검사항목 안의 기준 표기(`BOD(20이하)`, `SS(20이하)` 및 유사 표기) 분리 | v1.1 |
| 12 | 행을 누르면 추출 결과와 함께 **원본 공문** 보기, 원본 파일 바로 열기 | v1.1 |

### 1.3 공문 분석 결과 (개발 기준 자료 39건, 발신기관 13곳)
- 상단(기관명·수신·제목)과 하단(발신명의·결재란·시행/접수·주소·연락처)은 전자문서 공통 양식이라 위치로 추출.
- 본문 시료 표는 **부서마다 형식이 다름** (열 이름 15가지 이상, 기준 표기 5가지 이상, 병합 칸, 범위 시료번호, 하위 시료, 글상자 안의 표 등).
- → 기관별 조건 대신 **열 이름 사전 + 값 모양 판정 + 값 해석 규칙**으로 처리.

| 발신기관 | → 의뢰기관 / 의뢰자 | 비고 |
|---|---|---|
| 포천시, 포천시농업기술센터 | 포천시 / 포천시장 | 센터는 주소로 시 판정 |
| 가평군 | 가평군 / 가평군수 | |
| 남양주시, 진접읍, 진건읍 | 남양주시 / 남양주시장 | 읍은 주소로 시 판정 |
| 경기도 | 경기도 / 경기도지사 | 발신명의: 기후환경관리과장 |
| 양주시·파주시·고양시·구리시·동두천시 | 각 시 / 시장 | 고양시 푸른도시사업소 포함, 동두천시는 v1.1에서 추가 |

## 2. 개발 과정

| 단계 | 내용 | 결과 |
|---|---|---|
| 1. 공문 분석 | 38건 구조 분석, 유형·예외 정리, 오류 대응 방안 36개 항목 수립 | 설계서 |
| 2. 추출 엔진 | ODT(ZIP·XML) 읽기, 상·하단·시료 표 추출, 병합/범위/하위시료 전개, 항목 표준명·기준·지역·채취일 해석, 검증 경고 | 38건 → 93행, 원문 시료 수 전부 일치 |
| 3. 1차 검증 | 검증용 엑셀로 원문 대조, 오류 5건 수정 | 사용자 확인 완료 |
| 4. HTML 화면 | 폴더 연결·재연결, 표(공문 단위 묶음)·정렬·검색·필터·열 선택, 원문 대조 패널 | |
| 5. 완료 처리 | 공문 단위 체크(`_처리상태.json`), 처리 완료 이동, 되돌리기, 잠긴 파일 안전 처리 | |
| 6. 엑셀·기준표 | 엑셀 작성기 자체 구현(전 셀 텍스트), 기준표 양식 자동 생성·읽기(xlsx/csv) | |
| 7. 파이썬 판 | 같은 엔진을 파이썬으로 이식(표준 라이브러리만), tkinter 화면, 명령줄 | HTML 판과 2,604개 필드 차이 0 |
| 8. **v1.1** | 시료 표 미인식(동두천시 `시료명`) 원인 분석·보완, 항목 안 기준 표기 일반화, 접수일 내림차순, 열 순서, 원본 미리보기·원본 파일 열기 | 39건 회귀: v1.0 결과 차이 0 + 신규 공문 인식, 두 판 추출·미리보기 결과 동일 |

**기술 메모**
- 두 판 모두 외부 라이브러리 **0개** → 인터넷이 막힌 내부망에서도 동작.
- HTML 판: ZIP 해제는 브라우저 내장 기능, 폴더 접근은 Edge/Chrome의 파일 시스템 접근 기능.
- 파이썬 판: `zipfile`, `xml.etree`, `tkinter`, `json` (파이썬 기본 포함).
- 원본 미리보기: ODT 안의 서식 정보(쪽 너비, 표 열 너비·테두리·병합, 글꼴 크기·굵기·정렬, 그림)를 읽어 HTML로 다시 그린다. 두 판이 같은 HTML을 만든다.
- 두 판은 `_처리상태.json`과 `기준표.xlsx`를 **같은 형식**으로 쓰므로 섞어 써도 된다.

## 3. 설치 및 사용 (HTML 판)

### 3.1 설치
설치 없음. `공문추출기.html`을 원하는 곳(예: 바탕화면)에 두고 **Edge로 연다**.
- 기본 브라우저가 Edge가 아니면: 파일 오른쪽 클릭 → **연결 프로그램** → **Microsoft Edge**.
- v1.0에서 올리는 경우: HTML 파일만 바꾸면 된다. 공문 폴더의 `_처리상태.json`·`기준표.xlsx`는 그대로 쓴다.

### 3.2 폴더 구성

```
공문/                        ← 공문 폴더 (이름 자유)
├─ ○○ 검사의뢰(...).odt       ← 처리할 공문을 여기에 저장
├─ 기준표.xlsx               ← (선택) 기준표
├─ _처리상태.json             ← 완료 체크 기록 (프로그램이 자동 관리, 지우지 말 것)
└─ 성적처리완료/              ← 처리 완료한 공문 (자동 생성)
```

### 3.3 처음 실행
1. **[공문 폴더 선택]** → 공문을 모아 둘 폴더 선택.
2. 브라우저가 묻는 창에서 **[파일 보기 및 편집 허용]** 선택 (공문을 옮기려면 편집 권한 필요).
3. 폴더 안 공문을 모두 읽어 표로 보여 줌.

다음부터는 **[○○ 다시 연결]** 버튼 한 번으로 같은 폴더가 열린다.

### 3.4 화면 구성

| 영역 | 내용 |
|---|---|
| 상단 | 공문 폴더 이름, [공문 폴더 선택], [새로고침], [도움말] |
| 도구줄 | 검색, 기관 필터, 보기(처리 대기 전체 / 완료 체크 안 한 공문 / 완료 체크한 공문 / 성적처리완료 폴더), 확인필요만, 열 선택 |
| 표 | 시료 1개당 1행, **접수일 최근 순**. 기본 열: 완료 · 접수일 · 의뢰기관 · 의뢰자 · 발신명의 · 시행 · 시료번호 · 검사항목 · 시료채취일 · 확인필요 |
| 오른쪽 패널 | 행을 누르면 열림 — **[추출 결과] [원본 보기] [나란히]** 전환 |
| 하단 | [완료 체크한 공문 처리 완료], [엑셀 저장], [기준표 양식 만들기], 통계 |

- 기준·지역구분·채취자·접수번호·제목 등 다른 열은 **[열 선택]**에서 켠다 (브라우저가 기억).
- 머리글을 누르면 정렬. 접수일은 처음 누르면 최근 순, 다시 누르면 오래된 순.

**오른쪽 패널 (v1.1)**

| 보기 | 내용 |
|---|---|
| 추출 결과 | 공문 정보, 추출된 시료, 공문 시료 표 원문(글자), 본문(날짜 강조) |
| 원본 보기 | 원본 공문을 서식 그대로 표시 (로고·표 테두리·병합·정렬·결재란 포함) |
| 나란히 (기본) | 왼쪽 추출 결과, 오른쪽 원본 — 한눈에 대조 |

| [원본 파일 열기] | 원본 ODT를 내려받기 → 브라우저 다운로드 목록에서 열면 한글(기본 프로그램)로 열림 |

> 브라우저 보안상 HTML 판은 PC의 프로그램(한글)을 직접 실행할 수 없어 "내려받아 열기" 방식이다. 한글로 바로 열려면 파이썬 판의 [원본 파일 열기]를 쓴다.

| 표시 | 의미 |
|---|---|
| 노란 칸 / 확인필요 열 ⚠ | 직접 확인이 필요한 값 (채취일 없음, 미등록 항목, 제목-표 시료 수 불일치 등) |
| `본문` 꼬리표 | 채취일을 공문 본문 문장에서 찾음 |
| `기준표` 꼬리표 | 기준을 기준표에서 채움 |
| 연녹색 행 | 완료 체크한 공문 |
| 회색 행 | 접수번호가 같은 중복 공문 (집계 제외) |
| 빨간 행 | 읽기 실패 (손상·빈 파일, 파일명과 사유 표시) |

### 3.5 일상 업무 순서
1. 공문(ODT)을 공문 폴더에 저장 → 프로그램 창으로 돌아오면 **자동으로 다시 읽음** (안 되면 [새로고침]). 새 공문이 맨 위에 보인다.
2. **확인필요만**을 켜고 노란 칸을 오른쪽 패널의 원본과 나란히 대조.
3. 필요하면 **[엑셀 저장]** — 현재 보이는 공문(필터·정렬 적용)을 시료 1행 형식으로 저장.
4. 성적 작성이 끝난 공문은 맨 앞 칸 **완료 체크** (공문 단위, 껐다 켜도 유지).
5. **[완료 체크한 공문 처리 완료]** → 목록 확인 → [옮기기] → `성적처리완료` 폴더로 이동.

### 3.6 되돌리기
보기에서 **성적처리완료 폴더**를 고르면 옮긴 공문이 보인다. **[되돌리기]**를 누르면 공문 폴더로 돌아가고 완료 체크는 해제된다.

### 3.7 기준표
1. **[기준표 양식 만들기]** → 공문 폴더에 `기준표.xlsx` 생성 (기준이 비어 있는 지역구분 × 항목 목록).
2. 엑셀에서 **기준값** 칸을 채우고 저장 → 엑셀 닫기 → **[새로고침]**.
3. 새로운 지역·항목이 나오면 다시 [기준표 양식 만들기] → `기준표_추가필요.xlsx`가 생기므로, 채운 행을 `기준표.xlsx`에 옮겨 붙인다.

| 규칙 | 내용 |
|---|---|
| 우선순위 | 공문에 적힌 기준 > 기준표 |
| 지역구분 | 공문에 적힌 값 그대로 (가, 나, 청정, 특례, 기타, 하수처리구역내 등). `청정`과 `청정지역`은 같은 것으로 봄 |
| 전체 적용 | 지역구분을 비우거나 `*` → 모든 지역에 적용 (지역이 맞는 행이 있으면 그쪽 우선) |
| 항목명 | BOD, TOC, SS, T-N, T-P, n-H(광), ABS, 생태독성, 색도 등 (총인·총질소 등 한글명도 인식) |
| 파일 형식 | `기준표.xlsx` 또는 `기준표.csv` (한글 Windows 엑셀 기본 CSV도 읽음) |

### 3.8 공문에 적힌 기준을 읽는 방식 (v1.1 보완)

| 공문 표기 | 검사항목 | 기준 |
|---|---|---|
| `BOD(20이하), SS(20이하)` | BOD, SS | BOD 20, SS 20 |
| `SS(20 이하)`, `BOD (20㎎/L 이하)` | SS / BOD | 20 |
| `BOD(기준 20)`, `TOC(≤25)` | BOD / TOC | 20 / 25 |
| `T-P(0.5미만)` | T-P | 0.5 미만 |
| `pH(5.8~8.6)` | pH | 5.8~8.6 |
| `대장균군(3,000개/mL)` | 대장균군 | 3,000 |
| `BOD 20이하`, `SS: 20` (괄호 없음) | BOD / SS | 20 |
| `BOD(10), n-H(광)(5)` (기존) | BOD, n-H(광) | 10, 5 |
| 별도 기준 열 `BOD·SS 각 20㎎/L`, `20, 20` (기존) | | 20 |

- 괄호 안 단위(mg/L, ㎎/ℓ, ppm, 도, TU, 개/mL, %)와 `이하`·`미만`·`기준`·`≤`·`<` 표기는 모두 인식한다.
- 괄호가 없는 표기는 항목명이 사전에 있는 경우만 기준으로 분리한다 (`BOD5` 같은 이름이 기준으로 잘못 나뉘지 않도록).

### 3.9 시료 표를 찾는 방식 (v1.1 보완)
1. 열 제목에 `시료번호`·`검사지시번호`·`검사의뢰번호`·`검체번호`가 있으면 그 열.
2. 열 제목이 `시료명`·`검체명`·`시료코드` 등이면서 칸 값이 시료번호 모양(`동두천-10-1`처럼 숫자-숫자)이면 그 열.
3. 열 제목이 낯설어도, 검사항목 열이 있는 표에서 값이 시료번호 모양인 열을 찾아 사용.
- 시료번호로 쓰지 않은 `시료명`(예: 오수·폐수)은 `업종/성상` 열에 들어간다.

### 3.10 출력 열 (엑셀 29열, v1.1 순서)
상태 · 접수일 · 의뢰기관 · 의뢰자 · 발신명의 · 시행 · 시료번호 · 검사항목 · 시료채취일 · 기준 · 기준출처 · 지역구분 · 채취시각 · 채취일출처 · 시료채취자 · 접수 · 시행일 · 제목 · 업종/성상 · 시료량 · 채취지점 · 비고 · 기타 · 우편번호 · 주소 · 전화번호 · 이메일 · 확인필요 · 파일명

모든 칸은 텍스트로 저장되어 `10-9-3` 같은 시료번호가 날짜로 바뀌지 않는다. 행 순서는 화면과 같다(기본: 접수일 최근 순).

| 증상 | 원인·조치 |

| 같은 공문이 두 번 보임(회색) | 같은 공문이 다른 이름으로 두 번 저장됨. 하나를 지우거나 함께 처리 완료 |
| v1.1로 바꿨는데 열 순서가 그대로 | [열 선택] → [기본값] |

## 4. 설치 및 사용 (파이썬 판)

### 4.1 설치
- 파이썬 3.8 이상 (Windows용 python.org 설치본에는 tkinter가 기본 포함). **추가 패키지 설치 없음.**
- `공문추출기.py`를 원하는 곳에 둔다.

### 4.2 화면(창)으로 실행

```bash
python 공문추출기.py
```

설정(마지막 폴더·열 선택·창 크기)은 `%APPDATA%\공문추출기_설정.json`에 저장된다. 미리보기 HTML은 임시 폴더(`%TEMP%\공문추출기_미리보기`)에 만들어진다.

### 4.3 명령줄(창 없이) 실행

| 명령 | 동작 |
|---|---|
| `python 공문추출기.py --folder D:\공문 --excel 결과.xlsx` | 공문 폴더를 읽어 엑셀 저장 |
| `python 공문추출기.py --folder D:\공문 --json 결과.json` | JSON 저장 (다른 프로그램 연계용) |

### 4.4 이동 방식 차이
파이썬 판은 같은 드라이브 안의 **이름 바꾸기(os.rename)**로 옮긴다. 공문이 한글에서 열려 있으면 이동 자체가 실패하고 **아무것도 바뀌지 않는다**(원본·체크 유지, 안내 표시).

## 6. 유지보수

### 6.1 수정 위치 (두 판 모두 같은 이름)

| 수정할 것 | HTML 판 (`engine.js` / `app.js`) | 파이썬 판 | 예시 |
|---|---|---|---|
| 항목명 표기 추가 | `ITEM_DICT` | `ITEM_DICT` | `'노르말헥산': 'n-H(광)',` |
| 하위기관 → 의뢰기관 예외 | `ORG_EXCEPTIONS` | `ORG_EXCEPTIONS` | `'○○사업소': {'의뢰기관': '○○시', '의뢰자': '○○시장'},` |
| 지역코드로 인식할 비고 값 | `REGION_CODE` | `REGION_CODE` | `가|나|다|라|청정|특례|특정` |
| 열 이름 인식 규칙 | `function classify` | `def classify` | `채수일시`, `시료명` 등 새 열 이름 |
| 시료번호 모양 판정 | `looksLikeSampleNo` | `looks_like_sample_no` | 숫자-숫자 형태 |
| 항목 안 기준 표기 | `STD_PAREN`, `STD_PLAIN`, `STD_UNIT` | 같은 이름 | 새 단위·표기 추가 |
| 원본 미리보기 | `renderOdtHtml`, `ODT_PREVIEW_CSS` | `render_odt_html`, `ODT_PREVIEW_CSS` | |
| 화면 기본 열·순서 | `const COLS` (`def: 1`) | `VIEW_COLS` (마지막 값 True) | |
| 엑셀 열 순서 | `COLUMNS` | `COLUMNS` | |

규칙을 고칠 때는 **두 판을 같이 고쳐야** 결과가 같게 유지된다. 고친 뒤 `소스코드/시험`의 대조 스크립트로 두 판 결과가 같은지 확인한다.

### 6.2 HTML 판 다시 만들기
`소스코드/html` 폴더에서 `node build.js` → `dist/공문추출기.html` 생성. HTML 안의 세 `<script>`가 각각 `engine.js`, `xlsx.js`, `app.js`이므로 원본 파일이 없어도 HTML에서 잘라 내 복원할 수 있다.

### 6.3 파이썬 판 구성 (`공문추출기.py` 한 파일)

| 구역 | 내용 |
|---|---|
| 1~9 | ODT 읽기, 표 격자, 날짜, 사전, 머리글 분류, 상·하단, 시료 표(시료번호 열 판정), 항목·기준 분리, 본문 채취일·제목 대조, 메인 추출(`extract_odt`) |
| 10 | 기준표 조회·적용, xlsx/csv 읽기 |
| 10-1 | 원본 미리보기 (`render_odt_html`, `preview_html_document`) |
| 11 | 엑셀 작성 (`build_xlsx`, `export_rows_xlsx`) |
| 12 | 공문 폴더 관리 (`Folder`: 읽기·체크·이동·되돌리기·기준표 양식) |
| 13 | 화면 (`run_gui`, tkinter), 원본 열기·미리보기 도우미 |
| 14 | 명령줄 (`run_cli`, `main`) |

```python
import importlib.util
spec = importlib.util.spec_from_file_location('odt', '공문추출기.py')
odt = importlib.util.module_from_spec(spec); spec.loader.exec_module(odt)
F = odt.Folder(r'D:\공문'); F.scan()
for d in F.docs:
    for r in d.rows():
        print(r['접수일'], r['시료번호'], r['검사항목'], r['시료채취일'])
```

## 7. 주의
- `_처리상태.json`은 지우지 않는다 (지우면 완료 체크가 모두 사라짐. 이미 옮긴 공문에는 영향 없음).
- 공문 폴더 안의 하위 폴더는 `성적처리완료`만 사용한다. 다른 하위 폴더의 공문은 읽지 않는다.
- 공문 원본은 수정하지 않는다 (읽기·이동만). 원본 미리보기도 읽기만 한다.
- 원본 미리보기는 ODT의 서식 정보를 다시 그린 것이라 한글 화면과 줄바꿈·간격이 조금 다를 수 있다. 정확한 원본은 [원본 파일 열기]로 확인한다.
- 새 양식의 공문이 들어오면 처음 몇 건은 원본과 나란히 대조해 확인한다. 시료 표를 못 찾으면 "시료표 미인식"으로 표시되고 틀린 값은 넣지 않는다.
- 실제 Windows 업무 PC(Edge·한글 파일 잠금) 환경은 개발 중 시험하지 못했으므로, 처음 사용할 때 공문 한두 건으로 처리 완료·되돌리기를 확인한다.
