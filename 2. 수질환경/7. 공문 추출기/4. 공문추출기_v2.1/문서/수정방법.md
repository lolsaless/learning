# 공문추출기 — 수정 방법 (부품 단위)

v2.1부터 프로그램은 **부품 60개**로 나뉘어 있습니다. 고칠 일이 생기면 **해당 부품 파일 하나만** 고친 뒤 **빌드**(부품을 합쳐 `공문추출기.html` 한 파일로 만드는 작업)합니다.

```
소스/ (부품 60개)  ──빌드──▶  공문추출기.html (업무에서 쓰는 파일 1개)
```

> `공문추출기.html`은 **직접 고치지 않습니다.** 다음 빌드 때 덮어써집니다.

---

## 1. 고치는 순서

| 순서 | 할 일 | 방법 |
|---|---|---|
| ① | 고칠 부품 찾기 | `문서/부품지도.md` 맨 위 **"자주 하는 수정 → 고칠 부품"** 표, 또는 부품별 표의 "이럴 때 고침" 칸 |
| ② | 그 파일만 고치기 | VS Code 등으로 `소스/…/부품.js` 열기. 파일 맨 위 머리말에 하는 일·주요 이름이 있다 |
| ③ | 빌드 | Windows: **`빌드_windows.bat`** 더블클릭 / Mac: **`빌드_mac.command`** 더블클릭 |
| ④ | 확인 | `공문추출기.html`을 Edge로 열어 고친 기능 확인. 엔진을 고쳤다면 3장 시험 실행 |
| ⑤ | 기록 | `문서/변경이력.md`에 증상 → 원인 → 수정 → 확인 결과. 버전을 올리면 4장 참고 |

## 2. 빌드

| 방법 | 명령 | 설명 |
|---|---|---|
| Windows | `빌드_windows.bat` 더블클릭 | Python이 있으면 `tools/build.py`(검사 포함), 없으면 PowerShell 간단 빌드(검사 없음) |
| Mac | `빌드_mac.command` 더블클릭 | python3가 있으면 `tools/build.py`, 없으면 `tools/build_simple.sh`(검사 없음) |
| 명령줄 | `python tools/build.py` | VS Code 터미널 등. Mac은 `python3` |
| 검사만 | `python tools/build.py --check` | 파일은 만들지 않고 검사만 |
| 자동 빌드 | `python tools/build.py --watch` | 부품을 저장할 때마다 자동으로 다시 빌드(1초 간격). 멈추려면 Ctrl+C |

**빌드가 하는 일**

1. `소스/빌드목록.txt` 순서대로 부품을 이어 붙입니다. 각 .js·.css 앞에 `/* ===== 부품경로 ===== */` 표시를 넣어, 화면에서 오류가 나도 어느 부품인지 찾을 수 있습니다.
2. 검사합니다. 하나라도 걸리면 **파일을 만들지 않고** 기존 `공문추출기.html`을 그대로 둡니다.

   | 검사 | 오류 예 | 조치 |
   |---|---|---|
   | 목록의 파일이 있는가 | `목록에 있지만 파일이 없음` | 파일 이름 오타 확인 |
   | 목록에 없는 부품 | `[주의] 목록에 없는 부품` | 새로 만든 부품이면 `빌드목록.txt`에 한 줄 추가 |
   | 이름 중복 | `[화면] 이름 "render" 이(가) 두 부품에 있음` | 한쪽 이름을 바꾼다 (5장 규칙 1) |
   | 문법(Node.js가 있을 때) | `문법 오류 → 부품 40_화면/17_도움말.js 의 19번째 줄 근처` | 그 줄의 괄호·따옴표·쉼표 확인 |
   | `</script` 글자 | `"</script" 가 있으면 화면이 깨집니다` | `<\/script`로 쓴다 |
   | 버전 표기 | `[주의] 버전 표기가 다름` | 4장 |

3. 이전 `공문추출기.html`을 `빌드결과/이전/`에 보관합니다(최근 5개). 잘못 빌드했으면 그 파일을 꺼내 쓰면 됩니다.
4. `시험/_엔진_묶음.js`(시험용 엔진)와 `문서/부품지도.md`를 새로 만듭니다.

> Node.js가 없으면 문법 검사를 건너뜁니다(안내가 나옵니다). 나머지 검사는 Python만으로 합니다. 문법 검사까지 하려면 Node.js(LTS)를 설치합니다.

## 3. 시험 (Node.js 필요)

| 시험 | 명령 | 자료 | 확인하는 것 |
|---|---|---|---|
| 처리기한 단위시험 | `node 시험/처리기한_단위시험.js` | 필요 없음 | [별표 2] 계산 16가지(13시 규칙, 공휴일, 긴/짧은 항목, 지정 휴일, 근무일 지정, 남은 기간), 폴더 이름 |
| 엔진 회귀 | `node 시험/엔진_회귀.js <의뢰공문폴더> [기준.json]` | 의뢰공문 ODT | 처음 실행 결과를 기준으로 두고, 고친 뒤 다시 실행해 **칸 단위 차이 0** 확인 |
| 성적서·대조 | `node 시험/성적서_대조시험.js <의뢰공문폴더> <시행·성적서폴더> [특이공문폴더]` | 실제 자료 | 특이 공문 시료, 시행공문 번호, 성적서 시료 수 = 파일 이름 건수, 짝짓기 |
| 화면 통합 | `python 시험/화면_통합시험.py <시험자료폴더>` | 시험용 폴더 | 브라우저에서 폴더 정리 → 대조 → 기한 → 설정 → 이력 문서 → 완료 → 되돌리기 → 직접 입력 → 엑셀 (Playwright 설치 필요) |

- 시험은 빌드가 만든 `시험/_엔진_묶음.js`를 씁니다. 엔진을 고친 뒤에는 **빌드 → 시험** 순서로 합니다.
- 엔진 회귀 기준 만들기: 고치기 **전에** `node 시험/엔진_회귀.js D:\공문` → `시험/결과/회귀_날짜.json`이 생깁니다. 고친 뒤 `node 시험/엔진_회귀.js D:\공문 시험/결과/회귀_날짜.json`.
- 시험 결과(`시험/결과/`)에는 실제 공문 내용이 들어가므로 배포 묶음에 넣지 않습니다.

## 4. 버전 올리기
1. `소스/00_틀/02_화면구성.html`의 `<span class="ver">v2.1</span>`
2. `소스/20_엔진/99_엔진_끝.js`의 `const ENGINE_VERSION = '2.1';`
3. `문서/변경이력.md`에 새 버전 항목, 매뉴얼 첫머리 버전

두 표기가 다르면 빌드가 `[주의]`로 알려 줍니다.

## 5. 부품 규칙 (꼭 지킬 것)

| 번호 | 규칙 | 이유 |
|---|---|---|
| 1 | **엔진(20_엔진)·화면(40_화면) 부품은 각각 한 함수 안에 이어 붙는다.** 다른 부품의 이름을 `import` 없이 바로 쓸 수 있다. 대신 맨 앞에 쓰는 `function`·`const`·`let` 이름이 **묶음 안에서 겹치면 안 된다.** | 겹치면 한쪽이 덮어써짐 → 빌드가 오류로 막음 |
| 2 | 부품 파일은 **혼자서는 실행되지 않는 조각**이다. `00_…_시작.js`, `99_…_끝.js`는 묶음의 앞뒤이므로 고치지 않는다(엔진 끝의 API 목록만 예외). | |
| 3 | 엔진 함수를 화면에서 새로 쓰려면 `20_엔진/99_엔진_끝.js`의 `API = { … }`에 이름을 더한다. 화면은 `E.이름` 또는 `E2.이름`으로 부른다(같은 묶음). | 엔진 밖으로 나가는 문 |
| 4 | 새 부품을 만들면 번호를 붙여 알맞은 폴더에 두고 `소스/빌드목록.txt`에 한 줄 추가. 머리말(하는 일·주요 이름·이럴 때 고침)을 쓰면 부품지도에 자동으로 실린다. | |
| 5 | 순서가 중요하다: **CSS는 뒤에 있는 규칙이 이긴다**, 엔진·화면 부품은 맨 위(부품을 읽을 때 바로 실행되는 줄)에서 뒤 부품의 이름을 쓰면 안 된다(함수 안에서 쓰는 것은 괜찮다). | |
| 6 | 새 버튼: ① `00_틀/02_화면구성.html`에 버튼(`id`) ② 기능을 해당 부품에 함수로 ③ `40_화면/18_이벤트_연결.js`의 `bindUi`에서 연결. | |
| 7 | `10_외부라이브러리`(pdf.js)는 고치지 않는다. | 공개 라이브러리 원본 |

**부품 머리말 형식** (새 부품에도 똑같이)

```js
/* ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   [40_화면/07_필터_정렬.js] 필터링·정렬
   하는 일 : 보기(처리 대기·임박·도착 등) 필터, 검색, 정렬 값
   주요 이름: isChecked, isUrgent, sortVal, visibleDocs, checkedGroups
   이럴 때 고침: 새 보기 필터·정렬 기준
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ */
```

## 6. Claude에게 수정을 맡길 때

전체 코드를 다시 읽지 않도록, 요청할 때 아래처럼 말하면 됩니다.

```
공문추출기 v2.1 수정 요청.
- 증상: (예) 성적서에서 '총유기탄소'가 결과 칸에 안 나온다
- 자료: (해당 파일 첨부 또는 폴더 경로)
부품지도.md를 보고 관련 부품만 읽고 고쳐 줘. 고친 뒤 빌드·시험하고 변경이력을 남겨 줘.
```

Claude 작업 순서(약속):
1. `문서/부품지도.md`(프로젝트 문서에도 있음)만 먼저 읽고 고칠 부품을 정한다.
2. 그 부품(필요하면 바로 이웃 부품 1~2개)만 읽고 고친다.
3. `python tools/build.py` → 검사 통과 확인 → 관련 시험(엔진이면 `처리기한_단위시험`·`엔진_회귀`, 화면이면 `화면_통합시험`).
4. 고친 부품 이름과 변경 줄을 변경이력에 적고, 바뀐 부품과 `공문추출기.html`만 다시 저장한다.

## 7. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| 빌드 창이 바로 닫힘 / 아무 일 없음 | 폴더를 압축 파일 안에서 직접 열었는지 확인 → 압축을 풀고 실행 |
| Windows: "Python 이 없어 간단 빌드로…" | 정상 동작(검사만 빠짐). 검사까지 하려면 python.org에서 Python 설치(설치 때 "Add to PATH" 체크) |
| Windows: PowerShell 오류 "스크립트를 실행할 수 없으므로" | 기관 보안 정책으로 막힘 → Python 설치 후 다시 실행, 또는 전산 담당자 문의 |
| Mac: "권한이 없어 열 수 없음" | 터미널에서 `chmod +x 빌드_mac.command` 한 번 실행. 처음 한 번은 오른쪽 클릭 → 열기 |
| 빌드 메시지 한글이 깨짐 (Windows) | 결과에는 영향 없음. Windows 10 이전 콘솔의 글꼴 문제 |
| 빌드는 됐는데 화면이 비거나 버튼이 안 됨 | Edge에서 F12 → 콘솔의 빨간 오류 → 오류 줄 위쪽의 `/* ===== 부품 ===== */`로 부품 확인. 직전 정상 파일은 `빌드결과/이전/` |
| `[오류] 이름 … 두 부품에 있음` | 5장 규칙 1. 새로 만든 쪽 이름을 바꾼다 |
