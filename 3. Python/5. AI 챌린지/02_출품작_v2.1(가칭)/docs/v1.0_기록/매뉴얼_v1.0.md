# 숫자지기 v1.0 매뉴얼

> **한글 보고서의 숫자마다 "어느 폴더 어느 파일 어느 칸에서 왔는지"를 찾아 대조하고, 고친 값과 출처를 이력으로 남기는 도구**

---

## 1. 최초 기획

### 1.1 배경
- 의회 보고자료·행정사무감사 요구자료는 여러 팀이 각자 엑셀에서 숫자를 옮겨 적고, 대표 팀이 이를 다시 취합한다.
- 옮겨 적는 단계마다 실수가 생긴다: 자리 바뀜(2.3→3.2), 합계 누락, 원·천원 혼동, 증감률 계산 실수, 요일 오기.
- 숫자의 출처가 기록되지 않아, 확인하려면 원본을 다시 뒤져야 하고, 원본이 나중에 바뀌면 어느 숫자가 영향을 받는지 알 수 없다.

### 1.2 목적
1. 숫자마다 **출처**(파일 전체 경로·시트·칸·파일 고유값)를 자동으로 찾는다.
2. 틀린 숫자는 **원본 값으로 바로 고치고**, 빈 칸은 원본을 골라 **[입력하기]** 로 채운다.
3. 모든 변경을 **이력**으로 남기고, 원본이 바뀌면 **영향받는 칸**을 알려 준다.

### 1.3 요구사항

| 번호 | 요구사항 | 결과 |
|---|---|---|
| R1 | hwpx와 엑셀 원본 대조 | ✅ |
| R2 | 행·열 이름이 달라도 대조 | ✅ 숫자 배열 모양으로 대조 |
| R3 | 일부만 복사·행 순서 바꿈·행열 뒤집기 대응 | ✅ |
| R4 | 원본 10개 이상에서도 정상 작동 | ✅ 18개에서 시험 |
| R5 | 원본끼리 값이 다르면 사용자가 선택 | ✅ |
| R6 | 프로그램에서 바로 수정 + 이력 | ✅ |
| R7 | 원본 셀 선택 → [입력하기] | ✅ |
| R8 | 출처를 폴더·파일까지 정확히 명시 | ✅ |
| R9 | 원본 변경 알림 | ✅ |
| R10 | 엑셀 복사 순간 출처 기록 | ✅(Windows, 미검증) |
| R11 | 원본 파일 수정 금지 | ✅ |
| R12 | 저사양 PC에서 동작, AI는 최소 보조 | ✅ v1.0은 AI 없이 계산으로 판정 |

## 2. 개발 과정

### 2.1 단계

| 단계 | 내용 | 결과물 |
|---|---|---|
| 1 | 실제 한글 문서(hwpx) 3개의 내부 구조 분석 — 문단·표·누름틀(필드) 구조 확인 | 문서 틀(header) |
| 2 | 시연 자료 생성기: 가상 기관의 원본 엑셀 12개, 팀 제출 hwpx 5개, 오류를 심은 취합본, 빈 작성틀, 정답표 | tools/make_demo.py |
| 3 | 엔진: hwpx·xlsx 읽기/쓰기(표준 라이브러리), 숫자 규칙, 표 블록 대조, 합계·비율·증감률·요일 재계산 | app/core |
| 4 | 이력 장부(SQLite), 작업본 버전, 원본 변경 감지, 내보내기 | ledger·workspace·report |
| 5 | 화면(HTML) + 로컬 서버 | app/ui, app/server.py |
| 6 | 검증: 정답표 채점, 자동 시험 20개, 화면 시험, 성능 시험 | tests/ |
| 7 | 재검토: 우연 일치 제거, 연쇄 오류 표시, 동시 조작 차단 | 아래 2.4 |

### 2.2 사용한 방법(쉬운 설명)

- **숫자 배열로 출처 찾기**: 문서 표의 숫자들이 원본의 어느 열·행에 몰려 있는지 "투표"해서 위치를 정한다. 이름(머리글)은 보지 않으므로 "총인"과 "T-P"처럼 이름이 달라도 찾는다. 행과 열을 뒤집은 표도 함께 시험한다.
- **반올림·단위 환산**: 원본 2.338을 문서에 2.3으로 적었으면 '반올림 일치', 원본 1,282,197,640원을 1,282,198천원으로 적었으면 '단위 환산 일치'.
- **우연 일치 걸러내기**: 큰 원자료 시트(지점별 측정값 등)에서 숫자가 우연히 맞는 경우를 막기 위해, 맞은 원본 칸이 여기저기 흩어져 있거나 반올림으로만 맞은 블록은 버린다.
- **누름틀**: 작업본의 숫자마다 한글 누름틀을 씌우고 `표2_은하천하류_BOD`처럼 이름을 붙인다. 문서를 고쳐도 이름으로 같은 칸을 다시 찾으므로 이력이 끊기지 않는다.
- **파일 고유값(SHA-256)**: 파일 내용으로 계산한 64자리 번호. 한 글자만 바뀌어도 달라지므로, 원본이 바뀌었는지 정확히 알 수 있다.

### 2.3 검증 결과

| 시험 | 결과 |
|---|---|
| 정답표 채점(심은 오류·정상 사례 18항목) | **18/18 일치**, 정답표에 없는 빨강·노랑 표시 **0개** |
| 원본 변경 후 채점 | **18/18 일치** |
| 자동 시험 20개 | **모두 통과**(개발 환경 Linux, 사용자 Mac 둘 다) |
| 성능 | 20만 칸 엑셀 읽기 1.8초 / 원본 18개 검증 1.2초(개발 환경), 사용자 Mac에서 7.4초 / 3.2초 |
| 화면 시험(시연 전체 흐름) | 통과, 화면 오류 0 |

> 위 결과는 개발 환경(Linux, Chromium 브라우저)에서 얻은 것이다. **한글 프로그램에서 생성 문서가 열리는지, Windows 클립보드 기록은 아직 직접 확인하지 못했다**(7장).

### 2.4 재검토에서 고친 것

| 발견한 문제 | 고친 내용 |
|---|---|
| 작은 정수(0·2·3)가 큰 원자료 시트의 소수 값과 반올림으로 우연히 맞아 엉뚱한 출처가 붙음 | 강한 근거·약한 근거 구분, 흩어진 블록 버림 |
| 원→천원 실수 하나 때문에 합계·비율 칸에 엉뚱한 '고칠 값'이 나옴 | 연쇄 오류로 표시하고 "먼저 ○○ 칸 확인" 안내 |
| 증감률 % 숫자에 우연히 같은 값의 원본이 출처로 붙음 | 계산으로 확인하는 숫자는 출처 후보를 보여 주지 않음 |
| 시연 준비 중에 [검증]을 누르면 반쯤 준비된 상태로 검증됨 | 서버가 작업을 하나씩 처리, 화면은 '처리 중' 동안 클릭 차단 |
| 값이 이미 같은 칸에 [입력하기]를 하면 아무것도 기록되지 않음 | 값은 그대로 두고 출처만 확정해 기록 |

## 3. 설치 및 사용

### 3.1 설치

| 순서 | 할 일 |
|---|---|
| 1 | Python 3.8 이상 설치: https://www.python.org/downloads/ (설치 첫 화면에서 **"Add python.exe to PATH"** 체크) |
| 2 | `숫자지기_v1.0` 폴더를 원하는 곳에 복사(예: `D:\도구\숫자지기_v1.0`) |
| 3 | 끝. 추가로 설치할 패키지는 없다(표준 라이브러리만 사용) |

> Python 설치가 어려운 PC: 휴대용 Python(Windows embeddable package)을 `숫자지기_v1.0\python\` 폴더에 풀어 두면 `.bat`이 그것을 사용한다.

### 3.2 폴더 구성

```
숫자지기_v1.0/
├─ 숫자지기_열기.bat            ← 이것을 더블클릭(Windows)
├─ 숫자지기_열기.command        ← Mac에서 시험할 때
├─ 시연자료_다시만들기.bat       ← 시연 자료를 처음 상태로 다시 생성
├─ README.md
├─ app/
│  ├─ server.py                 ← 실행 파일(로컬 서버)
│  ├─ config.py                 ← 바꿀 수 있는 설정값
│  ├─ core/                     ← 엔진(읽기·대조·이력·내보내기)
│  └─ ui/index.html             ← 화면
├─ tools/make_demo.py           ← 시연 자료 생성기
├─ tests/                       ← 자동 시험·채점·화면 시험
├─ docs/                        ← 설계서·매뉴얼
└─ 시연자료/                    ← 가상 기관 자료(아래 3.7)
```

### 3.3 처음 실행
1. `숫자지기_열기.bat`을 더블클릭한다. 검은 창이 뜨고 브라우저(Edge·Chrome)에 화면이 열린다.
2. 검은 창은 프로그램 본체다. **닫으면 프로그램이 꺼진다.** 작업 중에는 그대로 둔다.
3. 화면이 안 열리면 브라우저 주소창에 `http://127.0.0.1:8765` 를 입력한다.

### 3.4 화면 구성

| 탭 | 하는 일 |
|---|---|
| ① 작업 준비 | 작업 폴더 열기, 검증할 hwpx 선택, 원본(엑셀·팀 제출 hwpx) 등록, [원본 변경 확인] |
| ② 검증 | 문서를 색으로 표시. 숫자를 누르면 오른쪽에 출처·원본 미리보기·이력. [이 값으로 고치기] [이 출처로 확정] [직접 고치기] |
| ③ 입력하기 | 왼쪽 문서에서 칸을 누르고, 오른쪽 원본에서 셀을 끌어 고른 뒤 [입력하기] |
| ④ 이력 | 값 이력, 작업본 버전, 원본 변경 기록, 검증 기록 |
| ⑤ 설정·도움말 | 작업자 이름, 복사 기록(Windows), 사용 순서·색의 뜻 |

### 3.5 일상 업무 순서

1. **작업 준비**
   1. [작업 폴더 열기·만들기] → 이번 보고 건의 작업 폴더를 고르거나 새로 만든다(예: `문서\숫자지기\2026행감`).
   2. [문서 선택] → 취합한 hwpx를 고른다. **작업본 v001**이 만들어진다(원본 문서는 그대로).
   3. [폴더째 추가] → 원본 엑셀·팀 제출 hwpx가 든 폴더를 고른다. 하위 폴더까지 모두 등록된다.
2. **검증** → [검증 실행]
   - 빨강부터 확인한다. [다음 문제 ▶]로 차례로 이동할 수 있다.
   - 불일치: 오른쪽에서 원본 칸(주황 테두리)을 확인하고 **[이 값으로 고치기]**.
   - 출처 간 충돌: 어느 원본이 맞는지 판단해 맞는 쪽 값으로 고치거나 **[이 출처로 확정]**.
   - 출처 미확인: 계산한 값이면 근거를 확인하고, 원본이 따로 있으면 그 원본을 등록하거나 [입력하기]로 출처를 붙인다.
3. **입력하기**(빈 칸 채우기·출처 붙이기)
   - 자릿수(소수 몇 자리), 배율(÷1,000 등), 쉼표를 고른 뒤 넣는다.
4. **저장(새 버전)** → 메모를 적고 확인. 작업본 v002가 만들어지고 이력에 남는다.
5. **내보내기** → 출처대장(xlsx), 검증표시본(hwpx), 검증보고(html)가 `작업 폴더\내보내기`에 생긴다.
6. 원본을 받았다는 연락이 오면 → **[원본 변경 확인]** → 다시 검증 → 빨간 띠의 '바뀐 칸'만 확인.

> 작업본은 한글에서 열어 직접 고쳐도 된다(④ 이력 → [한글로 열기]). 저장하고 다시 검증하면 바뀐 칸이 '한글에서 직접 수정'으로 기록된다.

### 3.6 표시의 뜻

| 색 | 뜻 | 할 일 |
|---|---|---|
| 연녹 | 일치(반올림·단위 환산 포함), 계산 확인, 확정 | 없음 |
| 노랑 | 확인 필요: 출처 미확인 · 후보 여러 개 · **출처 간 충돌**(진한 노랑) | 출처 확인 후 확정 |
| 빨강 | 불일치 · 단위 다름 · 계산 오류 · 날짜·요일 오류 | 고치기 |
| 회색 | 빈 칸 | [입력하기]로 채우기 |
| 파란 점선 | 저장 전 변경(취소선=이전 값, 파랑=새 값) | [저장(새 버전)] |

|---|---|

심은 오류: 자리 바뀜(3.2↔2.3), 합계 오류, 원·천원 혼동, 집행률 오기, 증감률 오류(15.3%→실제 11.4%), 요일 오류(11. 25.(목)), 팀 제출본과 원본 충돌, 팀 문서→취합본 옮겨 적기 오류, 출처 없는 숫자. 정상 사례: 반올림, 단위 환산, 행·열 뒤바뀜, 머리글 다름, 합산값.

모든 기관·지명·수치는 가상이다.

## 4. 배포 방법

| 대상 | 방법 |
|---|---|
| 결과만 보는 사람(결재권자) | `내보내기` 폴더의 **검증보고 html**(인쇄)이나 **출처대장 xlsx**만 전달 |
| 담당자(직접 사용) | `숫자지기_v1.0` 폴더를 통째로 전달(시연자료 폴더는 빼도 됨). Python 설치 안내(3.1) |

## 6. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| 더블클릭해도 "Python 3.8 이상이 필요합니다" | Python 미설치 또는 PATH 미등록 → 3.1대로 설치(PATH 체크) 또는 휴대용 Python을 `python\` 폴더에 |
| 검은 창이 바로 닫힘 | 명령 프롬프트에서 `숫자지기_열기.bat` 실행해 오류 문구 확인 |
| 브라우저가 안 열림 | 주소창에 `http://127.0.0.1:8765` (8765가 사용 중이면 검은 창에 표시된 번호) |
| "프로그램과 연결이 끊겼습니다" | 검은 창이 닫힘 → 다시 실행(작업 내용은 작업 폴더에 남아 있음) |
| 문서 선택 시 "구형 hwp 또는 암호가 걸린 문서" | 한글에서 [다른 이름으로 저장] → 형식 hwpx, 암호 해제 |
| "이미 대상 문서가 있습니다" | 작업 폴더 1개 = 문서 1개. 새 문서는 새 작업 폴더에서 |
| 원본이 '읽기 실패' | 손상·암호·구형 xls → 엑셀에서 xlsx로 다시 저장 후 [빼기]→다시 추가 |
| 원본이 '파일 없음' | 파일을 옮김 → [빼기] 후 새 위치에서 추가 |
| 거의 모든 칸이 '출처 미확인' | 원본을 등록하지 않았거나 다른 원본을 등록함 → ① 작업 준비의 원본 목록 확인 |
| 맞는 값인데 '출처 미확인' | 여러 칸을 더한 값 등 계산값 → 근거 확인 후 그대로 두어도 됨 |
| "직접 고칠 수 없습니다" | 숫자가 한글 서식 때문에 여러 조각으로 나뉨 → 한글에서 작업본을 열어 고친 뒤 다시 검증 |
| 내보낸 hwpx가 한글에서 안 열림 | v1.0 미검증 항목 → 작업본·검증표시본 파일을 개발자에게 전달(한글_호환성_점검 결과와 함께) |
| 복사 기록 [켜기]가 비활성 | Windows가 아닌 PC → Windows에서만 동작 |

## 7. 주의

1. **원본·대상 문서는 수정하지 않는다.** 수정은 작업본(v002…)에만 저장된다. 제출할 때는 최신 작업본을 한글에서 열어 최종 확인 후 [다른 이름으로 저장]한다.
2. `숫자지기작업.db`(이력 장부)를 지우면 이력이 사라진다. `백업` 폴더에 하루 1회 자동 백업이 있다.
3. '일치'는 **원본과 같다**는 뜻이지 **원본이 맞다**는 뜻이 아니다. 원본 자체의 오류는 이 도구가 찾지 못한다.
4. 계산값(합산·평균 등)은 원본에 그대로 없으면 '출처 미확인'으로 나온다. 틀렸다는 뜻이 아니다.
5. 대조는 **숫자 글자** 기준이다. 글꼴·서식·그림 속 숫자는 보지 않는다.
6. 시연·개발에는 가상 자료만 쓴다. 실제 업무 자료에 개인정보가 있으면 출처대장 xlsx에도 그 값이 들어가므로 보관에 주의한다.
7. **미검증 항목**: 생성 hwpx의 한글 호환성, Windows 실행·클립보드 기록, Microsoft Excel에서의 출처대장 열기. `시연자료/한글_호환성_점검/`으로 먼저 확인한다.
