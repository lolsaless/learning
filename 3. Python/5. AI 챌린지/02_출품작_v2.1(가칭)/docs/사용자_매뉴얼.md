# 취합검증 도우미(가칭) v2.1 — 사용자 매뉴얼

- 한 줄 소개: **여러 원본을 모아 만든 문서의 숫자마다 원본 출처를 찾아 대조하고, 다시 받은 원본의 바뀐 곳과 문장 속 계산·AI가 쓴 글의 숫자까지 검증하며, 고친 값과 출처를 이력으로 남기는 도구**
- 이름은 가칭이다. 정식 이름은 `app/config.py` 의 `APP_NAME` 한 줄로 바꾼다.
- 작성: 2026-10-29

---

## 1. 무엇을 해 주나

| 고민 | 이 프로그램이 하는 일 |
|---|---|
| 여러 팀 엑셀을 옮겨 적다 숫자가 틀림 | 문서의 모든 숫자를 원본 엑셀·팀 제출 hwpx와 대조해 **빨강(틀림)·노랑(확인 필요)·연녹(일치)** 으로 칠한다 |
| 합계·비율·증감률·요일이 맞는지 일일이 계산 | 표 합계 행·열, 비율(%) 열, "전년 대비 ○% 증가" 문장, 날짜 요일을 다시 계산한다 |
| "이 숫자 어디서 왔지?" | 숫자마다 출처(파일 전체 경로·시트·칸·파일 고유값)를 찾아 보여 주고 **출처대장**으로 남긴다 |
| 팀이 엑셀을 고쳐 다시 보냄 | 이전 판과 **칸 단위로 비교**해 바뀐 칸과 **고쳐야 할 문서 칸·새 값**을 보여 준다. 이름을 바꿔 보낸 파일(`…(수정).xlsx`)도 짝을 찾는다 |
| 원본이 엑셀·구형 한글·PDF·CSV·워드로 제각각 | **14개 형식**(hwpx·hwp·xlsx·xlsm·xls·ods·csv·tsv·docx·odt·pdf·txt·md·html)을 같은 방식으로 읽는다 |
| "전체 480건 중 96건(20.0%)", "○○보다 312건 많음" 같은 문장 속 계산 | 다시 계산해 틀리면 빨강. 정해지지 않은 문형은 **AI(선택)** 가 검산식으로 읽고 프로그램이 계산 |
| 생성형 AI 가 쓴 보고서 초안의 숫자 | [글 붙여넣기]로 원본과 대조. 원본에 없는 숫자(지어낸 숫자)는 '출처 미확인' |
| 누가 언제 무엇을 고쳤는지 모름 | 값이 바뀔 때마다 이전 값·새 값·방법·출처·작업자를 이력에 쌓는다(지우지 않음) |
| 시연·평가용 자료가 없음 | **무작위 가상자료**(가상 기관의 원본·답변서·오류 심은 취합본·공문·참고자료·정답표)를 만들고 **자동 채점**한다 |

판정은 모두 **규칙과 계산**으로 한다. AI 는 문장을 읽는 일만 하고, 그 답도 프로그램이 검사한다(8장). 원본 파일은 읽기만 하고, 고친 내용은 작업 폴더의 새 파일로 저장한다.

## 2. 설치와 실행

### 2.1 준비물

| 항목 | 내용 |
|---|---|
| 운영체제 | Windows 10·11(주 사용), macOS·Linux(시험용) |
| Python | **3.8 이상**(표준 라이브러리만 사용, 추가 설치 없음). 3.8.20·3.10(사용자 PC)·3.13에서 전체 시험 통과 |
| 브라우저 | Edge·Chrome(인터넷 연결 불필요) |
| 파일 형식 | 검증 대상: hwpx(고치기 가능), hwp·docx·odt·pdf·txt·md·html·붙여 넣은 글(읽기 전용 검증) / 원본: 위 14개 형식 모두 |
| AI(선택) | 없어도 됨. 쓰려면 내 컴퓨터에 Ollama 또는 LM Studio 등(8장) |

Python 설치(Windows): python.org 에서 내려받아 설치 화면 첫 장의 **"Add python.exe to PATH"** 를 체크한다. 설치가 어려우면 인터넷이 되는 PC 에서 `휴대용Python_넣기_Windows.bat` 을 한 번 실행한다. 프로그램 폴더 안 `python\` 에 공식 휴대용 Python 이 들어가고, 이 폴더째 옮기면 Python 이 없는 PC 에서도 `실행_Windows.bat` 이 그대로 동작한다(**미검증**: Windows 실기 확인 필요).

### 2.2 실행 파일(더블클릭)

| Windows | Mac | 하는 일 |
|---|---|---|
| `실행_Windows.bat` | `실행_Mac.command` | **프로그램 실행**(브라우저 화면이 열림) |
| `휴대용Python_넣기_Windows.bat` | — | `python\` 폴더에 휴대용 Python 넣기(한 번) |
| `시연자료_만들기_Windows.bat` | `시연자료_만들기_Mac.command` | 무작위 시연자료 3개 만들기 |
| `자동평가_Windows.bat` | `자동평가_Mac.command` | 무작위 시나리오 20개로 자동 평가 → 보고서 |
| `시험_전체실행_Windows.bat` | `시험_전체실행_Mac.command` | 자동 시험 전체(구조·기능·가상자료) |
| `기본시연자료_다시만들기_Windows.bat` | (명령: `python3 tools/make_demo.py`) | 고정 시연자료(한빛도) 다시 만들기 |

### 2.3 처음 실행
1. `실행_Windows.bat` 을 더블클릭한다. 검은 창이 뜨고 브라우저에 화면이 열린다.
2. 검은 창이 프로그램 본체다. **닫으면 프로그램이 꺼진다.**
3. 화면이 안 열리면 주소창에 `http://127.0.0.1:8765` 를 입력한다(사용 중이면 검은 창에 나온 번호).
4. 이 PC 안에서만 열리는 주소다. 다른 PC에서는 접속할 수 없다.

## 4. 일상 업무 순서

1. **작업 준비**
   1. [작업 폴더 열기·만들기] → 이번 보고 건의 작업 폴더를 고르거나 만든다.
   2. [문서 선택] → 취합한 문서를 고른다. hwpx 면 **작업본 v001** 이 만들어진다(원본 문서는 그대로). 그 밖의 형식은 '읽기 전용 검증'(대조·재계산·보고서는 되고 고치기는 원래 프로그램에서). AI 가 쓴 글은 [글 붙여넣기].
   3. [폴더째 추가] → 원본(엑셀·hwp·PDF·CSV 등)·팀 제출 문서가 든 폴더를 고른다(하위 폴더까지, 읽을 수 있는 형식만 등록).
2. **검증** → [검증 실행 →]
   - 빨강부터 본다. [다음 문제 ▶]로 차례로 이동한다.
   - 불일치: 오른쪽 원본 칸(주황 테두리)을 확인하고 **[이 값으로 고치기]**.
   - 출처 간 충돌: 어느 원본이 맞는지 판단해 맞는 값으로 고치거나 **[이 출처로 확정]**.
   - 출처 미확인: 계산한 값이면 근거를 확인한다. 원본이 따로 있으면 등록하거나 [입력하기]로 출처를 붙인다.
3. **입력하기**: 자릿수·배율(÷1,000 등)·쉼표를 고른 뒤 넣는다. 값이 이미 같으면 바꾸지 않고 출처만 확정한다.
4. **저장(새 버전)**: 메모를 적고 확인 → 작업본 v002 가 생기고 이력에 남는다.
5. **내보내기**: `작업 폴더\내보내기` 에 출처대장(xlsx)·검증표시본(hwpx)·검증보고(html).
6. 팀이 원본을 고쳐 보냈다면 → 9장(재제출 비교).

작업본은 한글에서 직접 고쳐도 된다. 저장 후 다시 검증하면 바뀐 칸이 '한글에서 직접 수정'으로 이력에 남는다.

### 4.1 내보내기 파일

| 파일 | 내용 |
|---|---|
| 출처대장_문서_날짜.xlsx | 검증결과(칸별 상태·출처 전체 경로·시트·칸·원본 값) / 값 이력 / 원본 목록(고유값) / 원본 변경 기록 / 작업본 버전 |
| 검증표시본_문서_v00N_날짜.hwpx | 작업본 사본. 틀린 칸 빨간 굵은 글씨, 확인 필요 칸 노란 배경 |
| 검증보고_문서_날짜.html | 인쇄용 요약(브라우저에서 Ctrl+P). 효과 추정·본문 문장 검산 표 포함 |

검증표시본(hwpx)은 대상이 hwpx 일 때만 만든다. 다른 형식은 출처대장·검증보고만 만든다.

## 5. 시연자료 만들기(5 시연자료 탭)

### 5.1 고정 시연자료와 무작위 시연자료

| 구분 | 고정 시연자료 | 무작위 시연자료 |
|---|---|---|
| 위치 | `시연자료/` | `시연자료_무작위/<도이름>_<씨앗값>/` |
| 기관 | 한빛도 보건환경연구원(항상 같음) | 가상 기관 8곳 중 무작위 |
| 쓰임 | 시연 영상·자동 시험 기준(정답표 18개) | 다양한 평가·시연, 기능 개발 시험 |
| 시작 | 1 작업 준비 → [시연 시작] | 5 시연자료 → [이 자료로 시연] |

### 5.2 만들기 설정

| 설정 | 뜻 |
|---|---|
| 씨앗값 | 같은 값이면 언제나 같은 자료가 만들어진다. 비우면 무작위 |
| 크기 | 작게(요구자료 5개)·보통(8개)·크게(12개) |
| 오류 수 | 취합본에 심을 오류 수(0~30). 표 수보다 많으면 문장 오류로 채운다 |
| 오류 종류 | 자리 바뀜·옮겨 적기 오타·합계·단위 혼동·비율·증감률·요일·출처 간 충돌·출처 없는 숫자·**문장 계산 오류**(차이·비중·배수·합계) |
| 함께 만들 문서 | 공문(요구·검사 의뢰·결과 알림·협조 요청) / 참고자료(시험법 요약본·장비 점검 매뉴얼·작성 지침) / 작성틀 / 재제출본 |
| 공문 형식 | hwpx + odt, hwpx 만, odt 만 |
| 취합본 형식 | hwpx·docx·pdf·odt·md·무작위 섞기 — hwpx 가 아니면 읽기 전용 검증 시연 |
| 원본 형식 섞기 | 원본을 xlsx·ods·csv·pdf·docx 로 섞어 만듦(실제 업무 폴더처럼). 팀 답변서도 hwpx·docx·pdf 로 섞임 |
| 자유 문형 계산 문장 | 정해지지 않은 문형의 계산 문장을 섞음(AI 읽기 시험용. AI 없이 채점하면 이 문장들은 채점에서 뺌) |

### 5.3 만들어지는 것

```
<도이름>_<씨앗값>/
├─ 공유폴더(가상)/2026 행정사무감사/
│  ├─ 00_공문함/     요구 공문, 검사 의뢰 2건, 결과 알림 2건, 협조 요청(hwpx·odt)
│  ├─ 01_원본자료/   팀별 원본 엑셀(머리글을 코드·다른 이름으로, 행·열 뒤집기, 원 단위, 월별 시트, 세부기록 등)
│  ├─ 02_팀제출/     팀 답변서 hwpx
│  ├─ 03_취합/       취합본(오류 심음), 작성틀
│  └─ 04_참고자료/   시험법 요약본 2개, 장비 점검 매뉴얼, 요구자료 작성 지침
├─ 나중에_받은_자료/  재제출본 2개(같은 이름 1개, '(수정)' 붙은 이름 1개)
├─ 정답표.json        자동 채점용: 대조 오류·연쇄·정상 사례 / 재제출 바뀐 칸 / 문서 판정
└─ 시나리오_안내.md   사람이 읽는 요약(심은 오류 표)
```

## 7. 읽을 수 있는 파일 형식

| 형식 | 원본으로 | 검증 대상으로 | 비고 |
|---|---|---|---|
| hwpx | ✅ | ✅ 고치기 가능(작업본·누름틀) | |
| hwp(한글 2002 이후, HWP 5.0) | ✅ | ✅ 읽기 전용 | 암호·배포용 hwp 는 못 읽음 → 한글에서 풀고 저장 |
| xlsx · xlsm · xls · ods | ✅ | — | xls 는 97-2003 형식. 'xls' 이름의 HTML 표 파일도 읽음 |
| csv · tsv | ✅ | — | UTF-8·CP949(한국어 윈도우) 자동 판별 |
| docx · odt | ✅ | ✅ 읽기 전용 | 전자문서시스템 내려받기 odt 포함 |
| pdf | ✅ | ✅ 읽기 전용 | 글자가 있는 PDF. 표는 테두리선·칸 간격으로 복원, 쪽이 넘어가도 한 표로 이음. **스캔(그림) PDF 는 못 읽음** |
| txt · md · html | ✅ | ✅ 읽기 전용 | 마크다운 표·탭 표·HTML 표 |
| doc · ppt · pptx · hwt · 그림 | ✗ | ✗ | 안내 문구: docx·PDF 로 저장해서 쓰기 |

- **읽기 전용 검증**: 원본과 대조·합계·증감률·문장 계산·요일 확인·출처대장·검증보고는 모두 되고, 고치기(누름틀·작업본 저장)만 안 된다. 고칠 것은 원래 프로그램에서 고친 뒤 다시 검증한다.
- 원본이 문서(hwp·docx·pdf 등)면 출처는 `표2 3행 4열` 처럼 표 위치로, 시트(xlsx 등)면 `시트!B4` 로 적힌다.
- **글 붙여넣기(AI 초안 검증)**: 1 작업 준비 → [글 붙여넣기] → 생성형 AI 가 쓴 보고서·메일 본문을 붙여 넣는다. 마크다운 표(`| 가 | 나 |`)·탭 표는 표로 읽는다. 원본 어디에도 없는 숫자는 '출처 미확인'(노랑)으로 표시되어 **지어낸 숫자**를 찾을 수 있다.

## 8. AI(선택 기능)

### 8.1 AI 가 하는 일과 하지 않는 일

| AI 가 하는 일 | AI 가 하지 않는 일 |
|---|---|
| 정해지지 않은 문형의 **문장 속 계산을 검산식으로 읽기**(예: "1,520건을 기록해 1,208건에 그친 본청을 312건 앞섰음" → `1,520 − 1,208 = 312`) | 맞다·틀리다 판정(프로그램이 계산) |
| 검증 결과 **요약 초안** 쓰기 | 원본 값 찾기·고치기 |

AI 답은 프로그램이 세 번 검사한다: ① 형식(JSON)이 맞는가 ② **숫자가 모두 문장에 그대로 있는가**(없으면 '지어낸 숫자'로 버림) ③ 프로그램이 직접 계산. AI 가 읽은 식이 틀리면 **노랑(확인 필요)** 으로만 표시한다(AI 가 숫자 짝을 잘못 지었을 수 있으므로). 빨강은 규칙과 계산으로만 나온다.

AI 가 없어도 다음 문형은 **규칙으로 자동 검산**한다: "…○건으로 ○○(○건)보다 ○건 많음/적음", "전체 ○건 중 ○○이 ○건(○%)", "○○(○건)은 ○○(○건)의 ○배", "○ ○건, ○ ○건을 합하여 총 ○건", "…(○건) 대비 ○% 증가/감소".

### 8.2 설정(7 설정·도움말 → AI)

1. 내 컴퓨터에 AI 를 설치한다. 예: **Ollama**(ollama.com) 설치 → 명령 창에서 `ollama pull exaone3.5:7.8b`
2. 종류: `Ollama(내 컴퓨터)` · 주소: `http://127.0.0.1:11434`(자동) · 모델 이름: `exaone3.5:7.8b`
3. [저장] → [연결 시험] → "연결됨 · 시험 문장 검산식 1개" 가 나오면 준비 끝.
4. 2 검증 → **[AI 로 문장 읽기]**. 결과는 검증 화면 위 '본문 문장 검산' 목록과 검증보고에 남는다(읽은 쪽: 규칙/AI·모델 이름, 버린 답과 이유).

| 종류 | 주소(기본) | 예 |
|---|---|---|
| Ollama | `http://127.0.0.1:11434` | exaone3.5:7.8b · qwen2.5:7b · gemma2:9b |
| OpenAI 호환 서버 | `http://127.0.0.1:1234` | LM Studio · llama.cpp server · vLLM 에 올린 모델 |
| 시험용 모의 AI | — | 실제 AI 아님(시연·시험용, 정해진 문형만 흉내) |

- **모델 바꾸기** = 모델 이름만 바꾸고 [저장]. 코드는 그대로다.
- **보안**: 기본 설정은 내 컴퓨터(127.0.0.1)의 AI 만 쓸 수 있다. 문서 내용이 다른 컴퓨터로 나가지 않는다(`app/config.py` 의 `AI_ALLOW_REMOTE`).
- **모델 비교**: `python tools/ai_eval.py --models ollama:exaone3.5:7.8b ollama:qwen2.5:7b --n 10` → `평가결과/AI모델비교_*.md`(AI 문장 수·버린 답·검출·빨강 오탐·시간).

### 8.3 검증 요약 만들기

2 검증 → [검증 요약 만들기]: **규칙 요약**(검증 숫자로 만든 문장, 항상 정확)과, AI 를 설정했다면 **AI 요약 초안**을 보여 준다. AI 요약에 검증 결과에 없는 숫자가 있으면 노란 표시와 경고가 나온다.

## 9. 재제출 비교(팀이 원본을 다시 보냈을 때)

| 상황 | 할 일 | 보여 주는 것 |
|---|---|---|
| 같은 이름으로 덮어씀(공유 폴더 파일이 바뀜) | 1 작업 준비 → **[원본 변경 확인]** | 바뀐 원본마다: 바뀐 칸(이전 → 이후), 행 추가·삭제, **고쳐야 할 문서 칸과 새 값** |
| 이름을 바꿔 보냄(`…(수정).xlsx`, `…_최종.xlsx`) | **[다시 받은 파일 비교]** → 파일 선택 | 어느 원본의 새 판인지(이름·내용 점수), 위와 같은 비교. [확인]을 누르면 원본을 새 파일로 바꾸고 다시 검증 |

- 원본을 등록하거나 바뀔 때마다 그 판이 작업 폴더 `원본보관/` 에 복사되어 있어서 비교할 수 있다(원본 파일은 건드리지 않음).
- 형식이 달라도 비교한다(예: 처음엔 xlsx, 다시 받은 것은 PDF).
- 다시 검증하면 바뀐 칸이 빨강(불일치)으로 보이고 '고칠 값'에 새 값이 나온다 → [이 값으로 고치기].
- 한계: 여러 칸의 평균·합으로 만든 문서 값(월평균 등)은 '새 값'을 미리 계산하지 않는다(다시 검증하면 빨강). PDF·워드로 받은 원본은 표시된 자릿수까지만 알 수 있어 끝자리 1 차이가 날 수 있다.

## 11. 6 구성도 보는 법

- 다섯 층: **U 화면 → W 화면 연결 → A 조립부 → P 기능 파트 → B 바탕**. 위층이 아래층을 쓰고, 아래층은 위층을 모른다.
- 상자 하나 = 구성요소 하나(번호 예: P3 검증). 누르면 오른쪽에 파일·줄 수·클래스·함수·화면 주소가 나온다.
- 파랑 = 고른 구성요소가 쓰는 것, 주황 = 그것을 쓰는 것.
- 아래 **고칠 곳 찾기** 표: "이걸 고치려면 어느 파일" 안내.
- 코드를 직접 읽어 만들므로 늘 최신이다. 같은 내용이 `docs/파트지도.md` 에도 있다(`python tools/part_map.py` 로 다시 만듦).

## 13. 주의

1. **원본·대상 문서는 수정하지 않는다.** 수정은 작업본(v002…)에만 저장된다.
2. `작업장부.db`(이력 장부)를 지우면 이력이 사라진다. `백업` 폴더에 하루 1회 자동 백업이 있다.
3. '일치'는 **원본과 같다**는 뜻이지 원본이 맞다는 뜻이 아니다.
4. 대조는 숫자 글자 기준이다. 그림 속 숫자·서식은 보지 않는다.
5. 시연·개발에는 가상 자료만 쓴다. 실제 업무 자료를 쓰면 출처대장에도 그 값이 들어가므로 보관에 주의한다.
