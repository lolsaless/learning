# 심사 검토서 — 취합검증 도우미(가칭)

- 검토 대상: v2.0(2026-10-29 오전판) → 개선판 v2.1
- 기준: 「2026 공공 AI 대전환 챌린지」 참가 안내서 세션1 평가 기준(필요성 20 · 창의성 30 · 활용성 20 · 완성도 15 · 확산가능성 15)과 공통 개발 규칙
- 방법: 심사위원이 구동안내서대로 프로그램을 켜고, 제출 서류와 산출물을 본다고 가정했다. 점수는 **검토자의 추정**이다(공식 점수 아님).

## 2. 감점 요인과 개선(우선순위 순)

| 순위 | 감점 요인 | 영향 지표 | 개선 내용(v2.1) |
|---|---|---|---|
| 1 | AI 미사용, 모델 비종속 미입증 | 창의성·확산 | **AI 파트**: 모델 교체형 연결(Ollama·OpenAI 호환 = EXAONE·Gemma·GPT-OSS·Solar 등), AI가 문장을 검사식으로 바꾸고 **코드가 다시 계산해 채택**, 결과 요약문의 숫자를 코드가 검증, 모델 비교 평가 도구 |
| 2 | 'AI 신뢰성 확보' 주제와 연결 없음 | 창의성·필요성 | **AI 초안 검증**: 생성형 AI가 쓴 보고서 글을 붙여 넣으면 숫자·합계·증감률·요일을 원본과 대조(환각 숫자 = '출처 미확인') |
| 3 | 파일 형식 제한 | 활용성·확산 | **형식 등록부**: hwp(구형)·hwpx·xls·xlsx·xlsm·ods·csv·tsv·docx·odt·pdf·txt·md·html 읽기. hwpx 외 문서도 검증 대상(읽기 전용)으로 사용 |
| 4 | 무엇이 바뀌었는지 모름 | 활용성 | **재제출 비교 파트**: 원본 보관본과 비교해 바뀐 칸·문서 영향 칸(이전→이후) 표시, 이름을 바꿔 다시 보낸 파일도 '새 판 후보'로 짝지음 |
| 5 | 효과 수치 없음 | 필요성·활용성 | 검증 결과에 **수작업 대비 절감 시간 추정**(칸당 확인 시간은 설정값, 추정임을 표시) |
| 6 | Windows 구동 위험 | 완성도 | 휴대용 Python 묶음 만들기 도구, 실행 파일 점검. 실제 Windows 시험은 사용자 확인 필요 |
| 7 | 시험 자료가 hwpx·xlsx뿐 | 완성도 | 가상자료가 원본·대상을 여러 형식으로 섞어 만들고, 자동 평가가 형식별·재제출·AI 검증까지 채점 |

## 4. 남은 일(제출 전, 사용자 확인 필요)

| 순서 | 할 일 | 이유 |
|---|---|---|
| 1 | 사용자 PC 에서 `python tests/run_all.py` → 전체 통과 | 개발 환경 밖 첫 확인 |
| 2 | Ollama 설치 → `ollama pull exaone3.5:7.8b` 와 다른 모델 1개 → `python tools/ai_eval.py --models ollama:exaone3.5:7.8b ollama:<다른 모델>` | 신청서 '사용 모델명/교체 가능여부' 근거(모델 비종속) |
| 3 | `시연자료/한글_호환성_점검/` hwpx 를 한글에서 열기 | 작업본·검증표시본이 열리지 않으면 핵심 기능 실패 |
| 4 | Windows PC(가능하면 Python 없는 PC + 휴대용 Python)에서 `실행_Windows.bat` | 구동안내서대로 구동 못 하면 제외 |
| 5 | 실제 업무 hwp·PDF·xls 몇 개를 원본으로 등록해 '읽기 실패'가 없는지(내용은 대화에 붙이지 않음) | 형식 지원 실사용 확인 |
