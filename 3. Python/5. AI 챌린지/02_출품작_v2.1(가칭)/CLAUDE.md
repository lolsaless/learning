# 개발 규칙 (Claude가 매 대화 시작 때 읽음)

## 1. 시작
- 이 파일과 `진행현황.md` 를 먼저 읽는다. 지금 단계와 다음 할 일은 진행현황.md 1장·7장.
- 구성요소·파일·함수 위치는 `docs/파트지도.md`(자동 생성), 고치는 방법은 `docs/유지보수_안내.md`, 설계는 `docs/설계서_v2.1.md`.
- 사용자 폴더는 device_bash 로 직접 다룬다(`$HOME/mnt/5. AI 챌린지/02_출품작_v2.1(가칭)/`). 한글 경로는 `cd "$HOME/mnt"/*AI*/02_*/` 처럼 글롭으로 찾는다.
- 폴더 구성: `01_대회자료/`(공고·참가 안내서) · `02_출품작_v2.1(가칭)/`(지금 판) · `99_보관/`(v2.0·숫자지기·버전지기·기획문서). 안내는 `00_폴더_안내.md`.

## 2. 구조 규칙(자동 시험으로 검사)
- 기능 하나 = `app/parts/<이름>/`(part.py · routes.py · README.md). **파트는 다른 파트를 import 하지 않는다.**
- 파트끼리 값이 필요하면 조립부 `app/workspace.py` 에서 넘긴다(인자 또는 콜백).
- common·formats·store 는 파트·조립부·web 을 모른다.
- 바뀔 수 있는 값은 `app/config.py`. 이름은 가칭 → `APP_NAME` 만 사용.
- 화면: `ui/pages/<이름>.html` + `ui/js/pages/<이름>.js`. 서버와는 `api()` 로만.
- 파이썬 파일 하나 800줄 이하. Python 3.8 문법까지만(3.9+ 문법 금지: dict | dict, match 등).
- 새 기능을 시험할 자료는 가상자료 파트(정답표.json)로 만든다. 재제출 비교는 정답표의 '재제출'(evaluation.score_resubmit), 양식 분석은 '양식' 항목으로 채점한다.
- 새 파일 형식은 `app/formats/registry.py` 한 줄 + 읽기 함수(유지보수 안내 4.4). AI 읽기 결과는 빨강으로 단정하지 않는다(노랑까지).

## 3. 불변 규칙(대회)
- 원본 읽기 전용. 작업본·보관본·내보내기는 작업 폴더 안에만.
- 표준 라이브러리만(설치 없이 실행). 외부 인터넷·외부 라이브러리 0.
- 합성 모의데이터만. 실제 업무 문서 내용을 대화에 붙이지 않는다.
- AI는 보조. 판정은 계산, AI 출력은 코드가 검증. AI가 없어도 전 기능 동작.
- 확인한 것과 추정한 것을 구분, 직접 시험 못 한 것은 "미검증".

## 4. 단계 마무리
1. `python3 tests/run_all.py` → 전체 통과(가능하면 Python 3.8 로도)
2. 엔진·형식을 바꿨으면 `python3 tools/evaluate.py --n 100 --seed 40000` 과 `--n 25 --src-mix --target-fmt mix` — 빨강 오탐이 늘면 되돌림
3. 화면을 바꿨으면 서버 켜고 `tests/e2e_ui.py` · `tests/e2e_mock.py` · `tests/e2e_v21.py`
4. `python3 tools/part_map.py` 로 파트 지도 갱신
5. 진행현황.md 갱신(상태·결정·미검증·다음 할 일)
6. 답변: ① 결과 ② 사용자가 확인할 것(표) ③ 다음 단계 시작 문장
