## 3. 절대 규칙
| 번호 | 규칙 |
|---|---|
| R1 | 감시 폴더의 원본은 **읽기만** 한다. 수정·이동·삭제 코드 금지. 산출물은 작업 폴더에만 쓴다(대회 공통 규칙) |
| R2 | 결과 HTML은 **외부 링크 0개**(CDN·글꼴·이미지 포함). 외부 라이브러리 없이 브라우저 내장 기능·자체 구현만 사용 |
| R3 | 개발·시험·시연 자료는 **합성 모의데이터만**. `samples/`의 실제 파일은 구조 확인용이며 저장소·제출물에 넣지 않는다 |
| R4 | AI는 **선택 기능**. AI가 꺼져도 다른 모든 기능이 동작해야 한다. AI 출력은 반드시 `ai/verify.js`를 거친다 |
| R5 | 확실하지 않은 판정은 자동 처리하지 않고 "확인 필요"와 사유를 남긴다 |
| R6 | 한 파일 실패가 전체를 멈추지 않는다 |
| R7 | 문서 내용은 PC 밖으로 보내지 않는다(AI 기본 주소는 127.0.0.1) |
| R8 | 이번 단계 범위 밖 기능은 만들지 않는다. 필요하면 `진행현황.md`의 "나중에" 목록에 적는다 |

## 4. 코드 규칙
- 언어: JavaScript(ES 모듈), 의존 패키지 0개. 실행·시험: Node.js 22(`node --test`)
- `src/core, extract, lineage, diff, classify, integrate, ai(verify·prompts·mask)`는 **화면(DOM)을 쓰지 않는 순수 함수**로 만든다 → Node 시험과 Web Worker에서 그대로 실행
- XML은 `core/xmlsax.js`(자체 SAX)로 읽는다. `DOMParser` 금지(작업 스레드에 없음)
- 바꿀 수 있는 값(판정 기준값, 파일명 정리 규칙, 제외 패턴, 기준 열 사전, AI 기본값)은 `src/config/defaults.js` 한곳에 둔다
- 빌드: `npm run build` → `dist/버전지기.html` 한 파일
- 파일명·문자열은 NFC로 정규화(맥 자모 분리 대응)
- 주석·화면 문구·오류 메시지는 한국어

## 5. 작업 방식
1. 시작: `진행현황.md` → 이번 단계 표 → 설계서의 해당 장을 읽는다
2. 작업: 엔진은 시험부터 쓰고 구현한다. 모의데이터로 확인한다
3. 끝: `npm test` 통과 → `npm run build` → `진행현황.md`의 단계 상태·결정·미검증·다음 할 일 갱신 → 사용자에게 결과와 확인 요청을 표로 보고
4. 직접 시험하지 못한 것(실제 Edge·한글·엑셀 화면, 업무망, Ollama 연결)은 **"미검증"**으로 적는다
