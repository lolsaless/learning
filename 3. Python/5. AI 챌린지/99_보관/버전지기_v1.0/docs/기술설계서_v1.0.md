## 1. 용어와 범위

### 1.1 세 가지 핵심 기능의 정의

| 기능 | 이 시스템에서의 뜻 | 결과물 |
|---|---|---|
| **분류** | ① **문서 묶기(계보)**: 이름이 달라도 내용이 같은 문서의 여러 버전을 하나의 "문서"로 묶는다. ② **업무 분류**: 문서를 "수질검사·감사·회의" 같은 업무 범주에 넣는다 | 문서 목록, 버전 나무, 분류 |
| **비교** | 같은 문서의 두 버전 사이에서 바뀐 문단·표 셀·시트 셀·숫자를 찾아 보여 준다 | 비교 창, 변경 목록 |
| **통합** | 한 문서의 모든 버전을 **하나의 이력**으로 합쳐 관리한다. 최신본 결정, 누적 변경내역, AI 요약, 정리본 폴더 생성, 두 갈래 수정본의 병합 검토표가 여기에 해당한다 | 문서 이력 화면, 정리본 폴더, 변경내역 보고서(HTML·xlsx), 병합 검토표 |

> "통합"은 **새 hwpx 파일을 자동으로 합쳐 쓰는 것이 아니다.** 두 수정본을 하나로 합친 문서를 프로그램이 직접 만들면 서식이 깨질 위험이 크다. 이번 판에서는 어느 쪽 변경을 받아들일지 정리한 **병합 검토표**까지 만들고, 실제 병합은 한글·엑셀에서 사람이 한다. 자동 병합 파일 생성은 대회 이후 과제로 둔다.

### 1.2 우선순위 (11. 11. 기준)

| 등급 | 뜻 | 기능 |
|---|---|---|
| **필수** | 없으면 제출하지 않음 | hwpx·xlsx 읽기, 폴더 감시, 계보 묶기, 비교 창(문단·표·셀·숫자), 문서 이력 화면, 최신본 결정, AI 변경 요약 + 검증, 정리본 내보내기(복사), 체험 모드(자동 시작·중지), 정답 채점표 |
| **권장** | 일정 안에 넣음 | 업무 분류 규칙, AI 분류 추천, 통합 변경내역 보고서(누적), 검색, 확인 필요함 |
| **선택** | 남는 시간에 | 갈래 병합 검토표, 표준 파일명 제안, 변경내역 xlsx 저장 |
| 제외 | 대회 이후 | 원본 이동·삭제, 자동 병합 hwpx 생성, 구형 hwp·xls 본문 분석, 한글 자동화 연계, 로그인 시 자동 실행 |

일정이 밀리면 **선택 → 권장** 순서로 버린다. 필수 기능과 "다른 Windows PC에서 구동 시험"은 줄이지 않는다.

### 1.3 지켜야 할 규칙 (대회 공통 규칙 + 프로젝트 지침)

1. 감시 폴더의 원본은 **읽기만** 한다. 수정·이동·삭제하지 않는다.
2. 모든 산출물(보관소, 색인, 정리본, 보고서)은 **별도 작업 폴더**에 만든다.
3. 개발·시연에는 **합성 모의데이터만** 쓴다.
4. 문서 내용은 PC 밖으로 나가지 않는다. AI도 PC 안의 Ollama가 기본이다.
5. AI가 없어도 AI 요약 외의 모든 기능이 동작한다.
6. 확실하지 않은 판정은 자동 처리하지 않고 **"확인 필요"**로 남긴다.

## 2. 전체 구성

### 2.1 실행 구조

```
┌───────────────────── 버전지기.html (Edge/Chrome에서 실행) ─────────────────────┐
│                                                                              │
│  [원천 어댑터]                  [엔진]                         [화면]          │
│  실제 폴더(FS API) ─┐   ┌→ 추출기(hwpx·xlsx) → 색인 → 계보 → 분류 ┐          │
│  가상 폴더(체험)  ──┼→ 수집기                                    ├→ 화면 7개  │
│                    ┘   └→ 비교기(문단·표·시트·숫자) → 통합(이력·내보내기)┘    │
│                                         │                                    │
│                              [AI 계층] 요약·분류추천 → 검증기                 │
│                                         │ http://127.0.0.1:11434 (OpenAI 호환)│
└─────────────────────────────────────────┼────────────────────────────────────┘
        │읽기 전용                          │                  │읽기·쓰기
   감시 폴더                         Ollama + EXAONE        작업 폴더
   (예: 다운로드\받은문서)          (같은 PC, 선택)       (_버전지기\ 색인·보관소·정리본)
```

- **원천 어댑터**: 실제 폴더와 체험용 가상 폴더가 같은 함수(`list()`, `read()`)를 제공한다. 그래서 엔진은 두 경우를 구분하지 않는다. 체험 모드를 쉽게 만들 수 있는 핵심 설계다.
- **엔진**은 화면과 분리한 순수 함수로 만든다. 같은 코드를 Node.js 시험에서도 돌린다. 나중에 정보화사업으로 옮길 때도 엔진만 서버에 붙이면 된다.

### 2.2 브라우저 기능 사용 목록 (외부 라이브러리 없음)

| 필요한 일 | 사용하는 브라우저 내장 기능 | 비고 |
|---|---|---|
| 폴더 읽기·쓰기 | File System Access API(`showDirectoryPicker`) | `다운로드` 폴더 자체는 브라우저가 막음 → 하위 폴더 사용(11장) |
| 폴더 기억 | IndexedDB(브라우저 안 저장소)에 폴더 핸들 저장 | 다시 열 때 [다시 연결] 1클릭 |
| zip 풀기 | `DecompressionStream('deflate-raw')` | ODT 추출기와 같은 방식 |
| zip 만들기 | 무압축(store) 방식 + CRC32(오류 검사값) 자체 구현 | 모의데이터·정리본용 |
| XML 읽기 | **자체 구현 SAX 파서**(태그를 앞에서부터 차례로 읽는 방식) | 작업 스레드에는 `DOMParser`가 없기 때문 |
| 해시 | `crypto.subtle.digest('SHA-256')` | 내용 고유 번호 |
| 무거운 계산 분리 | Web Worker(Blob 주소로 생성) | 화면 멈춤 방지. 안 되면 나눠서 처리(11장) |
| AI 호출 | `fetch` → Ollama OpenAI 호환 주소 | 다른 출처 허용 설정 필요할 수 있음(11장) |

## 3. 데이터 구조

### 3.1 3층 모델 (v0.2 유지)

| 층 | 뜻 | 식별자 | 예 |
|---|---|---|---|
| 내용(content) | 파일 안의 바이트. 한 글자라도 다르면 다른 내용 | SHA-256 해시 | `a3f9…` |
| 파일(file) | 폴더 안의 이름·위치 | 경로 | `받은문서\결과보고_최종.hwpx` |
| 문서(document) | 사람이 생각하는 "그 문서". 버전을 묶는 단위 | `D-0001` | "10월 수질검사 결과보고" |

### 3.2 작업 폴더 구성

```
<작업 폴더>\_버전지기\
├─ 색인.json             ← 문서·버전·파일·판정·분류 (화면이 여는 주 자료)
├─ 내용\ab\<해시>.json   ← 추출한 본문·표·셀(내용 1개당 1파일, 필요할 때만 읽음)
├─ 보관소\ab\<해시>.hwpx ← 처음 발견한 원본 복사본(덮어써져도 비교 가능)
├─ 설정.json             ← 감시 폴더, 분류 규칙, 판정 기준값, AI 연결
├─ AI기록.json           ← AI 요약 결과 캐시(같은 비교는 다시 묻지 않음)
├─ 기록.jsonl            ← 사건 기록(추가만 함): 발견·색인·묶음·사용자 판정·내보내기
└─ 백업\색인_YYYY-MM-DD.json (최근 7개)
<작업 폴더>\정리본\       ← 통합 결과(7.4)
```

- 쓰기 방식: File System Access API의 쓰기는 임시 파일에 쓴 뒤 닫을 때 한 번에 바꿔치기한다. 그래서 쓰는 도중 꺼져도 `색인.json`이 반쯤 쓰인 채로 남지 않는다(브라우저 동작, M0 확인).
- 저장 시점: 변경 후 2초 동안 추가 변경이 없으면 저장하고, 하루 첫 저장 때 백업을 남긴다.
- IndexedDB에는 **폴더 핸들과 빠른 표시용 사본만** 둔다. 원본 자료는 항상 작업 폴더에 있으므로, 브라우저 기록을 지워도 자료가 남는다.

## 4. 수집: 폴더 감시와 파일 읽기

### 4.1 처음 설정 순서 (사용자 화면 기준)

1. Edge 설정 → 다운로드 → 위치를 `다운로드\받은문서`로 바꾼다. 브라우저가 `다운로드` 폴더 자체는 선택하지 못하게 막기 때문이다.
2. 버전지기에서 [감시 폴더 연결]을 누르고 `받은문서`를 선택한다(읽기 권한).
3. [작업 폴더 연결]을 누르고 `문서\버전지기`를 선택한다(읽기·쓰기 권한). 감시 폴더 안에 두지 않는다.
4. 기존 파일 일괄 색인이 시작되고, 진행률이 표시된다.

### 4.2 감시 방식

| 상황 | 동작 |
|---|---|
| 탭이 보이는 동안 | 10초마다 폴더 목록 확인 |
| 탭이 숨겨진 동안 | 브라우저가 자동으로 늦춤(약 1분 간격) |
| 창으로 돌아올 때 | 즉시 다시 확인(ODT 추출기와 같은 방식) |
| 탭을 닫으면 | 감시 중지. 다음에 열 때 놓친 파일을 한 번에 처리 |

> 한계: 탭이 닫혀 있는 동안에는 감지하지 못한다. 매뉴얼에 "탭 고정(핀)"을 안내한다. 늘 켜져 있는 감시는 대회 이후 파이썬 판에서 다룬다.

### 4.3 한 번의 확인(scan) 절차

1. 폴더 목록을 읽고 `(이름, 크기, 수정시각)`을 색인과 대조한다.
2. 제외 대상을 거른다: `.crdownload`, `.tmp`, `.part`, `~$`로 시작하는 파일(엑셀 잠금 파일), `~`로 시작하는 파일, `_버전지기` 폴더.
3. 지원하지 않는 형식은 **목록에만** 올린다(이름·크기·날짜).
4. 새 파일과 바뀐 파일은 크기가 **두 번 연속 같을 때만** 처리한다(받는 중인 파일 제외).
5. 바이트를 읽어 SHA-256을 계산한다.
   - 해시가 이미 있으면 → 파일 기록만 추가한다(완전 중복, 분석 생략).
   - 처음 보는 해시면 → 보관소에 복사 → 추출 → 계보 판정 → 분류 순서로 처리한다.
6. 한 파일이 실패해도 다음 파일로 넘어간다. 실패한 파일은 빨간 행으로 표시하고 다음 확인 때 다시 시도한다(최대 3회).

### 4.4 hwpx 추출 절차

| 순서 | 대상 | 처리 |
|---|---|---|
| 1 | `mimetype` | `application/hwp+zip`인지 확인. zip이 아니고 OLE 형식(첫 바이트 `D0 CF 11 E0`)이면 "구형 hwp 또는 암호 문서"로 처리 |
| 2 | `Contents/content.hpf` | 구역(section) 파일의 순서 확인 |
| 3 | `Contents/section*.xml` | SAX로 차례대로 읽음. `hp:p`(문단) → `hp:run` → `hp:t`(글자) |
| 4 | 표 | `hp:tbl` → `hp:tr` → `hp:tc`. 셀 위치는 `hp:cellAddr`(행·열 번호), 병합은 `hp:cellSpan`. 셀 안 문단은 `kind:'cell'` |
| 5 | 글상자·각주·머리말 | 하위 문단 목록(`hp:subList`)까지 모두 읽고 `kind`로 구분. 머리말·꼬리말·쪽번호는 비교에서 기본 제외 |
| 6 | 제목 | ① 문서 정보의 제목 ② 첫 3문단 중 가장 긴 짧은 줄(40자 이하) ③ 파일명 정리값 순서로 결정 |
| 7 | 정규화 | NFC(맥 자모 분리 정리), 연속 공백을 1칸으로, 앞뒤 공백 제거. 빈 문단은 버림 |
| 8 | 문단 해시 | 정규화한 글자로 32비트 해시(빠른 대조용) |
| 9 | 그림 | `BinData/`는 압축을 풀지 않고 zip 목록의 크기·CRC만 기록 |

정확한 요소 이름은 M0에서 실제 샘플과 빈 문서로 확정한다(14장).

### 4.5 xlsx 추출 절차

| 순서 | 대상 | 처리 |
|---|---|---|
| 1 | 형식 확인 | zip이 아니고 OLE 형식이면 "암호 xlsx 또는 구형 xls" → 목록만 |
| 2 | `xl/workbook.xml` | 시트 이름·순서·숨김 여부(`state`), 1904 날짜 기준 여부 |
| 3 | `xl/_rels/workbook.xml.rels` | 시트 이름 → 시트 파일 경로 |
| 4 | `xl/sharedStrings.xml` | 공유 문자열 목록(서식이 섞인 글자 `r/t`는 이어 붙임) |
| 5 | `xl/styles.xml` | 셀 서식 번호 → 날짜 서식 여부(기본 14~22, 45~47번과 y·m·d·h가 들어간 사용자 서식) |
| 6 | `xl/worksheets/sheetN.xml` | `c`(셀): `r`(주소), `t`(형식: s=공유문자열, n=숫자, b=참거짓, str=수식문자, inlineStr, e=오류), `f`(수식), `v`(저장된 값) |

| 8 | 병합 | `mergeCells`를 기록, 첫 셀만 값 보유 |
| 9 | 한도 | 시트당 20만 셀을 넘으면 앞부분만 색인하고 경고(비교는 전체, 12장 성능 시험) |

## 5. 분류 ① — 같은 문서 묶기(계보)

### 5.1 판정 흐름

```
새 내용(해시)
 ├─ 1. 해시가 같은 내용 있음 ─────────────→ 완전 중복(같은 버전)
 ├─ 2. 사용자 판정(같음/다름) 있음 ─────────→ 그대로 따름(자동 판정보다 우선)
 ├─ 3. 후보 찾기: MinHash + 묶음 검색(LSH) → 비슷할 가능성이 있는 내용 최대 20개
 ├─ 4. 정밀 점수: 상용구를 뺀 문단(또는 셀) 집합의 유사도·포함도
 ├─ 5. 보조 규칙: 기간 표시가 다르면(10월↔11월, 1분기↔2분기) 자동 연결 금지
 └─ 6. 판정
       ├─ 점수 ≥ 0.90 → 같은 문서의 새 버전(자동)
       ├─ 0.60 ≤ 점수 < 0.90 → "확인 필요"(사람이 [같은 문서]/[다른 문서] 선택)
       └─ 점수 < 0.60 → 새 문서
```

### 5.2 각 단계 상세

| 단계 | 방법 | 쉬운 설명 |
|---|---|---|
| 지문 재료 | hwpx: 정규화 본문을 5글자 조각으로 자름. xlsx: `시트명|셀값` 조각(숫자 포함) | 문서를 작은 조각 묶음으로 바꿈 |
| MinHash | 조각마다 128가지 해시를 계산하고 각 최솟값만 남김 | 128개 숫자로 된 "축약 지문". 두 지문이 같은 자리의 값이 같은 비율 ≈ 두 문서의 유사도 |
| LSH 묶음 검색 | 128개를 4개씩 32묶음으로 나눔. 한 묶음이라도 같은 문서끼리만 후보로 봄 | 전체 문서와 일일이 비교하지 않고 후보만 빠르게 추림 |
| 상용구 | 문단(셀) 해시가 전체 문서 중 3건 이상, 30% 이상에 나오면 상용구로 보고 점수에서 제외 | 공문 양식, 결재란, "붙임" 문구 때문에 다른 문서가 묶이는 것 방지 |
| 유사도 | `겹치는 문단 수 ÷ 두 문서 문단 합집합` | 서로 얼마나 같은가 |
| 포함도 | `겹치는 문단 수 ÷ 작은 문서 문단 수` | 한쪽이 다른 쪽에 들어 있는가(발췌·취합본) |
| 최종 점수 | `max(유사도, 포함도 × 0.95)` | 포함 관계도 같은 계보로 인정 |
| 파일명 보조 | 버전 표시를 지운 기본 이름이 같으면 자동 기준을 0.90 → 0.85로 낮춤 | 파일명은 보조 근거일 뿐, 단독으로 묶지 않음 |
| 형식 | hwpx와 xlsx는 서로 묶지 않음 | — |

기준값(0.90, 0.60, 0.85, 30%)은 `설정.json`에 두고, 모의데이터 채점 결과로 조정한다.

### 5.3 버전 순서와 버전 나무

1. **받은 시각**(처음 발견한 시각, 첫 일괄 색인 때는 파일 수정시각)으로 1차 정렬한다.
2. 파일명 버전 표시로 보정한다: `v1 < v2 < … < 수정 < 최종 < 최최종`, `(1) < (2)`, 날짜 표기 `1015 < 1018`.
3. 새 버전의 **부모** = 같은 문서 안에서 그보다 먼저 받은 버전 중 **가장 비슷한 버전**이다.
4. 한 부모에 자식이 둘 이상이면 **갈래**로 표시한다(두 사람이 같은 원본을 각자 수정한 경우).
5. 사용자가 순서를 바꾸면 `confirmed`로 고정하고, 이후 자동 판정은 바꾸지 않는다.

### 5.4 파일명 버전 표시 정리 규칙 (`설정.json`에서 수정 가능)

| 제거 대상 | 예 |
|---|---|
| 버전 번호 | `v1`, `V2.1`, `ver3`, `_1차`, `2차수정` |
| 단계 표현 | `수정`, `수정본`, `최종`, `최최종`, `진짜최종`, `확정`, `검토`, `초안` |
| 브라우저 중복 표시 | `(1)`, `(2)`, ` - 복사본` |
| 날짜·작성자 꼬리 | `_1015`, `_20261015`, `_홍길동` (설정한 패턴만) |

예: `결과보고_v2_최종(1).hwpx` → 기본 이름 `결과보고`

### 5.5 규칙 분류

`설정.json` › `분류규칙`(화면의 설정 탭에서 표로 편집)

| 우선순위 | 대상 | 포함(쉼표=또는, +=그리고) | 제외 | 분류 |
|---|---|---|---|---|
| 10 | 제목 | 행정사무감사, 요구자료 | | 감사 |
| 20 | 본문앞 | 시료번호+검사항목 | | 수질검사 |
| 30 | 시트명 | 측정결과, 분석결과 | | 수질검사 |
| 90 | 파일명 | 회의, 회의록 | 결과보고 | 회의 |

- 분류는 **문서 단위**로 정한다. 같은 문서의 버전이 다른 분류로 흩어지지 않게, 첫 판정을 유지한다.
- 맞는 규칙이 여러 개면 우선순위가 높은 규칙을 따른다. 우선순위까지 같으면 "확인 필요"로 남긴다.
- 판정 이유(규칙 번호, 일치한 단어)를 저장해 화면에 표시한다.

### 5.6 AI 분류 추천 (권장)

- 대상: 규칙이 하나도 맞지 않은 문서
- AI에 주는 것: 제목, 본문 앞 500자(개인정보 가림), **분류 목록**
- AI가 돌려주는 것: 목록 중 하나 또는 "없음"과 한 줄 이유
- 검증: 답이 목록에 없으면 버린다.
- 표시: 노란 "AI 추천: 수질검사 [채택] [무시]". **사람이 채택하기 전에는 적용하지 않는다.**

## 6. 비교

### 6.1 비교 단위와 알고리즘

| 대상 | 1단계: 짝 맞추기 | 2단계: 세부 비교 | 표시 |
|---|---|---|---|
| hwpx 문단 | 문단 해시 목록에 **Myers 차이 알고리즘**(최소 편집 경로를 찾는 표준 방법) 적용 → 같음·추가·삭제 | 삭제·추가가 붙어 있는 구간에서 글자 2-gram 유사도 0.5 이상인 쌍을 "수정"으로 묶음. 수정 문단은 글자 단위 Myers로 바뀐 부분 강조 | 좌우 나란히. 추가=초록, 삭제=빨강 취소선, 수정=노랑 바탕 + 글자 강조 |
| 문단 이동 | 삭제된 문단과 같은 해시가 다른 위치에 추가돼 있으면 "이동" | — | 파랑 |
| hwpx 표 | 표 순서 + 머리글 유사도로 짝 맞춤 | 행을 **기준 열**(6.2)로 맞춘 뒤 셀 비교. 기준 열이 없으면 행 해시 Myers | 바뀐 셀 강조, 행 추가·삭제 |
| xlsx 시트 | 이름이 같은 시트끼리 짝. 남은 시트는 내용 유사도 0.7 이상이면 "이름 변경" | 시트별로 기준 열로 행을 맞춘 뒤 셀 비교 | 격자 보기. 바뀐 셀 노랑, 추가 행 초록, 삭제 행 빨강 |
| xlsx 수식 | 같은 셀의 수식(`f`)과 값(`v`)을 따로 비교 | "수식 변경" / "값만 변경" / "둘 다 변경" 구분 | 셀 모서리 표시 |
| 숫자 | 6.3 | — | **[숫자 변경만 보기]** 필터 |

### 6.2 기준 열 자동 탐지 (표·시트 공통)

1. 왼쪽 5개 열 중에서 고른다.
2. 머리글이 비어 있지 않아야 한다.
3. 값이 채워진 비율이 90% 이상이어야 한다.
4. 값이 서로 겹치지 않는 비율이 95% 이상이어야 한다.
5. 머리글에 `번호`, `시료`, `지점`, `코드`, `ID`, `성명`, `항목`이 들어간 열을 우선한다(사전은 설정에서 수정).
6. 조건을 만족하는 열이 없으면 행 순서로 비교하고 "기준 열 없음 — 행이 밀리면 비교가 부정확할 수 있음"이라고 표시한다.

## 7. 통합

### 7.1 문서 이력 만들기 (`integrate/history`)

1. 문서의 모든 버전을 버전 나무로 정렬한다.
2. **최신본 결정**:
   - 갈래가 없으면 → 가장 늦게 받은 끝 버전이 최신본이다.
   - 갈래가 있으면 → "최신본 확인 필요(갈래 2개)"로 표시하고 사용자가 고른다.
   - 사용자가 지정한 최신본은 고정한다.
3. **단계별 변경**: 부모 → 자식마다 비교 결과(`Change[]`)와 요약을 붙인다.
4. **누적 변경**: 첫 버전 → 최신본을 직접 비교한 결과를 따로 만든다. "처음 받은 문서에서 결국 무엇이 바뀌었나"를 보여 준다.

### 7.2 통합 변경내역 보고서 (`integrate/report`)

| 구성 | 내용 |
|---|---|
| 머리 | 문서 이름, 분류, 버전 수, 처음 받은 날, 최신본 |
| 전체 요약 | AI가 단계별 요약을 다시 3줄로 묶은 것. 검증 통과 문장만 싣고, AI가 꺼져 있으면 규칙 요약 |
| 타임라인 | 버전마다 받은 시각, 원래 파일명, 변경 수(숫자 변경 수), 단계 요약 |
| 숫자 변경표 | 모든 단계의 숫자 변경을 한 표로: 위치, 이전, 이후, 변화율, 버전 |
| 저장 | `변경내역.html`(인쇄 가능, 외부 링크 없음) + (선택) `변경내역_YYYY-MM-DD.xlsx`(모든 셀 텍스트, 머리글 고정, 자동 필터) |

### 7.3 갈래 병합 검토표 (선택, `diff/merge3`)

갈래 A·B와 공통 조상 O를 3자 비교한다(3-way 비교).

| O → A | O → B | 판정 | 제안 |
|---|---|---|---|
| 바뀜 | 그대로 | A만 수정 | A 채택 |
| 그대로 | 바뀜 | B만 수정 | B 채택 |
| 바뀜 | 같은 내용으로 바뀜 | 양쪽 동일 | 그대로 채택 |
| 바뀜 | 다른 내용으로 바뀜 | **충돌** | 사람이 결정(노랑) |

결과는 화면 표와 HTML로 저장한다. 실제 병합은 한글·엑셀에서 사람이 한다(1.1).

### 7.4 정리본 내보내기 (`integrate/organize`)

```
<작업 폴더>\정리본\
└─ 수질검사\
   └─ 10월 수질검사 결과보고\
      ├─ 10월 수질검사 결과보고.hwpx          ← 최신본(복사)
      ├─ _이전버전\
      │   ├─ 2026-11-02_0914_결과보고.hwpx
      │   └─ 2026-11-03_1630_결과보고_v2.hwpx
      ├─ 변경내역.html
      └─ _목록.json                           ← 어떤 해시를 복사했는지(다시 실행할 때 사용)
```

절차:
1. [미리보기]: 만들 폴더·파일 목록과 개수를 보여 준다.
2. [실행]: 보관소의 원본 복사본을 대상 위치로 **복사**한다. 감시 폴더의 원본은 건드리지 않는다.
3. 다시 실행하면 `_목록.json`과 대조해 **새로 생긴 것만** 복사한다(멱등: 여러 번 해도 결과가 같음).
4. 최신본이 바뀌면 기존 최신본 복사본을 `_이전버전`으로 옮긴다. 이것은 정리본 안에서의 이동이고 원본 이동이 아니다.
5. 같은 이름이 있으면 `(2)`를 붙이고 결과창에 안내한다.
6. 파일명에 쓸 수 없는 글자(`\ / : * ? " < > |`)는 `_`로 바꾸고, 경로가 길면 문서 이름을 60자로 줄인다.
7. 모든 복사를 `기록.jsonl`에 남긴다. [이번 내보내기 취소]를 누르면 이번에 만든 복사본을 지운다(작업 폴더 안에서만).

| ⑥ 검증 | 8.4 |
| ⑦ 저장 | `AI기록.json`에 (이전 해시, 이후 해시, 모델, 질문 틀 버전) 기준으로 저장 → 다시 열면 즉시 표시 |

### 8.3 질문 틀 (`ai/prompts.js`, 버전 관리)

```
[역할] 당신은 행정 문서의 변경 내용을 정리하는 보조자입니다.
[규칙]
1. 아래 변경 목록에 있는 내용만 쓰십시오. 목록에 없는 사실·추측·평가를 쓰지 마십시오.
2. 3~5개 문장, 각 문장은 "- "로 시작하고 끝에 근거 번호를 [C1] 또는 [C1,C4]처럼 붙이십시오.
3. 숫자는 목록에 적힌 값을 그대로 쓰십시오.
4. 숫자 변경을 먼저 쓰십시오.
5. "~했다" 형태의 행정 문체로 쓰십시오.
[문서] 10월 수질검사 결과보고 (v2 → 최종)
[변경 목록]
C1 | 표1 3행 '총인' 열 | 0.21 → 0.32
C2 | 문단 14 수정 | "기준 초과 지점은 2곳이다" → "기준 초과 지점은 3곳이다"
C3 | 문단 20 추가 | "추가 채수는 11월 둘째 주에 실시한다"
[답]
```

### 8.4 검증 규칙 (`ai/verify.js`) — "AI 신뢰성 확보"의 핵심

| 번호 | 검사 | 실패 시 |
|---|---|---|
| V1 | 문장에 근거 번호가 있고, 그 번호가 실제 변경 목록에 있는가 | ⚠ "근거 없음" |
| V2 | 문장 속 모든 숫자가 인용한 변경의 이전/이후 값에 있는가(표기 정규화 후 대조) | ⚠ "숫자 불일치: 0.23" |
| V3 | 인용한 변경의 핵심어(이전/이후 글자의 2글자 이상 명사 조각) 중 하나 이상이 문장에 있는가 | ⚠ "근거와 내용 다름" |
| V4 | 숫자 변경 중 어떤 문장에도 인용되지 않은 것이 있는가 | 요약 끝에 프로그램이 직접 한 줄 추가: "※ 요약에 빠진 숫자 변경: C7(1.2→1.5)" |
| V5 | 문장 수 1~6개, 문장당 120자 이하 | 넘는 부분은 잘라 내고 표시 |
| V6 | 전부 실패하거나 응답이 없음 | 규칙 요약으로 대체: "문단 3곳 수정, 1곳 추가, 숫자 2곳 변경(C1, C5)" |

화면 표시:
```
✔ 3지점 총인 농도가 0.21에서 0.32로 수정됐다. [C1]           ← 근거 클릭 → 비교 창의 해당 위치
✔ 기준 초과 지점이 2곳에서 3곳으로 늘었다. [C2]
⚠ 추가 채수는 11월 첫째 주에 실시한다. [C3]  — 근거와 내용 다름
※ 요약에 빠진 숫자 변경: C7(1.2→1.5)
검증 통과 2/3 · 모델 EXAONE 4.0 1.2B · 14초
```

## 9. 체험 모드와 모의데이터 생성기

### 9.1 동작

| 상황 | 동작 |
|---|---|
| 처음 실행(감시 폴더 미연결) | **자동 시작**. 상단에 "체험 모드 — 가상 문서로 시연 중입니다" 띠 표시 |
| 실제 폴더 연결 후 | 자동 시작 안 함. [체험 모드] 버튼으로만 시작 |
| 체험 데이터 | 실제 색인과 분리된 별도 공간에 저장. [체험 종료] 시 삭제 |

조작 버튼: [⏸ 일시정지] [⏹ 중지] [⟲ 처음부터] [속도 1× / 3× / 10×] [실제 파일로 저장]
- **중지**: 재생을 멈추고 지금까지 들어온 문서로 계속 둘러볼 수 있다.
- **실제 파일로 저장**: 폴더를 골라 생성된 hwpx·xlsx를 실제 파일로 쓴다. 심사위원이 한글·엑셀에서 열어 확인할 수 있다.

### 9.2 시나리오 (고정 순서, 같은 결과 재현)

| 묶음 | 형식 | 파일 흐름 | 시험하는 기능 |
|---|---|---|---|
| A | hwpx | `결과보고.hwpx` → `결과보고_v2.hwpx` → `결과보고_최종.hwpx` → `결과보고_최최종(1).hwpx` | 버전 순서, 표 셀·숫자 변경, AI 요약 |
| B | hwpx | `자료요구.hwpx` → `[회신]산업환경팀_답변자료.hwpx` (이름 전혀 다름) | **이름이 달라도 연결** |
| C | hwpx | 같은 양식의 회의자료 5건(안건이 다름) | **잘못 묶지 않기**(상용구) |
| D | hwpx·xlsx | 같은 파일을 `(1)`, `(2)`로 다시 받음 | 완전 중복 |
| E | hwpx | 같은 원본을 두 팀이 각자 수정 | 갈래, 병합 검토표 |
| F | xlsx | `측정결과.xlsx` → `측정결과_수정.xlsx`(값 수정, 행 끼워 넣기, 수식 변경) | 기준 열로 행 맞춤, 숫자 변경 |
| G | xlsx | `10월_측정결과.xlsx`, `11월_측정결과.xlsx`(같은 양식, 다른 달) | **기간이 다르면 묶지 않기** |
| H | xlsx | 시트 이름 변경 + 시트 추가 | 시트 짝 맞추기 |
| I | 기타 | 0바이트, 손상 zip, `.crdownload`, `~$잠금.xlsx`, pdf | 오류·제외 처리 |
| J | hwpx | 100쪽 보고서 1건 | 속도 |

- 전체 약 45개 파일, 기본 속도로 약 3분 재생
- 내용은 공개 보도자료·공문의 문체를 본뜬 **가상 내용**이다(실제 기관·인물·수치 아님).
- 같은 씨앗값(난수 시작값)을 써서 매번 같은 파일이 만들어진다.

### 9.3 파일 생성 방법

| 형식 | 방법 |
|---|---|
| hwpx | `templates/blank.hwpx`(한글에서 저장한 빈 문서)의 부품을 HTML 안에 내장한다. `section0.xml`만 시나리오대로 새로 만들어 끼운다(문단·표). zip은 무압축으로 묶고 `mimetype`을 맨 앞에 둔다 |
| xlsx | ODT 추출기의 엑셀 작성기를 확장해 숫자·수식 셀을 지원한다 |
| 확인 | 생성 파일을 한글·엑셀에서 실제로 열어 보는 시험은 사람이 한다(미검증 → M0·11.9 확인) |

- `answer_key.js`에 정답을 미리 적는다: 묶음 구성, 버전 순서, 묶음별 기대 변경(위치·이전·이후).

```
체험 결과 채점
· 문서 묶기: 정답 14묶음 중 14 일치 (잘못 묶음 0, 빠뜨림 0)

```

같은 채점 코드를 `tests/scenario`에서 자동 시험으로 돌린다.

### 14.3 알려진 제약 (구동안내서에 그대로 적을 내용)

1. 탭이 열려 있는 동안만 새 파일을 감지한다.
2. 글자 내용 기준 비교다. 쪽 모양·글꼴·그림 위치 비교는 한글의 `문서 비교`를 쓴다.
3. 구형 hwp·xls와 암호 문서는 본문을 읽지 않는다.
4. AI 요약은 PC에 Ollama와 모델이 있을 때만 동작한다. 없으면 규칙 요약을 쓴다.
5. EXAONE 4.0의 라이선스는 "EXAONE AI Model License Agreement 1.2 - NC"(비상업)다. 모델은 프로그램에 넣지 않고 사용자가 직접 내려받는다. 공공기관 업무 사용 가능 여부는 확인이 필요하다(미검증).
6. 생성 모의데이터의 한글·엑셀 호환성, 업무망 PC 동작은 직접 확인한 범위만 "확인"으로 적고, 나머지는 "미검증"으로 적는다.
