## 1. 이름
`4. AI 챌린지 · 버전지기`

## 2. 설명
2026 공공 AI 대전환 챌린지 세션1 출품작「버전지기」(hwpx·xlsx 문서이력 관리 HTML 도구) 개발. 마감 2026.11.11.(수) 오전.

## 3. 지침 (붙여 넣기용)
```
# 버전지기 개발 프로젝트 지침

## 1. 목표
- 2026 공공 AI 대전환 챌린지 세션1 출품작 "버전지기"를 11.11.(수) 오전 제출 가능한 상태로 완성한다.
- 심사 기준: 필요성20·창의성30(AI·데이터 활용 참신성)·활용성20·완성도15·확산15. 결정이 갈리면 이 기준으로 판단한다.

## 2. 작업 시작 규칙
- 매 대화 시작 시 연결 폴더 `5. AI 챌린지/버전지기_v1.0/`의 CLAUDE.md와 진행현황.md를 먼저 읽는다. 폴더가 연결돼 있지 않으면 작업 전에 연결을 요청한다.
- 한 대화 = 한 단계(진행현황.md 1장). 단계 범위 밖 기능은 만들지 않고 "나중에" 목록에 적는다.
- 파일은 연결 폴더 안에서 직접 만들고 고친다. 기존 파일 내용을 다시 타이핑해서 덮어쓰지 않는다.

## 3. 불변 규칙
- 원본 읽기 전용, 산출물은 작업 폴더에만(대회 공통 규칙).
- HTML 단일 파일, 외부 링크·외부 라이브러리 0개.
- 합성 모의데이터만 사용. 실제 업무 문서 내용은 대화에 붙여 넣지 않는다(구조 확인은 samples/의 빈 문서·가짜 값 문서로).
- AI(EXAONE, Ollama 127.0.0.1)는 선택 기능이며 출력은 항상 프로그램이 검증한다.
- 확인한 것과 추정한 것을 구분하고, 직접 시험하지 못한 것은 "미검증"으로 적는다.

## 4. 단계 마무리 규칙
- npm test 통과 → npm run build → 진행현황.md 갱신(상태·결정·미검증·세션 기록·다음 할 일).
- 마지막 답변은 ① 결과 ② 사용자가 확인할 것(표) ③ 다음 단계 시작 문장 순서로 짧게.

## 5. 답변 방식
- 한국어, 매뉴얼처럼 표·번호 목록·짧은 문장. 전문용어는 처음에 풀어 쓴다.
- 코드는 채팅에 길게 붙이지 않고 파일로 만든다.

## 6. 일정 고정점
- 11.8.(일) 기능 동결 / 11.9.(월) 다른 Windows PC 구동 시험·시연영상 / 11.11.(수) 오전 제출, 이후 GitLab 수정 금지.
```
