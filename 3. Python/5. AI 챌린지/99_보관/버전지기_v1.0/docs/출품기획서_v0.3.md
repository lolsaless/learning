## 3. 출품작 정의

### 3.1 이름 후보 (결정 필요)

| 후보 | 느낌 | 비고 |
|---|---|---|
| **버전지기** | 버전을 지켜 주는 도구 | 짧고 기능이 바로 드러남 (추천) |
| 문서족보 | 문서의 계보(족보)를 만들어 줌 | 발표에서 기억에 남음 |
| 최최종 탈출 | 문제 상황을 직접 표현 | 발표용 부제로 쓰기 좋음 |

예: **"버전지기 — 다운로드 폴더의 '최종_최최종'을 끝내는 AI 문서 이력 관리"**

### 3.2 해결하는 문제 (발표 첫 장면)
1. 메일로 받은 hwpx가 다운로드 폴더에 쌓여, 어떤 파일이 무엇이었는지 잊는다.
2. `v1·v2·최종·최최종·(1)`이 섞여 **어느 것이 최신이고 무엇이 바뀌었는지** 파일을 하나씩 열어 비교해야 한다.
3. 같은 문서가 다른 이름으로 오면(회신본, 취합본) 연결 자체가 안 된다.
4. 한글 `문서 비교`는 두 파일을 사람이 직접 골라야 하고, `문서 이력 관리`는 작성자가 기능을 켜고 저장한 문서에만 남는다.

### 3.3 핵심 기능 (MVP, 반드시 완성)

| 번호 | 기능 | 설명 | 심사 지표 |
|---|---|---|---|
| F1 | 자동 수집·색인 | 감시 폴더에 들어온 hwpx를 읽기 전용으로 읽어 본문·표·제목을 색인하고 원본 1부를 보관소에 복사 | 활용성·완성도 |
| F2 | **내용 기반 문서 계보** | 이름이 달라도 본문 유사도로 같은 문서의 버전을 묶음. 애매하면 "확인 필요" | 창의성 |
| F3 | **전/후 비교 창** | 문단 좌우 비교, 표 셀 단위 비교, **숫자 변경만 보기** | 창의성·활용성 |
| F4 | **AI 변경 요약 + 근거 검증** | 바뀐 내용을 3~5줄 행정 문체로 요약. 문장마다 근거 위치 링크, 숫자는 원문과 자동 대조. 검증 실패 문장은 표시 | 창의성(AI)·AI 신뢰성 |
| F5 | 통합 검색 | 모든 버전의 본문·제목·파일명 검색(2글자 이상) | 활용성 |
| F6 | 정리본 내보내기 | **별도 폴더**에 `분류/문서명/최신본 + _이전버전 + 변경내역.html`을 **복사**로 생성. 원본은 그대로 | 활용성·규칙 준수 |
| F7 | 체험 모드 | 내장 모의데이터를 "메일 도착"처럼 하나씩 흘려 넣는 **도착 재생기** | 완성도(구동성) |

### 3.4 여유가 있으면 (우선순위 순)
1. AI 제목 추정·표준 파일명 제안 (`2026-10-15_수질검사결과보고_v3.hwpx`)
2. AI 자연어 검색: "지난주 받은 수질 관련 최신본" → 날짜·분류·키워드 조건으로 바꿔 검색
3. docx·odt 추출기 (hwpx처럼 zip + XML 구조라 같은 틀로 추가 가능)

### 3.5 대회 이후로 미루는 것
원본 파일 이동·다운로드 폴더 비우기, 한글 자동화(HwpObject) 연계, 분류 규칙 자동 제안, 다운로드 출처 기록(Zone.Identifier), 태그·메모, 로그인 시 자동 시작.

## 4. v0.2 → v0.3 변경표

| 번호 | 항목 | v0.2 | v0.3 | 이유 |
|---|---|---|---|---|
| 1 | AI 사용 | 사용 안 함 | **선택형 AI 계층 추가**(로컬 모델 기본, 교체 가능). AI가 꺼져도 모든 핵심 기능 동작 | 창의성 30점, 모델 비종속 권장 |
| 2 | 정리 방식 | 분류 폴더로 **이동**, 저널·되돌리기 | 별도 폴더로 **복사**(정리본). 원본 무변경 | 대회 공통 규칙 "원본 보호" |
| 3 | 이동 저널 | `move_job·move_item` | `export_job·export_item`(복사 기록). 다시 실행하면 정리본만 갱신(멱등) | 2번에 따름 |
| 4 | 실행 방식 | 로그인 시 상주(작업 스케줄러) | 프로그램을 켜 둔 동안 감시. 자동 시작은 대회 이후 | 심사위원 PC 구동 위험 제거 |
| 5 | 의존 패키지 | watchdog 등 | **파이썬 표준 라이브러리만**(zipfile, xml, sqlite3/FTS5, difflib, http.server). 감시는 5초 폴링(주기적으로 확인) | 설치 실패 0, 라이선스 단순, 이관 쉬움 |
| 6 | 배포 | wheels 폴더 동봉 | Windows용 **휴대형 패키지**(파이썬 내장, 압축 풀고 `실행.bat`) + 소스 실행(`python run.py`, Mac·Linux) | 심사위원 환경을 모름 |
| 7 | 데이터 | 실제 다운로드 폴더 | **합성 모의데이터 세트** 내장(7장) | 민감자료 금지 |
| 8 | 범위 | M0~M6 | MVP F1~F7 | 16일, 핵심 기능 우선 권장 |
| 9 | 정답셋 | 실제 샘플 200개 | 모의데이터 정답 라벨 + (선택) 실제 문서는 결과 숫자만 측정, 내용 외부 반출 없음 | 민감자료 금지 |

## 5. AI 설계 — "AI가 요약하고, 프로그램이 검증한다"

### 5.1 원칙
1. **AI 없이도 동작**: 계보·비교·검색은 규칙과 알고리즘으로 처리한다. AI는 사람이 읽기 쉬운 요약과 추정만 맡는다. AI가 틀려도 데이터가 망가지지 않는다.
2. **AI 출력은 반드시 검증**: AI 요약의 모든 문장이 실제 변경 항목을 가리키는지, 숫자가 원문에 있는지 프로그램이 확인한다. 이것이 세션1 주제 중 **"AI 신뢰성 확보"**에 해당한다.
3. **모델 교체 가능**: OpenAI 호환 방식(여러 모델 서버가 공통으로 쓰는 요청 형식) 하나로 연결한다. 설정 파일의 주소·모델명만 바꾸면 된다.
4. **문서 전체를 보내지 않음**: 바뀐 부분(비교 결과)만 보낸다. 보내기 전에 주민등록번호·전화번호 같은 개인정보 형태는 가린다.

### 5.2 AI 기능

| 기능 | AI에게 주는 것 | AI가 돌려주는 것 | 프로그램 검증 | 실패 시 |
|---|---|---|---|---|
| F4 변경 요약 | 변경 목록(번호 C1, C2… + 이전/이후 문장·셀 값) | 3~5문장 요약, 문장마다 근거 번호 `[C3]` | ① 근거 번호가 실제로 있는지 ② 요약의 모든 숫자가 해당 변경의 이전/이후 값에 있는지 ③ 변경 중 숫자 변경이 요약에서 빠졌는지 | 해당 문장에 "검증 실패" 표시. 전체 실패면 규칙 요약("문단 3 추가, 숫자 2곳 변경")으로 대체 |
| 제목 추정(선택) | 본문 앞 1,000자 | 문서 종류·제목·날짜(JSON) | 제목이 본문에 실제로 있는지 | 파일명 정리값 사용 |
| 자연어 검색(선택) | 검색 문장 | 날짜 범위·분류·키워드(JSON) | 형식 검사 | 일반 검색으로 전환 |

화면 예시(변경 요약):

```
v2 → 최종 (변경 7곳, 숫자 변경 3곳)
✔ 총인 기준 초과 지점이 2곳에서 3곳으로 늘었다. [C2]
✔ 3지점 총인 농도가 0.21에서 0.32 mg/L로 수정됐다. [C5]
⚠ 보고 기한이 11월 말로 변경됐다. [C9] ← 검증 실패: '11월 말'이 원문에 없음
```

### 5.3 모델 연결과 시연 계획

| 구분 | 내용 |
|---|---|
| 기본 | 로컬 모델 서버(Ollama 등)에서 행정안전부 AI 공통기반 지원 모델 계열 실행: Gemma, EXAONE 등 |

## 6. 시스템 구조와 배포

### 6.1 구조

```
┌──────────── 버전지기 (사용자 PC 안에서만 동작) ────────────┐
│ ① 수집기: 감시 폴더 5초 폴링 + 시작 시 전체 대조            │
│ ② 엔진: hwpx 추출 → 해시 → 보관소 복사 → 색인 → 계보 → 비교 │
│ ③ AI 계층(선택): 요약·추정 → 검증기                         │
│ ④ 저장: SQLite(+FTS5 검색), 보관소(내용 해시 이름)          │
│ ⑤ 화면: 로컬 웹(127.0.0.1), HTML/JS 내장, 외부 링크 0       │
│ ⑥ 내보내기: 정리본 폴더에 복사 + 변경내역.html             │
└───────────────────────────────────────────────────────────┘
   감시 폴더(읽기 전용)         정리본 폴더(산출물, 별도 위치)
```

- 엔진, AI 계층, 화면을 분리했다. 정보화사업으로 옮길 때는 엔진을 서버나 업무망 공통 도구에 붙이고, 화면만 바꾸면 된다. 이 내용을 확산 항목의 근거로 쓴다.
- 기관 맞춤 요소(감시 폴더, 분류 규칙, 판정 기준값, AI 연결)는 모두 설정 파일에 둔다. 코드를 고치지 않아도 된다.

### 6.2 형식 선택: HTML 단일 파일 대신 파이썬 판을 쓰는 이유

| 비교 | HTML 단일 파일 | 파이썬 + 로컬 웹 (선택) |
|---|---|---|
| 설치 | 없음 | 휴대형 패키지면 압축 해제만 |
| 새 파일 자동 감지 | 탭이 열려 있을 때만, 매번 폴더 권한 승인 | 프로그램 실행 중 계속 |
| 저장 | 브라우저 저장소(IndexedDB) | SQLite 파일(백업·이관 쉬움) |
| 로컬 AI 연결 | 브라우저 보안(CORS) 설정 필요 | 바로 가능 |

판정: 핵심 요구가 "새 파일이 들어올 때마다"이므로 파이썬 판이 맞다. 대신 설치 부담은 휴대형 패키지와 체험 모드로 없앤다.

### 6.3 심사위원 구동 시나리오 (목표 10분 이내)

1. GitLab에서 `버전지기_v1.0_windows.zip` 내려받기 → 압축 풀기
2. `실행.bat` 더블클릭 → 브라우저에 화면이 열림
3. [체험 모드 시작] → 모의 문서 40여 개가 "메일 도착"처럼 하나씩 들어오고 자동으로 묶임
4. 문서 하나 선택 → 버전 타임라인 → [비교] → 숫자 변경 확인
5. (모델 서버가 있으면) [AI 요약] → 근거 링크·검증 표시 확인
6. [정리본 내보내기] → 원본 폴더는 그대로이고 별도 폴더가 생긴 것 확인

미검증: Windows 보안 프로그램이 `.bat`이나 내장 파이썬을 막을 수 있다. 깨끗한 Windows PC 1대 이상(동료 PC)에서 안내서대로 처음부터 시험해야 한다. 휴대형 패키지는 Windows용 내장 파이썬과 패키지를 내려받아 Mac에서도 조립할 수 있다. 다만 실제 실행 시험은 Windows에서 해야 한다.

## 7. 모의데이터와 평가셋

실제 업무 문서는 쓸 수 없다. 그래서 **현실과 같은 함정이 들어간 합성 문서 세트**를 만든다. 이 세트가 시연 자료, 회귀 시험, 정확도 평가표를 동시에 해결한다.

| 묶음 | 파일 예 | 시험하는 것 |
|---|---|---|
| A. 수질검사 결과 보고 | `결과보고.hwpx` → `결과보고_v2.hwpx` → `결과보고_최종.hwpx` → `결과보고_최최종(1).hwpx` | 숫자·표 셀 변경, 버전 순서 |
| B. 자료 요구·회신 | `요구자료.hwpx` → `[회신]산업환경팀_답변.hwpx` (이름 완전히 다름) | **이름이 달라도 연결** |
| C. 같은 양식, 다른 내용 | 회의자료 5건(양식 동일, 안건 다름) | **잘못 묶지 않기**(상용구 제외) |
| D. 완전 중복 | 같은 파일을 `(1)`, `(2)`로 다시 받음 | 해시 중복 |
| E. 갈래 | 같은 원본을 두 팀이 각자 수정 | 나무 구조 |
| F. 대용량 | 100쪽·300쪽 문서 | 속도(NFR-01) |
| G. 고장 파일 | 0바이트, 손상 zip, 받는 중(.crdownload) | 오류 처리 |

- 만드는 방법: 한글에서 빈 hwpx 1개를 저장해 틀로 쓰고, 프로그램이 본문 XML을 채워 만든다. 공개된 보도자료·공개 공문 문체를 참고하되 내용은 가상으로 쓴다.

## 8. 필요성·효과의 근거 만들기

추정 숫자를 지어내지 않는다. 직접 측정한 값만 쓴다.

| 근거 | 방법 | 개인정보·보안 |
|---|---|---|
| 다운로드 폴더 실태 | 업무 PC에서 **이름·크기·해시만** 세는 스크립트 실행: 전체 파일 수, hwpx 비율, `최종·v2·(1)` 등 버전 표시가 붙은 파일 수, 완전 중복 수 | 내용을 읽지 않고, 결과 숫자만 기록 |
| 동료 실태(선택) | 같은 부서 3~5명 동일 스크립트 또는 간단한 설문(하루에 받는 hwpx 수, 버전 확인에 걸리는 시간) | 개인 식별 없이 합계만 |
| 시간 비교 | 같은 과제("v2와 최종의 차이 찾기", "지난달 받은 ○○ 최신본 찾기")를 수작업과 도구로 각각 해 보고 시간 측정 | 모의데이터로 수행 |

효과 계산식(구동안내서·발표용):
`연간 절감 시간 = 1회 절감 시간 × 하루 횟수 × 근무일(약 250일)`
→ 개인 수치를 부서·기관 단위로 늘려 보이되, **측정값과 가정값을 구분해서 표기**한다.

| 사용 모델명/교체 가능 여부 | OpenAI 호환 연결, Gemma·EXAONE 계열 2종 시연, 설정만으로 교체 가능, AI 없이도 핵심 기능 동작 |
| 개요 및 주요 기능 | 받은 hwpx를 내용으로 색인해 이름이 달라도 같은 문서의 버전을 자동으로 묶고, 문단·표·숫자 단위 비교와 근거가 검증된 AI 변경 요약을 제공한다. 원본은 건드리지 않고 정리본을 별도 폴더에 만든다. |

## 11. 결선 대비

### 11.1 발표 핵심 메시지 3개
1. "파일명이 아니라 **내용**으로 문서의 족보를 만든다."
2. "AI가 요약하고, **프로그램이 그 요약을 원문으로 검증**한다."
3. "모든 공무원의 다운로드 폴더에 바로 쓸 수 있고, **설정 파일만** 바꾸면 어느 기관이든 쓴다."

### 11.2 예상 질문과 답

| 질문 | 답의 방향 |
|---|---|
| 한글 문서 비교와 무엇이 다른가 | 한글은 두 파일을 사람이 고르고 모양까지 비교한다. 버전지기는 비교할 짝을 자동으로 찾고, 폴더 전체의 이력·숫자 변경·요약을 제공한다. 두 기능은 서로 보완한다 |
| 문서 본문을 DB에 저장하면 보안 문제는 | 사용자 PC 안에만 저장, 외부 통신 없음, 127.0.0.1 전용, 완전 삭제 기능, AI도 로컬 모델이 기본 |
| AI 없이도 된다면 AI 대회에 맞나 | AI가 가장 잘하는 "사람이 읽을 요약"을 맡기고, 틀릴 수 있는 부분은 프로그램이 검증한다. 이것이 AI 신뢰성 확보 방식이다 |
| 잘못 묶이면 | 기준을 보수적으로 잡았고, 애매하면 사람에게 묻는다. 정밀도 측정값 제시 |
| 정보화사업으로 옮길 때 | 엔진·AI·화면이 분리돼 있고 표준 라이브러리만 쓴다. 온나라·업무망 공통 도구에 엔진을 붙이는 구조 |
| 온나라 문서관리와 겹치지 않나 | 온나라는 결재 문서를 관리하고, 버전지기는 **결재 전 메일로 오가는 작업 파일**을 다룬다 |

## 13. 결정 필요 사항

| 번호 | 내용 | 선택지 | 제안 |
|---|---|---|---|
| 1 | 도구 이름 | 버전지기 / 문서족보 / 기타 | 버전지기 |
| 2 | 참가 단위 | 개인 / 팀(같은 기관 동료) | 개인으로 시작. 실태 측정·시험을 도울 동료가 있으면 팀 |
| 3 | 기관명 표기 | 경기도보건환경연구원 / 북부지원 포함 | 담당부서 확인 후 |
| 4 | AI 모델 | 로컬 2종(Gemma·EXAONE 계열) / + 공통기반 API 토큰 | 로컬 2종 필수, 토큰은 받으면 추가 |

| 7 | 정리본 폴더 위치 | `문서/버전지기_정리본` / 설정에서 지정 | 기본값 + 설정에서 변경 |
