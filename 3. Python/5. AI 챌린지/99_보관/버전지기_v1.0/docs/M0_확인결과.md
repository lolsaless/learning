## 2. 시험 도구 사용법 (`dist/M0_확인.html`)
1. 파일을 Edge(업무 PC)나 Chrome(Mac)에서 더블클릭으로 연다. 주소가 `file:///`로 시작해야 한다.
2. 맨 위 "0. 실행 환경"에서 `showDirectoryPicker: 있음`을 확인한다.
3. 1~4번 칸을 차례로 실행한다. 4번(hwpx)은 파일을 고르면 곧바로 결과가 나온다.
4. 5번 칸의 [결과 복사]를 눌러 대화창에 붙여 넣는다. (민감정보 없음: 파일 이름·개수·태그 이름만 포함. 실제 문서 파일명이 민감하면 붙여 넣기 전에 지울 것)

## 3. 안 될 때 대응 (설계서 14.2 그대로)
| 번호 | 안 되면 |
|---|---|
| 1 | `문서\받은문서` 등 다른 위치로 다운로드 위치 지정 |
| 2 | 화면 스레드 분할 처리(A5) |
| 3 | `launchctl setenv OLLAMA_ORIGINS "*"` 후 Ollama 재시작. 그래도 안 되면 AI 기능만 `python -m http.server`로 연 주소에서 사용 |
| 4 | 버전 업데이트 또는 다른 양자화 파일 |
| 5 | 틀 문서 교체, 부품 구성 조정 |
| 6 | 추출기 규칙 보완 |
| 7 | 높으면 대회 이후 지원 검토 |

## 4. 개발 환경에서 확인한 것 (이 기록의 근거)
- Node.js v22.23.4, npm 10.9.9에서 `npm test` 6개 통과, `npm run build` 성공.
- 헤드리스 Chromium + file:// 에서: Worker(Blob) 성공, `DecompressionStream` 있음, 가짜 hwpx(합성 데이터) 구조 읽기 성공(부품 목록, mimetype 무압축 첫 부품 확인, 표·글상자·각주 요소 개수).
- **직접 시험하지 못한 것**: 실제 Edge, 실제 Ollama·EXAONE, 한글·엑셀 열기, 업무망. 개발 도구가 도는 환경에서는 사용자 Mac의 Ollama(127.0.0.1:11434)에 접속되지 않음.
