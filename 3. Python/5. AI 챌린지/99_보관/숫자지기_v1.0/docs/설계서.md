# 숫자지기 v1.0 — 설계서

- 한 줄 소개: **한글(hwpx) 보고서의 숫자마다 원본(엑셀·팀 제출 문서) 출처를 찾아 대조하고, 고친 값과 출처를 이력으로 남기는 도구**
- 형식: **HTML 화면 + Python 로컬 서버**(표준 라이브러리만 사용, 설치할 패키지 없음)
- 대상 파일: hwpx(검증 대상·팀 제출본), xlsx·xlsm(원본)
- 작성일: 2026-10-26

---

## 1. 목적과 배경

| 항목 | 내용 |
|---|---|
| 해결할 문제 | 의회 보고자료·행정사무감사 요구자료처럼 여러 팀이 엑셀에서 숫자를 옮겨 적고 대표 팀이 다시 취합하는 과정에서 생기는 **옮겨 적기·합계·단위·증감률·요일 오류** |
| 지금 방식의 한계 | ① 출처가 기록되지 않아 "이 숫자 어디서 왔나"를 다시 찾아야 함 ② 원본 엑셀이 나중에 바뀌어도 문서의 어느 숫자가 영향을 받는지 모름 ③ 누가 언제 무엇을 고쳤는지 남지 않음 |
| 목표 | 숫자 하나하나에 **출처(파일 전체 경로·시트·칸·파일 고유값)** 를 붙이고, 검증·수정·입력을 모두 **이력**으로 남긴다 |

## 3. 전체 구성

```
숫자지기_열기.bat ──▶ app/server.py (Python, 127.0.0.1 전용 웹 서버)
                        │  └ 브라우저로 app/ui/index.html 화면을 엶
                        ▼
                  app/core/workspace.py  ── 작업 하나(작업 폴더 하나)를 관리
                   ├ hwpx_io.py   : hwpx 읽기 · 누름틀 만들기 · 값 넣기 · 색 표시
                   ├ xlsx_io.py   : xlsx 읽기·쓰기(표준 라이브러리)
                   ├ numbers.py   : 숫자 추출·반올림 비교·요일·증감률 규칙
                   ├ matcher.py   : 원본 색인 · 표 블록 대조 · 판정 · 합계/비율 재계산
                   ├ ledger.py    : 이력 장부(SQLite 파일 1개)
                   ├ report.py    : 출처대장 xlsx · 검증표시본 hwpx · 검증보고 html
                   └ clipwatch.py : 엑셀 복사 출처 기록(Windows)
```

### 3.1 작업 폴더

```
<작업 폴더>/
├─ 숫자지기작업.db      ← 이력 장부(지우지 말 것)
├─ 작업본/              ← <문서>_v001.hwpx, _v002.hwpx … (누름틀이 씌워진 문서)
├─ 내보내기/            ← 출처대장_*.xlsx, 검증표시본_*.hwpx, 검증보고_*.html
└─ 백업/               ← 이력 장부 하루 1회 자동 백업(최근 10개)
```

### 3.2 이력 장부(SQLite) 표

| 표 | 내용 | 비고 |
|---|---|---|
| versions | 작업본 버전(번호·경로·SHA-256·메모·작업자) | |
| sources | 원본(번호 S1…·전체 경로·구분·SHA-256·크기·수정시각·상태) | 빼도 지우지 않고 active=0 |
| source_events | 원본 등록·내용 변경·등록 해제 기록 | 이전·새 고유값 |
| events | **값 이력**: 칸·이전 값·새 값·방법·출처(경로·칸·고유값)·사유·작업자 | 추가만 함 |
| confirms | 칸별 확정 출처 | 값이 바뀌면 자동 무효 |
| pending | 저장 전 변경(대기 목록) | 프로그램을 꺼도 남음 |
| runs / run_items | 검증 기록(회차별 요약·칸별 상태) | 직전 대비 바뀐 칸 계산 |
| clips | 복사 기록(경로·시트·시작 칸·값) | Windows |

값 이력의 '방법' 종류: `작업본 생성` · `원본 값으로 수정` · `입력하기` · `직접 입력` · `출처 확정` · `한글에서 직접 수정`

## 4. 핵심 방법 — 이름이 아니라 "숫자가 놓인 모양"으로 출처 찾기

원본 엑셀의 머리글이 "T-P", 지점이 "HB-06"이고 한글 문서는 "총인", "가람강 합류전"이라도, **숫자들이 같은 배치로 놓여 있으면 같은 출처**로 본다.

| 단계 | 처리 | 쉬운 설명 |
|---|---|---|
| ① 색인 | 모든 원본 숫자 칸을 값 순서로 정렬. 배율 5가지(그대로·÷1,000·÷1,000,000·×1,000·×100)별로 따로 | 사전처럼 값으로 바로 찾게 함 |
| ② 후보 | 문서 숫자 하나마다 반올림 범위(예: 2.3이면 2.25~2.35) 안의 원본 칸을 찾음 | |
| ③ 열 맞추기 | 문서 표의 한 열에 있는 숫자들이 원본 어느 열(배율 포함)에 몰려 있는지 **투표** | 2칸 이상이 지지해야 인정 |
| ④ 행 맞추기 | 맞춘 열 안에서 문서 각 행이 원본 어느 행인지 투표 | 일부 행만 복사·순서 바꿈도 처리 |
| ⑤ 보충 | 맞춘 행으로 남은 열을, 맞춘 열로 남은 행을 다시 맞춤(최대 3회) | 0·1·3처럼 흔한 작은 값도 여기서 자리를 찾음 |
| ⑥ 뒤집기 | ③~⑤를 행·열을 바꾼 방향으로도 시험 | 엑셀은 측정소가 행, 문서는 열인 경우 |
| ⑦ 블록 거르기 | 우연히 맞은 블록을 버림: 흩어짐(맞은 원본 행 범위÷행 수) 3 초과, 반올림으로만 맞은 블록, 최고 블록의 절반 이하인 작은 블록 | 큰 원자료 시트의 우연한 일치 방지 |
| ⑧ 판정 | 맞춘 위치의 원본 값과 비교 | 5장 |

**강한 근거·약한 근거**: 정확히 같은 값, 단위 환산(큰 정수 원→천원), 소수 반올림(2.338→2.3)은 강한 근거. 소수 값(32.8)을 정수(33)로 반올림해야 맞는 경우는 우연일 가능성이 커서 약한 근거로 보고 투표에서 낮게 취급한다.

**표가 아닌 본문 숫자**는 배열이 없으므로 같은 값 검색만 한다. 개수(건·명·회 등) 정수는 **정확히 같은 값만** 후보로 인정한다.

## 5. 판정 규칙과 상태

| 상태(화면 글자) | 조건 | 색 |
|---|---|---|
| 일치 | 대조한 원본 모두 값이 같음(반올림·단위 환산 포함) | 연녹 |
| 일치(계산 확인) | 원본엔 없지만 합계·비율·증감률 재계산이 맞음 | 연녹 |
| 확정(사용자) | 담당자가 출처를 확정했고 값이 그대로임 | 진한 연녹 |
| 값 일치(위치 추정) | 표 블록은 못 맞췄지만 같은 값이 한 곳(또는 같은 값 여러 곳)에 있음 | 연녹(옅게) |
| 확인 필요: 출처 간 충돌 | 어떤 원본은 같고 어떤 원본은 다름 | 노랑(진하게) |
| 확인 필요: 출처 미확인 | 같은 값을 어디서도 못 찾음(계산값일 수 있음) | 노랑 |
| 확인 필요: 후보 여러 개 | 흔한 작은 값이 여러 곳에 있음 | 노랑 |
| 불일치 | 대조한 원본 값과 다름 → '고칠 값' 제시 | 빨강 |
| 불일치: 단위 다름 | 다른 배율로는 정확히 같음(예: 천원 표에 원 값) | 빨강 |
| 계산 오류 | 합계 행·열, 비율(%) 열, 증감률 문장 재계산이 다름 | 빨강 |
| 날짜·요일 오류 | "11. 25.(목)"처럼 요일이 달력과 다름 | 빨강(문장) |

- **반올림 판정**: 원본 값 x를 문서 표시 자릿수 d로 반올림했을 때 문서 값 v가 되는가(|x − v| ≤ 0.5×10⁻ᵈ).
- **합계 단수 차이**: 원→천원 환산 표에서 칸마다 반올림해 합이 몇 단위 어긋나도, 합계 칸이 원본 합계와 같으면 '일치'로 본다.
- **연쇄 오류**: 합계·비율 계산에 쓰인 칸이 이미 '불일치'면, 합계 칸에는 고칠 값을 내지 않고 "먼저 ○○ 칸을 확인하세요"라고 적는다.
- **증감률 문장**: `A건으로 전년(B건) 대비 C% 증가·감소`, `A%로 전년(B%) 대비 C%p 상승·하락` 형태를 다시 계산(방향까지 확인).

## 6. 누름틀(작업본)과 수정·입력

1. 대상 문서를 고르면 **작업본 v001**을 만든다. 데이터 숫자·빈 칸마다 누름틀을 씌우고 이름을 붙인다.
   - 이름 규칙: `표{번호}_{행 이름}_{열 이름}` (예: `표2_은하천하류_BOD`), 본문은 `P{문단}_{순번}`
   - 누름틀 구조는 실제 한글 문서의 필드 구조(`fieldBegin`/`fieldEnd`, 종류 번호 `%clk`=627272811)를 따랐다.
2. 수정·입력은 **대기 목록**에 쌓였다가 [저장(새 버전)] 때 **v002, v003 …** 새 파일로 저장된다(이전 버전은 그대로).
3. 저장 직후 새 파일을 다시 읽어 값이 제대로 들어갔는지 확인하고, 틀리면 저장을 취소한다.
4. 작업본을 한글에서 직접 고쳐 저장해도 된다. 다음 검증 때 파일 고유값이 바뀐 것을 알아채고, 바뀐 칸을 **'한글에서 직접 수정'** 으로 이력에 남긴다.
5. [입력하기]: 원본에서 여러 칸을 고르면 시작 칸부터 **같은 모양**으로 채운다. 값이 이미 같으면 값은 그대로 두고 **출처만 확정**한다.

### 6.1 클립보드 출처 기록(Windows)
엑셀은 Ctrl+C 때 클립보드에 `Excel\0C:\폴더\[파일.xlsx]시트\0R2C3:R5C6` 형태의 'Link' 정보를 함께 넣는다. 켜 두면 이것을 0.5초마다 확인해 기록하고, 검증 때 같은 값의 칸에 "복사 기록"으로 보여 준다.
→ **실제 Windows·엑셀에서 아직 시험하지 못함(미검증)**. 구문 해석은 자동 시험으로 확인했다.

## 7. 예상 오류와 대응

| 분류 | 상황 | 대응 |
|---|---|---|
| 파일 읽기 | 0바이트·깨진 zip·구형 hwp(OLE)·암호 문서 | 그 원본만 '읽기 실패'로 표시, 나머지 계속(시험 완료) |
| 파일 읽기 | 엑셀 잠금 파일(`~$…`) | 자동 제외(시험 완료) |
| 파일 읽기 | 50만 칸 넘는 시트 | 앞 40만 칸만 색인하고 '주의' 표시(config에서 조정) |
| 문서 구조 | 표 안의 표 | 안쪽 표는 건너뛰고 경고 |
| 문서 구조 | 숫자가 여러 글자 묶음(run)에 걸쳐 있거나 탭이 섞임 | 읽기·검증은 하되 '직접 고칠 수 없음' 표시 → 한글에서 수정 |
| 값 해석 | 날짜·연도·조문·항목 번호(요구자료 10.)·시각·전화번호 | 숫자로 보지 않음(config.SKIP_PATTERNS) |
| 값 해석 | △·▲(음수), 천 단위 쉼표, %·%p | 처리 |
| 대조 | 같은 값이 여러 원본에 있음 | 블록 대조 → 실패 시 후보 목록, 사용자가 확정 |
| 대조 | 계산값(두 분류를 더한 '기타' 등) | '출처 미확인'(틀렸다는 뜻 아님)으로 표시 |
| 원본 | 등록 후 파일 이동·삭제 | '파일 없음' 표시, 검증은 나머지로 계속 |
| 원본 | 내용 변경 | SHA-256 비교로 감지, 영향 칸 수 안내, 다시 검증 시 바뀐 칸 표시 |
| 저장 | 저장 후 값 확인 실패 | 새 버전 파일 삭제, 작업본 유지 |
| 동시 조작 | 준비 중에 검증을 누름 | 서버가 작업을 하나씩 처리, 화면은 '처리 중' 표시로 클릭 차단(시험 완료) |
| 환경 | 포트 사용 중 | 다음 번호 자동 선택, 이미 켜져 있으면 그 화면을 엶 |
| 보안 | 다른 사이트에서 이 서버로 요청 | 127.0.0.1만 열고, Host 확인 + 전용 머리글(X-Numjigi) 없는 요청 거부 |
