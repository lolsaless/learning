## 1. 한 줄 소개

> 요구 공문의 양식을 읽어 **채울 칸**을 알려 주고, 팀이 다시 보낸 엑셀·한글의 **바뀐 곳**을 찾아 주고, 취합본의 **모든 숫자를 원본과 대조**해 출처대장을 남기는 도구.
> AI는 글을 읽고 바꾸는 일만 하고, **맞다·틀리다 판정은 언제나 계산이 한다.**

## 2. 해결하는 고민(요구자료 한 건의 흐름)

| 단계 | 현장에서 생기는 일 | 담당 파트 | 상태 |
|---|---|---|---|
| ① 받기 | 공문 첨부 양식이 "작성해서 내는 것"인지 "참고용"인지, 어디를 채워야 하는지 모름 | **양식 분석**(form) | 2단계 |
| ② 나눠 받기 | 팀별로 엑셀·한글 답이 옴 | 원본(sources) | ✅ |
| ③ 다시 받기 | "수정본", "최종" 이 다시 옴. 무엇이 바뀌었는지 모름 | **재제출 비교**(compare) | 1단계 |
| ④ 취합 | 옮겨 적다 틀림(합계·단위·증감률·요일) | 검증(verify)·수정(edit) | ✅ |
| ⑤ 남기기 | 출처가 남지 않아 다음 해에 처음부터 다시 함 | 내보내기(export)·이력(history) | ✅ |
| 공통 | 문장 속 숫자 주장, 변경 요약 | **AI**(ai) — 출력은 코드가 검증 | 3단계 |

## 3. 설계 원칙 — "파트로 나누고, 조립부만 연결한다"

| 번호 | 원칙 | 지키는 방법 |
|---|---|---|
| P1 | 기능 하나 = 파트 폴더 하나(`app/parts/<이름>/`) | 폴더 안에 `part.py`(기능) · `routes.py`(화면 주소) · `README.md`(안내) |
| P2 | 파트는 다른 파트를 부르지 않는다 | 필요한 값은 **조립부** `app/workspace.py` 가 넘겨 줌. `tests/test_structure.py` 가 자동 검사 |
| P3 | 아래층은 위층을 모른다 | `common`·`formats`·`store` 는 파트·조립부·화면 연결을 import 하지 않음(자동 검사) |
| P4 | 바뀔 수 있는 값은 한 곳에 | `app/config.py` (이름·포트·배율·사전·색·켜진 파트) |
| P5 | 파트 켜고 끄기 | `config.PARTS` 목록에서 빼면 그 파트의 화면 주소가 꺼짐 |
| P6 | 화면도 페이지별 파일 | `ui/pages/<이름>.html`(모양) + `ui/js/pages/<이름>.js`(동작) |
| P7 | 원본은 읽기만 | 작업본·보관본·내보내기는 모두 작업 폴더 안에 새로 만듦(대회 공통 규칙) |
| P8 | 판정은 계산, AI는 보조 | AI 출력은 모두 코드가 다시 확인. AI가 없거나 틀려도 틀린 판정이 나오지 않음 |
| P9 | 파일 하나 800줄 이하 | 넘으면 나눌 때가 된 것(자동 검사) |

### 3.1 층 구조

```

            │ index.html · css · js/core.js · pages/* │
            └───────────────────┬────────────────────┘
                                │ api("/api/…")
            ┌───────────────────▼────────────────────┐
            │ 화면 연결(app/web)                       │
            │ server.py  core_routes.py  demo.py  fsbrowse.py │
            └───────────────────┬────────────────────┘
                                │ 켜진 파트의 routes.py 를 모아 주소표 생성
            ┌───────────────────▼────────────────────┐
            │ 조립부(app/workspace.py) — 계산 없음, 연결만 │
            └──┬──────┬──────┬──────┬──────┬──────┬───┘
               ▼      ▼      ▼      ▼      ▼      ▼
            원본   문서   검증   수정   이력  내보내기  클립보드   (+ 비교·양식·AI 예정)

               └──────┴──────┴──┬───┴──────┴──────┘
                                ▼
            공통(common) · 파일 형식(formats) · 저장소(store) · 설정(config.py)
```

```

├─ 시연자료_다시만들기.bat
├─ app/
│  ├─ main.py               ← 시작점
│  ├─ config.py             ← 설정(비개발자가 고치는 곳)
│  ├─ workspace.py          ← 작업 조립부
│  ├─ evaluation.py         ← 평가 조립부(정답표 채점·일괄 평가)
│  ├─ common/               ← 공통 도구: errors · files · numbers · context

│  ├─ store/                ← 이력 장부(SQLite)
│  ├─ parts/<이름>/         ← 기능 파트(아래 4장)

└─ docs/                    ← 이 설계서 · v1.0 기록
```

### 3.3 작업 맥락(Context)

조립부가 작업 폴더를 열 때 `Context(folder, db, user, lock)` 를 하나 만들어 모든 파트에 똑같이 넘긴다. 파트가 아는 것은 이 묶음과 공통 도구뿐이다.

### 3.4 파트끼리 값이 오가는 방법

| 필요 | 방법 | 예 |
|---|---|---|
| A의 결과를 B가 써야 함 | 조립부가 A를 부르고 결과를 B에 인자로 넘김 | `verify.run(doc=문서파트.doc(), names=원본파트.names(), …)` |
| A에서 일이 생기면 B가 알아야 함 | 조립부가 A에 알림 함수(콜백)를 연결 | 원본을 읽으면 `on_load` → 검증 파트 색인에 추가 |

## 5. 새 파트 설계

### 5.1 재제출 비교(compare) — 1단계

| 항목 | 설계 |
|---|---|
| 문제 | 원본이 바뀐 것은 v1.0도 알지만 **무엇이 바뀌었는지**는 모름. 팀이 이름을 바꿔 다시 보내면(`…_수정.xlsx`) 새 파일로만 보임 |
| 보관 | 원본을 등록·변경할 때 작업 폴더 `원본보관/<sid>/<고유값 앞 12자리>.<확장자>` 로 **복사**(원본은 그대로) |
| 비교 | xlsx: 시트 짝짓기(이름 → 모양) 후 셀 단위 `바뀜·추가·삭제`. hwpx: 표는 셀 단위, 본문은 문단 단위 |
| 짝 찾기 | 새로 등록한 파일이 기존 원본의 **새 판**인지: 파일 이름 유사도 + 시트 이름·크기·숫자 겹침 점수. 점수가 기준 이상이면 "새 판 후보"로 묻고, 사용자가 확인 |
| 영향 | 바뀐 셀 ↔ 마지막 검증에서 그 셀을 출처로 쓴 문서 칸 → "문서 칸 3개가 이 변경의 영향을 받음(이전 값 → 새 값)" |
| 출구 | `{"sheets":[…], "changes":[{"sheet","ref","old","new","kind"}], "affected":[{"slot","label","old","new"}]}` |
| 화면 | 원본 변경 확인 창에 [바뀐 곳 보기] → 셀 목록 + 미니 격자(노랑) |
| 시험 | 시연 2단계 자료(수질팀 수정본)로 바뀐 셀 정답표 채점 |

### 5.2 양식 분석(form) — 2단계

| 항목 | 설계 |
|---|---|
| 입력 | 요구 공문의 첨부(hwpx·xlsx) 여러 개 |
| 채울 칸 찾기 | `○○`·`□□` 자리 표시, 머리글 아래 빈 셀, "작성", "기재" 안내문 옆 빈칸, 엑셀의 빈 입력 칸(테두리·노란 바탕 등 서식 단서) |
| 판정: 작성 제출용 / 참고용 | 규칙 점수 — 빈 칸 비율, 자리 표시 수, "작성하여 제출" 같은 문구. **근거 목록을 함께 보여 줌** |
| 기한 | 본문의 날짜 + "까지" → 날짜·요일 계산은 코드(common/numbers) |
| 연결 | [이 양식으로 작업 시작] → 문서 파트의 대상 문서로 설정 → 입력하기 화면으로 |
| 출구 | `{"files":[{"name","kind":"작성제출|참고","score","reasons":[…],"fields":[{"where","label","hint"}]}], "deadlines":[…]}` |

### 5.3 AI(ai) — 3단계

| 항목 | 설계 |
|---|---|
| 연결 | 어댑터 하나(`adapter.py`): Ollama(127.0.0.1) · OpenAI 호환 주소(대회 공통기반 API 등). 모델 이름·주소는 `config.py` |
| 맡기는 일 | ① 문장 → 검사식: "전년보다 2배 늘었다" → `{대상, 항목, 비교, 배수}` ② 변경 요약 문장 ③ 양식 칸 설명 |
| 검증(코드) | ① 검사식을 계산해서 맞을 때만 채택, 원문에 없는 대상·숫자면 버림 ② 요약에 나온 숫자가 실제 변경 목록에 있는지 ③ 형식(JSON) 확인. 실패하면 규칙 결과만 보여 줌 |
| 모델 2종 비교 | 같은 시험 문장 묶음으로 채택률·오답률·속도 비교표(대회 권장 "모델 비종속" 입증) |
| AI가 없을 때 | 모든 기능이 규칙만으로 동작(AI 칸에 "AI 꺼짐") |

## 7. 새 파트 추가하는 법(유지보수 안내)

1. `app/parts/<이름>/` 폴더를 만들고 `__init__.py`(빈 파일), `part.py`, `routes.py`, `README.md` 를 둔다.
2. `part.py` 에 `class <이름>Part: def __init__(self, ctx)` 를 만든다. 다른 파트는 import 하지 않는다.
3. `routes.py` 에 `def routes(app): return [("GET"|"POST", "/api/<이름>/…", 처리함수), …]` 를 적는다.
4. `app/workspace.py` 에서 파트를 만들고, 필요한 값을 다른 파트에서 꺼내 넘겨 주는 함수를 추가한다.
5. `app/config.py` 의 `PARTS` 목록에 이름을 넣는다.
6. 화면이 필요하면 `ui/pages/<이름>.html`, `ui/js/pages/<이름>.js` 를 만들고 `index.html` 에 탭·`<section>`·`<script>` 한 줄씩 추가한다.
7. `python tests/run_all.py` → **전체 통과**를 확인한다.
