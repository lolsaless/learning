## 2. Git과 GitHub란? (12분)

### 이런 경험 있으시죠?
```
보고서.hwp
보고서_수정.hwp
보고서_최종.hwp
보고서_최종_과장님검토.hwp
보고서_최종_진짜최종.hwp
```
→ 어느 게 최신인지, 무엇이 바뀌었는지 알기 어렵습니다. USB·메일로 PC 사이를 옮기다 보면 더 헷갈립니다.

### Git = 변경 기록 장치
- 파일 이름을 바꾸지 않고, **"언제, 누가, 무엇을, 왜 바꿨는지"** 를 기록합니다.
- 이 기록 한 번을 **커밋(commit)** 이라고 합니다. 게임의 **세이브 포인트**와 같습니다.
- 언제든 예전 커밋으로 **되돌아가거나 비교**할 수 있습니다.

### GitHub = 인터넷 위의 보관소
- 내 PC의 Git 기록을 **인터넷에 올려 두는 곳**입니다.
- Mac mini, MacBook, Windows PC 어디서든 **같은 기록을 받아서** 이어서 작업합니다.
- 강사에게 과제를 **링크 하나로** 보여 줄 수 있습니다.

### 꼭 알아야 할 단어 6개

| 단어 | 뜻 | 비유 |
|---|---|---|
| **저장소 (repository, repo)** | Git이 기록을 관리하는 폴더 | 기록부가 붙어 있는 서류함 |
| **커밋 (commit)** | 변경 내용을 기록 한 번으로 저장 | 세이브 포인트 |
| **푸시 (push)** | 내 PC의 커밋을 GitHub로 올리기 | 보관소에 맡기기 |
| **풀 (pull)** | GitHub의 새 커밋을 내 PC로 받기 | 보관소에서 최신본 찾아오기 |
| **클론 (clone)** | GitHub 저장소를 통째로 내 PC에 복사 | 서류함을 처음 들여오기 |
| **.gitignore** | Git이 **무시할** 파일 목록 | "이건 기록하지 마세요" 쪽지 |

### 하루 작업 흐름
```
 작업 시작 ──▶ git pull (최신 받기)
     │
     ▼
 코드 수정 ──▶ commit (기록) ──▶ push (올리기)
                                     │
 다른 PC에서 ──▶ git pull ◀───────────┘
```

> ⚠️ **GitHub에 올리면 안 되는 것:** 실제 업무 데이터, 개인정보, 비밀번호·API 키. 저장소를 **비공개(Private)** 로 만들어도, 업무 데이터는 올리지 않는 것이 원칙입니다. (06회 안전 수칙)

## 3. 사용자 설정과 GitHub 로그인 (10분)

### 3-1. Git 사용자 설정 (한 번만)
커밋에 "누가 바꿨는지" 기록하기 위한 이름과 이메일입니다.
```bash
git config --global user.name "홍길동"
git config --global user.email "GitHub가입이메일@example.com"
git config --global init.defaultBranch main
```

### 3-2. GitHub CLI 설치와 로그인
GitHub는 **비밀번호 로그인을 받지 않습니다.** 공식 도구 **GitHub CLI(`gh`)** 로 로그인하면 가장 간단합니다.

| | 설치 |
|---|---|
| Mac | `brew install gh` |
| Windows | `winget install --id GitHub.cli -e --source winget` (설치 후 PowerShell 새로 열기) |

```bash
gh auth login
```
질문에 이렇게 답합니다.
1. Where do you use GitHub? → **GitHub.com**
2. Preferred protocol? → **HTTPS**
3. Authenticate Git with your GitHub credentials? → **Yes**
4. How would you like to authenticate? → **Login with a web browser**
5. 화면에 나온 **8자리 코드**를 복사 → Enter → 열린 브라우저에 코드 입력 → [Authorize]

확인: `gh auth status` → `Logged in to github.com account 내아이디`

## 4. 저장소 만들고 GitHub에 올리기 (15분)

`실습지.md` Part C~D를 따라 합니다.

1. `gitignore_예시.txt`를 `ai-black/.gitignore`로 복사 → `.venv`, `.DS_Store` 등이 올라가지 않게
2. `ai-black`에서 `git init` → 저장소 시작
3. `git add .` → `git commit -m "..."` → 첫 커밋
4. `gh repo create ai-black --private --source=. --push` → GitHub에 **비공개 저장소**를 만들고 한 번에 올리기
5. 브라우저에서 `https://github.com/내아이디/ai-black` 확인 → `.venv`가 **없는 것** 확인

### 커밋 메시지 쓰는 법
| 나쁜 예 | 좋은 예 |
|---|---|
| `수정` | `09회 과제: 측정값 8개로 변경, 기준 초과 횟수 추가` |
| `asdf` | `requirements.txt에 tabulate 추가` |
| `최종` | `10회 노트북: 회의실 측정값 추가` |

> **"무엇을 바꿨는지"** 가 한 줄에 보이게. 나중의 나와 동료가 읽습니다.

## 5. VS Code로 커밋하기, 다른 PC처럼 받아 보기 (15분)

### 5-1. VS Code 소스 제어 패널
왼쪽 활동 막대의 **가지 모양 아이콘**(소스 제어, `Ctrl + Shift + G`)
1. 바뀐 파일이 목록에 보임 (M = 수정, U = 새 파일)
2. 위쪽 칸에 커밋 메시지 입력 → **[✓ 커밋]**
3. **[변경 내용 동기화]** (또는 `…` → 푸시) → GitHub에 올라감

> 터미널 명령(`git add`, `git commit`, `git push`)과 **같은 일**을 버튼으로 하는 것입니다. 편한 쪽을 쓰세요.

### 5-2. 다른 PC 흉내 내기
실제로 PC가 두 대 없어도, **다른 폴더에 clone**해서 연습할 수 있습니다. (`실습지.md` Part F)
```
Documents/ai-black          ← "Mac mini"라고 생각
Documents/ai-black-other-pc ← "MacBook"이라고 생각 (clone으로 받음)
```
"MacBook"에서 고쳐서 push → "Mac mini"에서 pull → 바뀐 내용이 들어오는 것을 확인합니다.

> 💬 **강사 멘트 예시:** "선생님도 Mac mini, Intel MacBook, Windows를 번갈아 씁니다. 매번 USB로 옮기지 않고 **작업 시작할 때 pull, 끝날 때 push** 두 가지만 지키면 어느 PC에서든 이어서 작업할 수 있습니다."

### 5-3. 강사를 협업자로 추가 (과제 제출용)
GitHub 저장소 → **[Settings] → [Collaborators] → [Add people]** → 강사 아이디 입력 → 강사가 초대 수락
→ 앞으로 과제는 **commit·push 후 링크만 보내면** 됩니다.

## 6. 2단계 정리 (10분)

`2단계_정리퀴즈.md`를 풀고 함께 채점합니다.

### 오늘의 핵심 3줄
1. **commit**은 기록, **push**는 올리기, **pull**은 받기, **clone**은 처음 받기.
2. `.gitignore`로 `.venv`·시스템 파일·비밀 정보는 **올리지 않는다.** 업무 데이터도 올리지 않는다.
3. **작업 시작 = pull, 작업 끝 = commit + push**

### 2단계를 마치며
이제 여러분의 PC에는 **파이썬 + VS Code + 가상환경 + Git** 이 갖춰졌습니다. 3단계부터는 이 환경에서 본격적으로 코드를 읽고 고칩니다. `공통자료/설치_점검표.md`의 모든 항목에 ✅가 되어 있는지 확인하세요.

## 강사용 참고

| 증상 | 해결 |
|---|---|
| `Please tell me who you are` | 3-1의 `git config` 실행 |
| push할 때 아이디·비밀번호를 물어봄 | `gh auth login`을 안 했거나 3번 질문에 No → 다시 `gh auth login` |
| `gh repo create`에서 이미 같은 이름이 있다고 함 | GitHub에 `ai-black` 저장소가 이미 있음 → 다른 이름 사용 또는 기존 저장소 삭제 |
| `.venv`가 GitHub에 올라감 | `.gitignore`를 커밋 **전에** 만들지 않음 → `git rm -r --cached .venv` → 커밋 → 푸시 |
| `! [rejected] ... (fetch first)` | 다른 곳에서 먼저 push함 → `git pull` 후 다시 `git push` |
| Windows에서 한글 파일 이름이 `\354\240...`처럼 보임 | `git config --global core.quotepath false` |
| 기관 PC에서 GitHub 접속 차단 | 정보화 담당자 문의. 안 되면 개인 PC로만 GitHub 사용 |

### 실습 데이터에 대한 원칙 재확인
- 수업 실습 파일(가상 데이터)은 올려도 됩니다.
- 수강생이 과제로 **실제 업무 엑셀**을 쓴 경우, 해당 파일은 `.gitignore`에 추가하거나 다른 폴더에 두게 하세요.
