# S04. Windows에서 Homebrew 쓰기 — WSL2 (보충 실습)

| 항목 | 내용 |
|---|---|
| 권장 시기 | 4주차 (08회 이후), **Windows 사용자 중 원하는 사람만** |
| 시간 | 60~70분 (재부팅 포함) |
| 준비물 | Windows 10(버전 2004 이상) 또는 Windows 11, **관리자 권한**, 인터넷 |

## 이 실습은 왜 하나요?

Homebrew는 원래 Mac(과 리눅스)용이라 **Windows에 바로 설치되지 않습니다.**
대신 Windows 안에 **리눅스(Ubuntu)를 통째로 설치**하는 **WSL2**(Windows Subsystem for Linux)를 쓰면, 그 안에서 Homebrew를 쓸 수 있습니다.

| 이런 분께 추천 | 굳이 안 해도 되는 분 |
|---|---|
| Mac과 Windows를 번갈아 쓰면서 **같은 명령**을 쓰고 싶은 분 | 정규 수업(winget + `py -3.13`)으로 충분한 분 |
| 인터넷의 개발 안내가 대부분 Mac·리눅스 명령이라 답답한 분 | 기관 PC라서 가상화·관리자 권한이 막힌 분 |

> ⚠️ **WSL의 파이썬과 Windows의 파이썬은 완전히 별개입니다.** 가상환경, 설치한 라이브러리도 따로입니다. 처음에는 하나만 정해서 쓰는 것이 덜 헷갈립니다.

---

## 1. WSL2와 Ubuntu 설치 (20분, 재부팅 1회)

1. 시작 버튼 오른쪽 클릭 → **[터미널(관리자)]** 또는 **[Windows PowerShell(관리자)]**
2. 아래 명령 실행:
   ```powershell
   wsl --install
   ```
   - 가상 머신 플랫폼, WSL, Ubuntu가 함께 설치됩니다.
3. 안내에 따라 **PC 재부팅**
4. 재부팅 후 Ubuntu 창이 자동으로 열리고 설정을 묻습니다.
   - **사용자 이름**: 영어 소문자 (예: `hong`)
   - **비밀번호**: 입력해도 화면에 안 보이는 것이 정상. **잊지 마세요** (`sudo` 명령에 필요)
5. 확인 (Windows PowerShell에서):
   ```powershell
   wsl -l -v
   ```
   → `Ubuntu   Running   2` 처럼 **VERSION 2**가 보이면 성공

> 시작 메뉴에서 **"Ubuntu"** 를 검색하면 언제든 리눅스 터미널을 열 수 있습니다.

---

## 2. Ubuntu 준비 (5분)

Ubuntu 터미널에서:
```bash
sudo apt update
sudo apt install -y build-essential procps curl file git
```
- `sudo` = 관리자 권한으로 실행. 처음에 Ubuntu 비밀번호를 물어봅니다.

---

## 3. Homebrew 설치 (15분)

Mac과 **같은 명령**입니다.
```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

설치가 끝나면 **"Next steps"** 의 명령을 실행합니다. 리눅스에서는 보통 다음과 같습니다.
```bash
echo 'eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv)"' >> ~/.bashrc
eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv)"
```
> Mac은 `~/.zprofile`에 적었지만, Ubuntu의 기본 셸은 **bash**라서 `~/.bashrc`에 적습니다. Next steps에 나온 경로를 그대로 따르세요.

확인:
```bash
brew --version
brew --prefix          # /home/linuxbrew/.linuxbrew
```

---

## 4. Homebrew로 개발 도구 설치 (10분)

```bash
brew install python@3.13 gh tree
python3.13 --version
gh --version
```
→ 이제 Mac 강의노트의 명령(`python3.13 -m venv .venv`, `source .venv/bin/activate` 등)을 **그대로** 쓸 수 있습니다.

---

## 5. VS Code와 연결 (10분)

1. Windows의 VS Code에서 확장 **"WSL"** (만든 곳: Microsoft) 설치
2. Ubuntu 터미널에서 작업 폴더를 만들고 VS Code로 엽니다.
   ```bash
   mkdir -p ~/ai-black
   cd ~/ai-black
   code .
   ```
3. VS Code 왼쪽 아래에 **`WSL: Ubuntu`** 가 보이면 리눅스 안의 폴더를 열고 있는 것입니다.
   - 이 창에서 연 터미널은 Ubuntu 터미널입니다.
   - Python·Jupyter 확장은 **WSL 쪽에도** 설치하라고 안내가 나오면 [설치]를 누릅니다.

### 파일은 어디에 두나요?
| 위치 | 경로 | 권장 |
|---|---|---|
| 리눅스 홈 | `~/ai-black` (Windows 탐색기에서는 `\\wsl$\Ubuntu\home\hong\ai-black`) | ✅ WSL에서 작업할 때는 여기 (빠름) |
| Windows 폴더 | `/mnt/c/Users/hong/Documents/...` | ⚠️ WSL에서 열면 느림 |

> Windows 탐색기 왼쪽 목록 아래쪽의 **🐧 Linux** 항목에서도 리눅스 파일을 볼 수 있습니다.

## 문제 해결

| 증상 | 해결 |
|---|---|
| `wsl --install` 후 "가상화를 사용하도록 설정하세요" 오류 | PC의 BIOS/UEFI에서 가상화(Intel VT-x / AMD-V, SVM) 켜기. 기관 PC는 정보화 담당자에게 문의 |
| `wsl -l -v`에 VERSION 1 | `wsl --set-version Ubuntu 2` |
| Ubuntu 비밀번호를 잊음 | PowerShell: `wsl -u root` → `passwd 사용자이름` |
| `brew: command not found` | 3절의 Next steps(`~/.bashrc`) 명령을 실행하지 않음 |
| VS Code에서 `code .`가 안 됨 | Windows VS Code에 WSL 확장 설치 후 Ubuntu 터미널을 새로 열기 |
| 디스크 공간이 부족 | WSL은 수 GB를 씀. `brew cleanup`으로 정리 |
