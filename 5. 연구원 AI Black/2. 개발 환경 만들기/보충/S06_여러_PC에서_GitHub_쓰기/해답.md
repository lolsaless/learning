## 4절 충돌 실습 — 단계별 기대 결과

| 단계 | 기대 결과 |
|---|---|
| ② `git push` | `! [rejected] main -> main (fetch first)` — 다른 PC가 먼저 올린 커밋이 있어 거부 |
| ② `git pull` | `CONFLICT (content): Merge conflict in 01_practice/first_program.py` / `Automatic merge failed; fix conflicts and then commit the result.` |
| VS Code | 충돌 부분이 색으로 표시되고 위에 **[현재 변경 사항 수락 / 수신 변경 사항 수락 / 두 변경 사항 모두 수락 / 변경 사항 비교]** 버튼 |
| 해결 후 `git commit` → `git push` | 정상 완료. GitHub History에 두 커밋과 **병합(Merge) 커밋**이 함께 보임 |

> Git 버전·설정에 따라 `git pull` 때 "divergent branches" 안내와 함께 방법을 고르라고 할 수 있습니다. 그럴 때는 한 번만 설정하세요:
> ```bash
> git config --global pull.rebase false
> ```
> 그다음 다시 `git pull`.

## 강사 운영 팁
- 충돌 실습은 **일부러** 만드는 것이 중요합니다. 실제 업무에서 처음 충돌을 만나면 당황해서 폴더를 지우고 다시 받는 경우가 많습니다. "**충돌 = Git이 질문하는 것**"이라는 인식을 심어 주세요.
- 수강생이 2명이면 **같은 저장소를 공유**해서 실제로 서로 충돌을 만들어 보는 것도 좋습니다. (한 명의 저장소에 다른 한 명을 Collaborator로 추가)
- GitHub Desktop을 쓰는 수강생에게도, 충돌 해결은 **VS Code에서** 하도록 안내하세요. GitHub Desktop의 [Open in Visual Studio Code] 버튼을 쓰면 됩니다.
