# S06. 여러 PC에서 GitHub 쓰기 (보충 실습)

| 항목 | 내용 |
|---|---|
| 권장 시기 | 6주차 (12회 이후) |
| 시간 | 60~70분 |
| 준비물 | 12회에서 만든 GitHub `ai-black` 저장소, (가능하면) 두 번째 PC |
| 참고 자료 | `3. Python/1. brew setup/Git_시스템파일_차단_가이드.md` |

## 목표
- 새 PC를 **처음 세팅하는 순서**와 **매일의 작업 루틴**을 익힌다.
- **GitHub Desktop**으로 버튼만으로 pull·commit·push를 한다.
- 두 PC에서 같은 줄을 고쳤을 때 생기는 **충돌(conflict)** 을 해결한다.
- Mac·Windows를 오갈 때 생기는 문제(`.DS_Store`, 줄바꿈)를 예방한다.

## 2. 매일의 작업 루틴 (5분)

```
┌─────────────── 작업 시작 ───────────────┐
│ 1. VS Code로 ai-black 폴더 열기            │
│ 2. git pull  (다른 PC의 최신 내용 받기)      │
│ 3. requirements.txt가 바뀌었으면           │
│    pip install -r requirements.txt        │
└──────────────────────────────────────────┘
               ▼   작업   ▼
┌─────────────── 작업 끝 ─────────────────┐
│ 4. commit (무엇을 했는지 메시지)            │
│ 5. push   (GitHub로 올리기)                │
└──────────────────────────────────────────┘
```

> ⚠️ **가장 흔한 실수:** 다른 PC에서 push한 뒤, 이 PC에서 **pull을 잊고** 작업 시작 → 나중에 push가 거부되거나 충돌 발생. **"앉으면 pull, 일어나면 push"** 로 외우세요.

## 3. GitHub Desktop — 버튼으로 하는 Git (15분)

터미널이 아직 부담스럽다면 **GitHub Desktop**을 써도 됩니다. 하는 일은 똑같습니다.

### 설치
| | 명령 |
|---|---|
| Mac | `brew install --cask github` |
| Windows | `winget install --id GitHub.GitHubDesktop -e --source winget` |

### 사용
1. 실행 → **[Sign in to GitHub.com]** → 브라우저에서 승인
2. **[File] → [Add local repository]** → `Documents/ai-black` 선택 (이미 있는 저장소 추가)
3. 화면 구성

| 버튼·영역 | 하는 일 | 터미널 명령 |
|---|---|---|
| **Fetch origin / Pull origin** | GitHub의 최신 내용 확인·받기 | `git pull` |
| 왼쪽 **Changes** 목록 | 바뀐 파일 (체크한 것만 커밋) | `git status`, `git add` |
| 왼쪽 아래 **Summary** 칸 + **[Commit to main]** | 커밋 | `git commit -m "..."` |
| **Push origin** | 올리기 | `git push` |
| **History** 탭 | 지난 기록 | `git log` |

### 미션
1. `01_practice/hello_vscode.py`에 한 줄 추가 → GitHub Desktop의 Changes에서 **초록(추가)/빨강(삭제)** 확인
2. Summary에 메시지 입력 → **[Commit to main]** → **[Push origin]**
3. GitHub 웹에서 반영 확인

## 4. 충돌(conflict) 해결해 보기 (20분)

**충돌**은 두 PC에서 **같은 파일의 같은 줄**을 다르게 고쳤을 때 생깁니다. Git이 "어느 쪽이 맞나요?"라고 묻는 것입니다. 무서운 것이 아닙니다.

### 충돌 만들기 (12회 Part F처럼 두 폴더로 흉내)
```bash
cd ~/Documents                       # Windows: cd ~\Documents
gh repo clone ai-black ai-black-pc2  # "두 번째 PC"
```

**① "두 번째 PC"에서 고치고 push**
`ai-black-pc2/01_practice/first_program.py`에서 `limit = 1000`을 `limit = 900`으로 바꾸고:
```bash
cd ai-black-pc2
git add .
git commit -m "기준값 900으로 변경"
git push
```

**② "첫 번째 PC"에서 pull 없이 같은 줄을 다르게 고치고 commit**
`ai-black/01_practice/first_program.py`에서 `limit = 1000`을 `limit = 1200`으로 바꾸고:
```bash
cd ../ai-black
git add .
git commit -m "기준값 1200으로 변경"
git push           # ← 거부됨: rejected (fetch first)
git pull           # ← CONFLICT 발생!
```

### 충돌 해결
1. VS Code에서 `first_program.py`를 열면 이렇게 보입니다.
   ```
   <<<<<<< HEAD
   limit = 1200
   =======
   limit = 900
   >>>>>>> (다른 쪽 커밋 번호)
   ```
   - 위(`HEAD`) = **내 PC**의 내용, 아래 = **GitHub(다른 PC)** 의 내용
2. 그 위에 보이는 버튼 중 하나를 누릅니다.
   - **[현재 변경 사항 수락]** (내 것 = 1200) / **[수신 변경 사항 수락]** (다른 PC 것 = 900) / **[두 변경 사항 모두 수락]**
   - 또는 `<<<<<<<`, `=======`, `>>>>>>>` 줄을 직접 지우고 원하는 값만 남겨도 됩니다.
3. 저장 후:
   ```bash
   git add .
   git commit -m "기준값 충돌 해결: 1000으로 유지"
   git push
   ```
   (직접 고쳐서 `limit = 1000`으로 되돌리는 것도 좋은 연습입니다)

4. 연습이 끝나면 `ai-black-pc2` 폴더는 지워도 됩니다.

> 💡 **충돌을 줄이는 법:** 작업 시작 전 pull, 작업 끝나면 바로 push, 한 파일을 여러 PC에서 동시에 고치지 않기

## 5. Mac ↔ Windows를 오갈 때 주의할 것 (10분)

### 5-1. `.DS_Store` 같은 시스템 파일
- 저장소의 `.gitignore`에 넣었다면(12회) 이 저장소는 안전합니다.
- **모든 저장소**에서 무시하려면 PC마다 한 번: `3. Python/1. brew setup/Git_시스템파일_차단_가이드.md`의 "전역 설정" 실행

### 5-2. 줄바꿈 문자 (CRLF / LF)
- 텍스트 파일의 "줄바꿈" 표시가 Windows(CRLF)와 Mac(LF)이 다릅니다. 그대로 두면 **아무것도 안 고쳤는데 파일 전체가 바뀐 것처럼** 보일 수 있습니다.
- PC마다 한 번 설정:
  ```bash
  git config --global core.autocrlf input    # Mac
  git config --global core.autocrlf true     # Windows (Git 설치 시 기본값인 경우가 많음)
  ```

### 5-3. 한글 파일 이름
- Mac과 Windows는 한글 자모를 저장하는 방식이 조금 달라, 같은 한글 파일이 **두 개처럼** 보이는 경우가 드물게 있습니다.
- 그래서 **코드 파일·폴더 이름은 영어**로 짓는 것을 권장합니다. (07회 이름 짓기 규칙)
- Mac에서 한 번 설정해 두면 예방에 도움이 됩니다: `git config --global core.precomposeunicode true`
