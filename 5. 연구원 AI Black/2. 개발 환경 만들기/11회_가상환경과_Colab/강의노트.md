## 2. 라이브러리와 가상환경 (12분)

### 라이브러리 = 남이 만들어 둔 도구 상자
파이썬만으로도 계산은 되지만, 엑셀 읽기·그래프·통계 같은 일은 **다른 사람이 만들어 둔 도구(라이브러리, 패키지)** 를 가져다 씁니다.

| 라이브러리 | 하는 일 | 쓰는 단계 |
|---|---|---|
| `pandas` | 엑셀 같은 **표**를 다룸 | 4단계 |
| `openpyxl` | `.xlsx` 파일 읽고 쓰기 (pandas가 내부에서 사용) | 4단계 |
| `matplotlib` | 그래프 | 5단계 |
| `ipykernel` | VS Code에서 노트북 실행 | 2단계~ |

라이브러리는 **`pip`** 이라는 설치 도구로 설치합니다. (`pip install pandas`)

### 가상환경 = 프로젝트 전용 도구 상자
**문제:** 라이브러리를 PC 전체(공용 파이썬)에 설치하면…
- 프로젝트 A는 pandas 2, 프로젝트 B는 pandas 3이 필요하면 **충돌**
- 무엇을 설치했는지 뒤죽박죽 → "내 PC에선 되는데 다른 PC에선 안 돼요"
- Mac의 Homebrew 파이썬은 아예 공용 설치를 **막아 둡니다** (`externally-managed-environment` 오류)

**해결:** 프로젝트 폴더 안에 **전용 파이썬 + 전용 도구 상자**를 만든다 → 이것이 **가상환경(`.venv`)** 입니다.

```
ai-black/
├── .venv/              ← 이 과정 전용 파이썬과 라이브러리 (10회에 VS Code가 만든 것)
├── requirements.txt    ← "이 도구들이 필요하다"는 목록
├── 01_practice/
└── 02_homework/
```

> 💬 **강사 멘트 예시:** "가상환경은 **실험실의 개인 실험대**와 같습니다. 공용 실험대에 시약을 마구 올려 두면 다른 사람 실험과 섞이죠. 내 실험대에 필요한 시약만 올려 두고, 시약 목록(`requirements.txt`)을 적어 두면 다른 실험실에서도 똑같이 차릴 수 있습니다."

### 이 과정의 원칙
1. `ai-black` 폴더에 **가상환경 하나(`.venv`)** 를 만들어 과정 내내 씁니다.
2. 필요한 라이브러리는 **`requirements.txt`** 에 적어 둡니다. (과정 폴더의 `requirements.txt`를 복사해서 사용)
3. `.venv` 폴더는 **복사하거나 Git에 올리지 않습니다.** PC마다 `requirements.txt`로 **새로 만듭니다.**
   - Mac mini, MacBook, Windows를 번갈아 쓴다면: 코드와 `requirements.txt`만 옮기고, 각 PC에서 `.venv`를 만듭니다.

## 3. 가상환경 직접 만들기 (20분)

10회에 VS Code가 버튼으로 해 준 일을 **터미널로 직접** 해 봅니다. `실습지.md` Part A~B를 따라 합니다.

### 순서 요약

| 단계 | Mac | Windows (PowerShell) |
|---|---|---|
| ① 폴더 이동 | `cd ~/Documents/ai-black` | `cd ~\Documents\ai-black` |
| ② 만들기 | `python3.13 -m venv .venv` | `py -3.13 -m venv .venv` |
| ③ 켜기 | `source .venv/bin/activate` | `.venv\Scripts\Activate.ps1` |
| ④ 확인 | 줄 앞에 `(.venv)` / `which python` | 줄 앞에 `(.venv)` / `where.exe python` |
| ⑤ pip 업데이트 | `python -m pip install --upgrade pip` | 같음 |
| ⑥ 라이브러리 설치 | `pip install -r requirements.txt` | 같음 |
| ⑦ 끄기 | `deactivate` | `deactivate` |

- 10회에 이미 `.venv`가 만들어졌다면 ②는 건너뛰어도 됩니다. (다시 만들어도 괜찮습니다)
- **가상환경을 켜면** `python3.13`/`py -3.13` 대신 그냥 **`python`** 이라고 써도 됩니다. 켜져 있는 동안 `python` = 이 가상환경의 파이썬
- Windows에서 ③이 "스크립트를 실행할 수 없으므로…" 오류가 나면 → 한 번만 실행:
  ```powershell
  Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
  ```

### VS Code가 알아서 켜 준다
- VS Code에서 인터프리터를 `.venv`로 선택해 두면, **새 터미널을 열 때 자동으로** `(.venv)`가 켜집니다.
- 노트북의 커널도 `.venv`를 고르면 됩니다.

## 5. 내 PC vs Google Colab (8분)

| | 내 PC (가상환경) | Google Colab |
|---|---|---|
| 설치 | 필요 (오늘 한 것) | 필요 없음, 브라우저만 |
| 데이터 위치 | **내 PC** — 밖으로 안 나감 | **구글 서버**로 업로드 |
| 라이브러리 | 직접 설치 (`requirements.txt`) | 대부분 미리 설치됨 |
| 인터넷 | 없어도 실행 가능 | 필수 |
| 파일 보관 | 계속 남음 | 세션이 끝나면 올린 파일이 사라짐 |
| 이럴 때 | **실제 업무 데이터**, 반복 쓰는 프로그램 | 연습, 공개 데이터, 설치가 안 되는 PC, 강의 |

> **업무 데이터 = 내 PC**, **연습·공개 데이터 = Colab도 OK** (06회 "AI에게는 구조를, 내 PC에서는 실제 데이터를"과 같은 원칙)

`실습지.md` Part D에서 같은 노트북을 Colab에서 실행해 비교합니다.

## 강사용 참고

| 증상 | 해결 |
|---|---|
| `pip install` 중 `externally-managed-environment` (Mac) | 가상환경이 **꺼진** 상태. `source .venv/bin/activate` 후 다시 |
| `(.venv)`가 보이는데 `ModuleNotFoundError` | VS Code 노트북 커널이 `.venv`가 아님 → 오른쪽 위 커널 다시 선택 |
| `pip install`이 매우 느리거나 SSL 오류 | 기관 네트워크(프록시) 문제일 수 있음 → 개인 네트워크, 또는 정보화 담당자 문의 |
| `.venv`를 OneDrive·iCloud 폴더 안에 만들어 느림 | 동기화 폴더 밖(예: 홈 폴더 아래)으로 `ai-black`을 옮기거나 동기화 제외 |
| Windows에서 `py -3.13 -m venv` 실패 | `py --list`로 3.13 설치 확인 |

### 참고: 여러 Mac에서 가상환경을 공유하지 않는 이유
`3. Python/1. brew setup/apple-silicon-python-venv-setup.md`에 정리된 것처럼, Apple 실리콘과 Intel Mac은 파이썬 실행 파일이 달라 **가상환경 폴더를 공유하면 동작하지 않습니다.** 코드와 `requirements.txt`만 공유하고 가상환경은 PC마다 만듭니다. (이 가이드처럼 `~/.venvs/이름`에 따로 두는 방법도 있습니다)
