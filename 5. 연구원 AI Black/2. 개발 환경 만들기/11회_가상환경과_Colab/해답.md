## Part B. 실험: 가상환경을 끄면?
- **Mac:** `ModuleNotFoundError: No module named 'pandas'` — Homebrew 파이썬(공용)에는 pandas를 설치하지 않았기 때문
- **Windows:** 마찬가지로 `ModuleNotFoundError`. (누군가 공용 파이썬에 pandas를 설치해 두었다면 오류 없이 실행될 수도 있음)
- **핵심:** 라이브러리는 **가상환경 안에만** 설치되어 있다. 그래서 VS Code·터미널에서 **가상환경이 켜져 있는지** 항상 확인해야 한다.

## 과제 해답

### 1~2. 다시 만들기 명령
Mac:
```bash
cd ~/Documents/ai-black
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```
Windows:
```powershell
cd ~\Documents\ai-black
py -3.13 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 3. 도전 — `pip freeze` vs 직접 적기

| | `pip freeze > requirements.txt` | 이름만 직접 적기 (이 과정 방식) |
|---|---|---|
| 내용 | 설치된 **모든** 라이브러리와 **정확한 버전** (`pandas==3.0.5` 등, 딸려 온 것까지 수십 줄) | 내가 직접 쓰는 라이브러리 **이름만** |
| 장점 | 완전히 똑같은 환경을 다시 만들 수 있음 | 짧고 읽기 쉬움, 운영체제가 달라도 잘 설치됨 |
| 단점 | 길고, Mac·Windows 간에 맞지 않는 버전이 섞일 수 있음 | 설치 시점에 따라 버전이 조금 다를 수 있음 |
| 이럴 때 | 완성된 프로그램을 배포할 때, 결과 재현이 꼭 필요할 때 | 학습, 여러 운영체제를 오가며 쓸 때 |

> 💬 이 과정은 Mac·Windows를 함께 쓰므로 **이름만 적는 방식**을 기본으로 합니다. 6단계에서 프로그램을 배포할 때 버전 고정을 다룹니다.
