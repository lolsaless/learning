## 1. 설치·환경 (2단계)

### `command not found: brew` (Mac)
- **원인:** Homebrew는 설치됐지만 터미널이 위치를 모름 (PATH 설정 안 됨)
- **해결:** 설치 마지막에 나온 "Next steps"의 두 줄을 실행. Apple 실리콘 기준:
  ```bash
  echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
  eval "$(/opt/homebrew/bin/brew shellenv)"
  ```
  Intel Mac은 `/opt/homebrew` 대신 `/usr/local`
- 새 터미널 창을 열어 `brew --version` 확인

### `zsh: command not found: python` (Mac)
- **원인:** Mac에서는 `python`이라는 이름이 없습니다. 이 과정에서는 버전을 붙인 **`python3.13`** 으로 실행합니다.
- **해결:** `python3.13 --version`. 가상환경을 켠 상태에서는 `python`도 동작합니다.
- `python3.13`도 없다고 나오면 `brew install python@3.13`이 끝났는지, Homebrew PATH 설정이 되어 있는지 확인하세요.

### `python`을 입력했더니 Microsoft Store가 열림 (Windows)
- **원인:** Windows의 "앱 실행 별칭"이 가짜 `python`을 먼저 실행
- **해결:** [설정] → [앱] → [고급 앱 설정] → **[앱 실행 별칭]** → `python.exe`, `python3.exe`의 **앱 설치 관리자** 항목 끄기 → PowerShell 새로 열기
- 또는 `py -3.13` 명령 사용 (이 과정의 기본 방법)

### `'python'은(는) 내부 또는 외부 명령... 아닙니다` / `python: The term 'python' is not recognized` (Windows)
- **원인:** 설치할 때 **"Add python.exe to PATH"** 를 체크하지 않음
- **해결:** Python 설치 파일을 다시 실행 → [Modify] 또는 제거 후 재설치하면서 **Add python.exe to PATH 체크**
- 이 과정에서는 원래 **`py -3.13`** 명령을 기본으로 쓰므로, PATH 설정이 안 되어 있어도 `py -3.13`은 동작합니다.

### `winget: 용어가 cmdlet... 인식되지 않습니다` (Windows)
- **원인:** "앱 설치 관리자(App Installer)"가 없거나 오래됨
- **해결:** Microsoft Store에서 **"앱 설치 관리자"** 검색 → 업데이트/설치 → PowerShell 새로 열기

### `code: command not found` (Mac)
- **해결:** VS Code 실행 → `Command + Shift + P` → **"Shell Command: Install 'code' command in PATH"** 선택

### `.venv\Scripts\Activate.ps1 ... 이 시스템에서 스크립트를 실행할 수 없으므로` (Windows)
- **원인:** PowerShell 보안 설정이 스크립트 실행을 막음
- **해결:** PowerShell에서 한 번만 실행
  ```powershell
  Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
  ```
  `Y` 입력 → 다시 `.venv\Scripts\Activate.ps1`

### `externally-managed-environment` (Mac, `pip install` 할 때)
- **원인:** Homebrew로 설치한 파이썬에 직접 라이브러리를 설치하는 것을 막아 둠 (정상입니다)
- **해결:** **가상환경을 켜고** 설치 (11회). `pip install --break-system-packages`는 쓰지 마세요.

### `ModuleNotFoundError: No module named 'pandas'`
- **원인 1:** 라이브러리를 설치하지 않음 → `pip install pandas`
- **원인 2:** 설치는 했는데 **다른 파이썬**으로 실행 중
  - 터미널: 가상환경이 켜져 있는지 확인 (줄 앞에 `(.venv)`)
  - VS Code: 오른쪽 아래(또는 노트북 오른쪽 위)의 **인터프리터/커널**이 `.venv`인지 확인

### VS Code 노트북에서 "커널을 선택하세요" / `ipykernel` 설치 요청
- **해결:** 오른쪽 위 **[커널 선택]** → **[Python 환경]** → `.venv` 선택. `ipykernel` 설치를 묻으면 **[설치]**

## 2. Git·GitHub (12회)

### `Please tell me who you are` (커밋할 때)
- **해결:** 이름과 이메일을 한 번만 설정
  ```bash
  git config --global user.name "홍길동"
  git config --global user.email "내GitHub이메일@example.com"
  ```

### `Authentication failed` / 비밀번호를 물어봄 (push할 때)
- **원인:** GitHub는 비밀번호 로그인을 받지 않음
- **해결:** GitHub CLI로 로그인: `gh auth login` → GitHub.com → HTTPS → Login with a web browser

### `! [rejected] ... (fetch first)` (push할 때)
- **원인:** 다른 PC(또는 웹)에서 먼저 올린 변경이 있음
- **해결:** 먼저 받고 다시 올리기
  ```bash
  git pull
  git push
  ```

### `.DS_Store`, `.venv` 같은 파일이 변경 목록에 잔뜩 보임
- **해결:** 저장소 맨 위에 `.gitignore` 파일을 만들고 무시할 이름 적기 (12회 실습, `3. Python/1. brew setup/Git_시스템파일_차단_가이드.md`)

### 경로에 공백이 있어서 `No such file or directory`
- **해결:** 경로를 따옴표로 감싸기: `cd "5. 연구원 AI Black"`
