## 문제 2
```python
def to_number(text):
    """측정값 문자열을 float로 바꾼다. 쉼표·공백은 정리하고, 바꿀 수 없으면 None."""
    try:
        return float(text.strip().replace(",", ""))
    except ValueError:
        return None
```
```
' 612 ' → 612.0
'1,020' → 1020.0
'45.2' → 45.2
'N/A' → None
'' → None
'-' → None
'불검출' → None
'9OO' → None
```

## 문제 3
```python
raw = ["930", "1,012", "N/A", "1088", " 1045 ", "", "1120"]
numbers = [to_number(t) for t in raw]
valid = [n for n in numbers if n is not None]
print("평균:", round(sum(valid) / len(valid), 1))    # 1039.0
print("유효하지 않은 값:", numbers.count(None))       # 2
```

## 문제 4
- **원래 출력:** `3` (기대는 2)
- **원인:** 안쪽 반복에서 **측정값마다** `over_count`를 늘리므로 "기준을 넘은 **측정값 수**"(A의 1045·1120, C의 1015 → 3)를 셉니다. 구하려던 것은 "기준을 넘은 값이 하나라도 있는 **시설 수**"입니다.
- 참고: A가 `[845, 1120]`처럼 초과 값이 시설마다 하나뿐이면 원래 코드도 우연히 2가 나옵니다. **우연히 맞는 결과**가 가장 위험한 논리 오류입니다.
- **고친 코드:** 시설마다 한 번만 세기
```python
over_count = 0
for name, values in facilities.items():
    for v in values:
        if v >= 1000:
            over_count += 1
            break              # 이 시설은 이미 초과 → 다음 시설로
print("기준 초과 시설 수:", over_count)    # 2
```
또는 `any()` 사용: `sum(1 for vs in facilities.values() if any(v >= 1000 for v in vs))`
- **검증:** 원래 코드는 3, 고친 코드는 2. A의 값을 `[845, 1120]`으로 바꾸면 둘 다 2가 나와 버그가 숨어 버리는 것도 확인해 보세요.
